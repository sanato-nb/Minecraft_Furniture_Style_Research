## 우선 설계 검증 경계 (정적 발견, 아직 재현하지 않음)
- **D-R01 (T04, T12, T13)**: validate_checkpoint는 attempt.input_sha256와 task.input_sha256을 대조하지만 latest_results/assessment는 task ID/종료 여부만 확인한다. 체크포인트 없는 잘못된 입력 시도에서 PASS가 선택될 가능성. 기존 T12 fixture PASS 소급 변경 금지. 확인 기준: 불일치 입력 시도에 대한 최신 판정 및 확정 검색 차단을 기존 T04/T12/T13 회귀에 연결.
- **D-R02 (T08, T13)**: render_result_guard는 실물 SHA와 계획 연결을 검사하지만 PNG 디코딩 및 고정 width/height 검사를 직접 호출하지 않는다. 별도 fixture oracle의 정상 PNG 검사와 실제 PASS 집계 경로가 분리됨. 확인 기준: SHA가 맞는 비PNG/크기가 다른 PNG에 대해 generation PASS 집계 및 확정 검색이 차단되는지 검증. 실제 시각 정확성은 별도.
- **D-R03 (T11, T13)**: provenance 조회 결과가 비면 권리 거부 조건이 성립하지 않으며 export는 safe_links/safe_relations 외 claim/measurement/assessment 전체 행을 반환한다. 기존 문서가 인정한 권리 부재 및 자유문 경계. 확인 기준: 신뢰된 로컬 fixture 조회와 외부 공개 가능한 출력 계약을 분리하고 미확인 권리 및 민감 필드의 명시적 음성 시험. 실제 인증/라이선스 심사 구현은 제외.

T04/T08/T13 우선 교정 후보 3건, 공유 회귀 T11/T12. 나머지 6개 PARTIAL의 기존 합성 근거는 유지하며 추가 전수 엔진 구현을 요구하지 않는다. 표의 '필요시' 항목은 신규 필수 분모가 아니라 기존 요구의 제한된 확인 후보이다. T12의 기존 PASS도 현재 실행된 fixture 결과로 보존하고 정적 발견을 재현하기 전 변경하지 않는다.

## 운영/연구 단계 이관 원칙
- 실제 운영 DB/쓰기 경로/인증/저장소를 검증하려면 별도 승인된 운영 도입 범위 및 계획이 필요하다. 실제 역사 CSV 정규화와 전체 이관은 원본 보호 및 승인 근거를 전제로 별도 수행.
- UV·상태·렌더·스타일·실제 기법 일반화는 본 연구/별도 기술 검증에서 원본·독립 기준·정확한 분모에 연결한다. 게임 실행이나 유료 API를 필수화하지 않는다.
- cross-job 합성 시험 자체는 가능하나 현재 고정 실행계획은 단일 Job이다. 운영 구현 필수 조건과 구분하고 별도 기술 검증 후보로 기록한다. 실제 장기 보존/복구와 동일하지 않다.
