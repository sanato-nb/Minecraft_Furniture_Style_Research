# RQ-001 → 7단계 연구 DB 상세 설계 인계 (설계 입력, 승인 아님)

기준: 데이터 명세 v0.2, 연구 계약 v0.6, RQ001 최종 종료 보고 및 G_areas.json. 새 DB 설계를 시작하기 전에 해당 자료 및 기존 schema v1~v4/기능을 다시 확인하고 설계 범위·완료 조건을 확정한다. 여기서는 DDL/컬럼/마이그레이션을 확정하거나 구현하지 않는다.

## 재사용 가능한 기반
- 기존 release/asset/research_run/research_execution/source_job/source_checkpoint/ai_review/upstream_observation 및 카탈로그 재현: 고정 원본 25,387개. 운영 식별자 및 pin/해시 연결을 보존한다.
- DB 9경로/8고유 blob의 실제 무결성 확인. E_FINAL_EVIDENCE.json의 테이블/행수/키와 E 아티팩트의 전체 DDL/컬럼/인덱스/FK를 설계 입력으로 사용. 역사 DB의 물리적 PASS는 지식 내용 PASS가 아님.
- G_areas.json 14영역에 근거 필드, 출처 및 공백, 후속 설계 요구가 있음. 기존 구조와 중복 테이블 생성 방지.

## 설계에서 해결할 요구
1. 원본·버전·출처·증거를 연결하는 정규화 키와 해시/버전 충돌 정책.
2. 모델/요소/면/UV/PNG/frame/state/참조 그래프의 원본값·계산값·해석값 분리.
3. 가구 종류/부품 정체/비율/스타일/기법의 후보·추론·확정·UNKNOWN, 적용 조건·반례·신뢰도 및 검증 이력.
4. 렌더 생성 성공과 시각 정확성 분리. TV001은 PARTIAL, 다른 UVlock 및 전체 texel 오라클 미검증.
5. 실행 상태 PASS/PARTIAL/HOLD/FAIL 및 범위·시도·통과·예외 분모, 재개/재현 기록. 기존 execution은 PASS/FAIL만 허용하므로 호환성 검토.
6. 통합 지식 검색(종류·부품·치수·색·기법·근거) 및 JSON export, 근거 필터, 테스트 계획. 기존 색인/검토 도구 재사용 여부 우선 확인.
7. 행별 장기 증거 보존·artifact 만료 정책, 데이터 보존/백업/마이그레이션 dry-run 및 역호환. 기존 DB/파일 직접 삭제·수정 금지.
