### 🟡 P1 — 재사용 화면·위험 시나리오·필드 정합성 21건

**기존 F2를 재사용한 15건:** `S14 S15 S16 S17 S18 S19 S28 S29 S37 S38 S39 S40 S41 S42 S43`.

이들은 H3에서 원본 PNG SHA 확인은 끝났지만 원본 로그의 해당 정확 상태·모델·프레임과의 **기록 단위 연결**을 다시 확인해야 한다. 같은 파일을 다시 게임 실행했다고 취급하지 않고, 기존 F2의 증거 한계를 개별 원장에 확정한다.

**위험 시나리오 5건:**

- **R01:** S10 대표 1사례만 원본 화면 근거로 수용. 다른 가구 전체로 자동 확대하지 않음.
- **R03:** H7은 `/setblock` 3단계, H8은 창작모드 실제 플레이어 우클릭 설치·좌클릭 제거와 F2 3장을 새로 확보. 같은 범위의 실험을 반복할 필요 없음. 수동 서바이벌 일반화와 UV 화면 인과는 별개.
- **R04:** 싱크 water=false/true 정적 2상태를 모델링 증거로 검수. 시간 변화 원인은 R06과 구별.
- **R05:** Handcrafted 침대 설치·수면·기상과 파괴가 **원본 게임 실행 2회에 분리**되어 있음. 정적 다중블록 형상 근거는 H9/H10과 구분해 교차 참조; 연속 게임플레이 1회 실험은 모델링 연구 필수조건으로 강제하지 않음.
- **R06:** 물이 있는 싱크 실제 시간차 F2 3장. 물 애니메이션 렌더 원인은 **소스/렌더 경로가 있어야** 승인. 단순 시간차만으로 유체 기능 승인 금지.

**별도 원본 필드 정합성 1건:** `S22` — 모델 hash-kind 필드가 `GIT_BLOB_SHA1`이라고 적혔지만 provider SHA 문자열은 64자리 SHA256. 과거 CSV는 조용히 바꾸지 않고 별도 오류·용어 원장으로 구분해야 한다.

## 3. 실제 수행 순서

1. **원본 출처 변경 없이 결합:** F11F 사례 행의 game version, run/artifact ID, PNG SHA, H3 ZIP/PNG 원본 검증, H6 log/capture JSON 근거를 70행에 연결하고 누락·충돌을 표시.
2. **P0 6건 우선 재판정:** 원본 선택 모델·렌더 경로·서버상태·화면 변화의 인과 충돌을 단건으로 해결. 필요하다고 증명될 때에만 좁은 실게임 재시험 설계.
3. **P1 21건 재사용 경계 고정:** 기존 원본 F2 재사용 15건과 위험 사례 5건·해시표기 1건. 특히 H7/H8 보완 사실 및 중복된 원본 게임 세션 수를 보존.
4. **P2 43건 표준 검수:** 원본 캡처 JSON/로그 시점·화면 해석·정확한 3D 모델/UV 근거를 사례별 기록. 옛 관찰과 새로운 독립 심사 여부를 각각 표시.
5. **H03·H05 재판정:** `PASS_SCOPED`가 늘어도 기존 `full_F_PASS`나 `H03/H05_EXIT`로 자동 승격하지 않는다. 해결됐다는 구체적 원본 SHA·모델·프레임 인과가 있을 때만 감사 결과 갱신.

## 4. 추가 게임 촬영 의사결정 원칙

- 원본 ZIP·PNG·로그가 이미 있고 문제 없이 동일 장면을 식별할 수 있다면 **재촬영하지 않는다**.
- 하나의 정확한 모델링 판단(다른 면·UV/동적 렌더 선택 등)에 출처만으로 풀리지 않는 모순이 있는 경우에만 **그 모순을 겨냥한 대조 실험**을 진행한다.
- 게임플레이 기능, 서바이벌 조작, 침대의 모든 행동 시퀀스, 물 물리·흐름은 **기본 3D 형상/UV 연구의 필수 검증으로 자동 추가하지 않는다**. 별도 목표가 될 때 독립 계약으로 관리한다.
- 기존 H16 텍셀 1개→남 20/북 16화면 픽셀의 인과 증거는 해당 AF 의자 소스 및 카메라에 한정. F70 전체 UV 인과 인증으로 대체할 수 없다.
- 제3자 모드 자산의 AI 학습·재배포권과 모델링 결과의 출처 검증은 완전히 별도. H03/H05 미승인 사유를 권한 부족만으로 덮지 않는다.
