# INT-3 / 1차 완료 — AI 가구 제작 연구 지식 DB 통합

**실제 첫 성공 실행: 2026-11-21. 범위:** 고정된 1-3(모델/기하) + 1-4(원본 PNG·UV) + 1-5(바닐라/모드 비교)의 독립 검수를 통과한 **정적 연구 증거를 AI가 조회 가능한 관계형 지식 DB로 연결**한다. 모델 가중치 학습 또는 실제 새 가구 생성 실행은 하지 않았다.

## 왜 기존 H2 운영 DB를 재구성하지 않았는가

기존 `mcfr.research_db`는 릴리스·원본 자산·연구 회차·실행 기록·재개를 담당한다. INT-3는 근거의 **의미적 관계와 제한조건**을 조회할 수 있도록 `mcfr.knowledge_db` 별도 SQLite 파일을 생성한다. 운영 DB·1-3~1-5 원본 및 감사 기록은 변경하지 않고, 출처와 버전/해시를 양쪽에서 연결하는 확장 방식을 택했다.

1-5의 모델 적용 **52개는 1-3 모델 키에 직접 결합**된다. 나머지 **22개 바닐라 대조 적용**은 1-3-F가 전체 바닐라 모델을 저장하는 DB가 아니므로 모델 키를 임의 생성하지 않았다. 대신 1-5 비교 원장의 source asset 272행과 SHA 346행을 새 DB에 통합하여, 이 22개의 **실제 원본 경로와 해시를 조회 가능하게 보존**한다. 직접 키 미연결 상태와 원본 출처 미확보를 혼동하지 않는다.

## 화소와 예외는 어떻게 표현하는가?

기존 1-4에서 원본 화소를 독립 재계산한 일반 사각형, 프레임, 점·선·경계·클리핑 UV **지원 영역을 참조하는 면 585,969개**는 `SOURCE_REGION_REMEASURED`로 표기했다. 이는 각 면마다 독립적으로 모든 이미지 픽셀을 별도 추출했다는 뜻이 아니라, **독립 재검증한 원본 영역을 모델별 면이 참조한다**는 뜻이다.

그 외 **6,343개 면**은 미결합 슬롯 6,202, 원본 PNG 경로 누락 139, 스프라이트 교차 불가 UV 2로 구분했다. 69,118개의 영면적 UV와 5,144개 범위 밖 UV를 무조건 게임 렌더 오류로 분류하지 않는다. 가구 모델의 원본 계보·기하 제공자는 별도 데이터로 유지된다.

## AI 학습/재배포 안전 경계

모든 소스 릴리스의 `license_review=NOT_REVIEWED`, `training_approved=0`, `redistribution_approved=0`을 기본으로 한다. 바닐라 모델에도 자동 권리 승인을 부여하지 않는다. `ai_training_eligible_model` 뷰는 원본 **모델·참조 텍스처의 권리**, 완전한 face 연결, 픽셀 근거 상태를 함께 확인하고 **현재 0개**만 반환해야 CI가 통과한다.

**이 DB는 AI가 참고할 수 있는 연구 지식 구조**이지 저작물을 포함한 임의 재학습 패키지가 아니다. 원본 모델 JSON·PNG·JAR 파일 본문은 DB/아티팩트에 넣지 않는다. 검수 성공과 학습/재배포 허용 여부는 서로 다른 판정이다. 역사 런타임 관찰 R01~R10도 새 게임 테스트 성공으로 재표시하지 않았다.

## 실행·조회

저장소 루트, Python 3.12, 외부 Python 라이브러리 불필요:

```sh
export PYTHONPATH=src
python -m mcfr.knowledge_db build --root . --out /tmp/MCFR_INT3_knowledge.sqlite --report /tmp/INT3_KNOWLEDGE_SUMMARY.json
python -m mcfr.knowledge_db validate --db /tmp/MCFR_INT3_knowledge.sqlite
python -m mcfr.knowledge_db summary --db /tmp/MCFR_INT3_knowledge.sqlite
python -m mcfr.knowledge_db finding --db /tmp/MCFR_INT3_knowledge.sqlite --id C03
python -m mcfr.knowledge_db model --db /tmp/MCFR_INT3_knowledge.sqlite --id MODEL_KEY
```

`model` 조회는 고유 키가 우선이며, 다른 버전과 겹치는 리소스 ID는 임의 선택하지 않고 **모호성 오류**를 반환한다. 기존 결과 파일이 있으면 실수로 덮어쓰지 않으며 명시적 `--force` 사용 시에만 교체한다.

## 실제 재현·신뢰 범위

- 독립 검수 입력 JSON: INT2 1-3·1-4·1-5 여섯 개 문서의 `status`, 범위 통과, 입력 SHA를 재확인한 다음 통합한다.
- 기하·면 링크는 1-3-F 원장을 읽되, **PR #26에서 고정 원본 JSON 전체 592,312면을 독립 재구성해 일치했다는 증거 경계**를 명시한다. INT-3가 원본 아카이브를 다시 검수했다고 주장하지 않는다.
- 입력 DB 세 개의 SHA-256, 핵심 4테이블의 **모든 논리 행 정렬 SHA-256**, 근거 JSON의 SHA-256을 [집계](INT3_KNOWLEDGE_SUMMARY.json)에 보존한다.
- 새 DB는 GitHub Actions 임시 산출물로 생성하고 **60일 아티팩트**로 보존한다. 공개 저장소에는 검수 집계와 코드·스키마만 두며 130MB가 넘는 DB 이진 파일은 직접 커밋하지 않는다.
- [실제 1차 성공 CI](https://github.com/sanato-nb/Minecraft_Furniture_Style_Research/actions/runs/44873264792). 후속 실행에서는 저장된 논리 해시·근거 SHA·22개 바닐라 출처 해시 보존·권리 상태가 일치해야 통과한다.

## 앞으로 남은 INT-3 작업

1. 지식 DB의 **의미 태깅**: 부품 역할(다리, 좌판, 등받이 등), 재료/스타일, 적합 가구 카테고리는 원본 관찰·시각적 검증 근거를 붙이고 검증되지 않은 추측을 섞지 않는다.
2. **버전별 업데이트/증분 재계산**: H2-H7 엔진과 연결해 영향 있는 모델·텍스처만 다시 연구한다.
3. **AI 제작 PoC의 검증용 질의 API 및 별도 신규 저작 가구 예제**. 구조·텍스처의 재배포/모델 학습 권한이 확인되지 않은 제삼자 에셋은 입력 훈련 대상에 넣지 않는다.
4. 실제 Minecraft 게임 내 모델 베이크, 배치, UV lock/tint, 특수 렌더, 충돌과 시각적 동작은 별도 런타임 시험 대상이다.
