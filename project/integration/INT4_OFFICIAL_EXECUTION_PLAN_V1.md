## 0. 원본 고정·경계

1. 포함: Minecraft Java 바닐라 1.21.11과 기존 1-5 대조에 필요한 1.21.1 원본, Another Furniture(AF), Handcrafted(HC), Macaw's Furniture(MACAW)의 기존 연구 고정 릴리스·로더·Git SHA/JAR 해시. 신규 업데이트, 다른 모드, 외부 리소스팩 변형은 다음 회차.
2. 고정 분모(서로 **더하지 않음**): 1-1 표본 PNG 150; 1-2 모델 2,390, blockstates 1,168, PNG 1,111 및 99 sidecar(바닐라 1.21.11); 1-3 모드 모델 파일 16,572(AF 1,629/HC 12,394/MACAW 2,549), 모드 blockstates 1,158; 1-4 유효 요소 인스턴스 105,383, 면 592,312, 슬롯 81,641, 원본 텍스처 쌍 2,256, 화소 근거 585,969; 1-5 고정 모드 상태 47+바닐라 15=62 사례/74 모델 적용/21 판정.
3. 예외: source model 중 no-static 108, parent_missing 48(둘의 교집합 44, 따라서 단순 합산 금지); 근거 미연결 면 6,343(슬롯 미연결 6,202/PNG 원본 누락 139/원본 교차영역 없음 2). 원본 model/element/face 자체 누락이나 실제 화면 오류라고 즉시 결론내리지 않는다.
4. 기존 INT-3 통합 DB의 model 16,579 = 모드 16,572 + 바닐라 모델 링크 7. 이 값은 1-2 전체 모델 2,390 및 1-3 모델 16,572와 분모가 다르다. 원본을 섞거나 중복 계산하지 않는다.
5. 기존 고정 SHA·역사 DB/CSV, 바이너리, F2, 실패 이미지/로그는 **불변**. 정정은 새로운 행/보고서로 첨부. 검증 당시와 배포 버전이 다르면 서로 별도 릴리스로 취급.
6. 본 v1의 INT-4-F 검증 대상은 역사 62개(필수 원본 사례) + 특별 시나리오 8개(상태 묶음), 총 **70개 검증 단위**. 같은 F2를 여러 단위의 근거로 참조할 수 있지만 스크린샷 수를 중복 증가시키지 않는다. A~E에서 새 고위험 **범주** 또는 현재 70개로 포착 불가능한 필수 상태가 발견되면 이 문서의 v2 범위 변경/차이 기록 없이는 70개 완료로 INT-4 전체 종료 선언 불가.

## 1. 검증 데이터 기본 계약

- 고유키: source_release_key + source_ref_path + source_sha + state_selector_or_rule + model_path + geometry_provider + element_index + face_direction/face_index + texture_slot + png_path + optional runtime_scenario.
- 레코드: id, cohort, minecraft_version, mod_version, loader, source_kind, original_path, original_sha, evidence_path, evidence_sha256_or_git_blob_sha, execution_ci, observed_at, evidence_method, exact_scope, applicable, result, exception_reason, prior_result_ref.
- 공통 evidence_method: ORIGINAL_SOURCE / STATIC_RECOMPUTE / PIXEL_DECODE / REAL_CLIENT_F2 / SERVER_STATE / HUMAN_IMAGE_OBSERVATION / INFERENCE / RIGHTS_REVIEW. 진짜 게임 화면은 스크린샷을 직접 열어 본 관찰이 있어야 하며 자동 프록시만으로 PASS 불가.
- 누락/충돌 결과는 원본 수정 대신 discrepancy 원장에 남긴다. 동일 파일 내용 해시는 SHA-256, Git blob은 SHA-1임을 식별. 렌더 결과에는 실제 client/server, launcher, JAR, version, world, camera/scene, screenshot SHA와 실패/재촬영 로그를 연결.
- 완료율 계산: 각 단위에 그 단계의 모든 **필수 검증 체크**가 충족되고 예외 처분이 기록된 경우만 numerator 1. N/A는 적용하지 않는 이유와 기초 근거를 반드시 기입. 근거만 발견됐거나 과거 PASS가 있다는 이유만으로 INT-4 완료로 자동 치환하지 않는다. 분모 확정 전 퍼센트 금지. 원본 파일·부모경로·상태 인스턴스·면·F2 시나리오는 별개 분모.

## 2. A~H 공식 실행 순서와 종료 게이트

### INT-4-A 모델·부모 원본 연결

- 단위: 모드 source model 파일 **16,572개**. 바닐라 고정 원본은 별도 2,390개/필요시 1.21.1 7개 연결로 별도 처리. release/path/blob SHA→model JSON→parent chain→제공자 기하까지 독립 추적.
- 선행 재사용: INT2_MOD_SOURCE_SUMMARY, INT4_PARENT_48_ORIGINAL_AUDIT_RESULT, INT4_PARENT_48_BLOCKSTATE_AUDIT_RESULT, INT3_KNOWLEDGE_SUMMARY. parent_missing 48개는 다른 경로에 같은 이름이 있다는 이유로 치환 금지; 이 48개는 고정 blockstate 및 item parent chain에서 도달 0/48이나 동적 로더까지 배제한 것은 아님.
- 산출: A 전수 model/parent 경로 원장, 누락·순환·동적/미사용 처리, provenance SHA, stage ledger. 완료: 16,572개 각각 exact-match 또는 설명 가능한 HOLD/NOT_APPLICABLE 등 최종 disposition + 복원 가능한 재실행 + 무단 정정 0.

### INT-4-B 요소·면·UV 구조 검증

- 단위: 유효 element 105,383개, face 592,312개. explicit UV 590,974/implicit UV 1,338은 별도 구조 판단. 실제 블록상태 회전·uvlock 적용과 모델 원형 UV를 혼동하지 않음.
- 재사용: INT2_MOD_SOURCE_SUMMARY 및 INT2_1_4_FULL_LINKS_SUMMARY의 전수 면 592,312/592,312·slot 81,641/81,641 재구성, 기존 1-3-C/F·1-4-E 감사.
- 산출: 원형/provider/face 번호, 방향/좌표/UV, 역방향·회전·암시 UV, parent exception, 행 SHA. 완료: 전체 면 행의 계산 또는 **사유가 지정된 분리 보류**, 출처 체크의 일치, 0건 무근거 PASS.

### INT-4-C 텍스처 슬롯·원본 PNG

- 단위: source slot 81,641, texture pairs 2,256, face 592,312. 원본 PNG 디코드 2,001은 이전 재감사의 범위이며, 고유 텍스처 수와 동일한 분모가 아님.
- 재사용: INT2_1_4_SUMMARY(2,001 PNG CRC/RGBA), FULL_LINKS, UV_REGIONS 및 1-4-F. 원본 화소 연결 585,969/592,312(98.929%)와 미연결 6,343의 상호 배타적 이유를 별도 보존. 프레임/투명/zero-area/UV 범위 외는 단일 결함 코드로 뭉치지 않는다.
- 완료: 원본 파일·슬롯·면 관계 전수 정리와 예외 6,343건 사유/영향/정정후속 결정, PNG SHA·RGBA·UV 원장 대조. 연결률 98.93%는 검증 종료율 98.93%가 **아님**.

### INT-4-D 블록상태·방향·변형·연결·릴리스

- 단위: 모드 blockstate 원본 JSON 1,158개(모델 파일 16,572와 분리), 바닐라 1.21.11 1,168개; 모델 선택자/가중치/회전/uvlock, multipart, 연결 상태, 릴리스마다 선택 모델의 동일성.
- 재사용: INT2_D_SUMMARY(바닐라 원본 상태 9,193개의 정적 열거), INT3_CHAIR_BLOCKSTATE_SOURCE_SUMMARY, INT4_NONCHAIR_15_CASES_AUDIT_RESULT(15사례/19모델 적용), AF variant3, Macaw neighbor, HC bed 자료.
- 주의: 모든 가능한 상태와 실제 게임에서 도달 가능한 상태는 다르다. AF variant3 소스의 남쪽 방향 선택 모델 차이는 확정 결함 아님. AF Git 연구/실제 배포 JAR 소스가 다르면 전 릴리스 동일성을 주장하지 않는다.
- 완료: 고정 원본의 선택자·모델·부모·기하 연결을 각 상태/규칙별 평가하고 시도하지 않은 런타임 전이는 미검증으로 분리; 고정 모드 1,158개 JSON 모두 처리 disposition, 본문/버전 SHA 고정.

### INT-4-E 기존 연구 결과와 출처 정합성

- 단위: 1-5 62사례, 74 모델 적용, 21 연구 판정. 기존 R01~R10 런타임은 별도 10건, 새로운 실제 게임 재실험과 합산 금지.
- 재사용: INT2_1_5_SUMMARY(62/74/21 기존 독립 출처 재검증), INT3_KNOWLEDGE_SUMMARY와 PR #39~#49. 부분/제한/반례 7건을 보편 규칙으로 승격하지 않는다.
- 완료: 각 비교 결론별 해당 model/state/texture/evidence/ref와 검증판본 연결; 예외 및 반례 누락 0; SHA가 다른 배포 버전/다른 모드 혼입 0.

### INT-4-F 실제 Minecraft 렌더 종합검증 — **정적 단계 후 수행**

- 검증 단위 총 70: 역사 사례 V01~V15, S01~S47 = **62개**, + R01~R08 고위험 실행 시나리오 **8개**. 정확한 명칭/버전/기존 F2 상태는 INT4_F_RENDER_TARGETS_V1.csv를 원장으로 쓴다.
- 필수 대표 범주 8: 일반 가구(R01), 방향별 모델 선택(R02), 연결/해제(R03), 기능형 전후 상태(R04), 다중 블록 설치/점유/제거(R05), 투명·애니메이션의 시간별 차이(R06), 연구/실게임 불일치(R07), 연구 Git/배포 JAR 차이(R08).
- 한 행당 요구되는 촬영은 1~6개 장면이므로 **70은 사진 수가 아니다**. 사례당 원본 selected state를 정확히 특정하고 원본 JAR/리소스와 해당 서버 상태·F2·시각 관찰·로그·SHA를 연결한다. 진단/리소스팩 개입 화면과 원본 일반 화면을 구별한다. 시간별 애니메이션의 두 F2에서 차이가 안 나면 곧바로 모드 오류라고 하지 않는다.
- 이전 증거: 비의자 대표 S14~S19/S28~S29/S37~S43 **15/15 실제 F2** 기존 결과; 의자 방향 16 F2, AF variant3의 6 F2, sink/bed/bookcase/neighbor 반복 실험 등은 해당 조건/버전이 일치할 때만 재사용. 과거 15장 이외 사례의 F2가 없다는 결론이 아니라, **정확한 사례 ID로 새 원장에 아직 대응하지 않았음**을 뜻한다.
- F2 미촬영 확정 수는 스크린샷·아티팩트의 실제 접근/개별 매핑을 감사하기 전 단정 금지. 현 시점 62 역사 사례 중 확인된 **기존 F2 증거 사례 15**, 나머지 **47은 미매핑**. 시나리오 8건은 기존 이미지·로그로 수용 가능 조건을 새로 판정해야 한다.
- 실패 F2(하늘·잔디만 보임, 카메라 조작 실패, 오탐)와 최초 아티팩트는 보존하되 성공 F2로 세지 않는다. 만료된 CI 아티팩트로 원본 이미지 재검사가 불가능하면 파일·SHA 기록만으로 이미지 실관찰 완료로 새 승인 불가.
- 완료: 70개 각각 accepted / conditional / hold / discrepancy / n/a 분류 + 필수 카테고리 표본 요건 충족 + F2/상태/릴리스 SHA 대조 + 실제 이미지 수동 확인. 문서만으로 F 자체 PASS 금지.

### INT-4-G 최종 연구 판정

- 분모를 섞지 않고 다층 원장으로 판정: 원본 모델 16,572건(정적 연결·예외), 면 592,312건(정적 추적), F 대상 70건, 기존 연구 판정 21건. 통합 진행률은 분모별 벡터로 보고. 원본 데이터 행은 개별 판단 근거이되 전부 같은 수준의 라이브 F2를 요구하지 않는다.
- 결과: VERIFIED(필수 정적/해당 필수 게임 근거 일치), CONDITIONAL(조건/버전/렌더 제외 이유 명시), HOLD(필수 증거 부재), CONFLICT(증거 상충), NOT_APPLICABLE(적용 불가 근거). **N/A도 기록으로 심사**, 정적만 있을 때 실게임을 본 척하지 않는다.
- 근거 최소: 원본 commit·파일 경로·SHA, 분석기/실행 ID, 관측된 관계/예외, 실제 게임이 필수라면 실제 F2/상태/로그 SHA와 직접 확인. 과거 1-5의 21건은 재사용 후보이지 신규 G 완료가 아니다.
- INT-5는 부품 역할 45후보, 재질·스타일·의미의 시각 판정; INT-6은 AI 학습/재배포 권한 별도 심사. 양쪽 현재 승인 0, INT-4 판정이 이를 변경하지 않음.

### INT-4-H 독립 종료 심사 및 인계

- 게이트: A~E 고정 원본의 누락 없는 disposition, C 6,343 예외·A 48 parent 누락·108 no-static의 교집합 명시, F 70개 필수 계약의 판정/조건부·보류 원인, G 각 층별 원장, 원본+실행 로그+SHA 완결, 독립 CI/경로 무결성, 실패·재시도 기록, 역사 파일 불변 및 main 미병합 유지.
- 미해결이 존재해도 **누락 없는 사유/영향/후속 소유 단계**가 있으면 범위 제한 종료 가능. 진실한 오류/불일치 항목을 지우거나 VERIFIED로 세탁해서 100% 만들지 않는다. 중대한 출처 불일치 또는 필수 F 시나리오 누락 시 INT-4 최종 종료 차단.
- 인계: INT-5에 부품·재질·스타일/렌더 의미 관련 증거만 넘기고, INT-6에는 출처·권한이 아직 미승인임을 전달. INT-7은 별도 전체 감사; H를 INT-7 완료로 표시하지 않는다.

## 3. 진행률·완성도 계산

- 원본 연결률: 증거로 링크된 대상 / 해당 stage 원본 고정 분모. 이 수치는 과거 증거의 **재사용 후보 준비율**이지 stage 완료율이 아님.
- 단계 수행률: 완료 조건의 모든 필수 체크가 새 INT-4 단계 원장에 기록된 단위 / 해당 단계 분모. 미구축 단계 원장은 '미산정'으로 표시. 이미 검증된 과거 자료를 자동으로 다시 수행하지 않고 해시·범위 동등성으로 인수한 뒤 단위 기록.
- F 증거매핑률: 확실히 대응된 역사 F2 사례 / 62 (현재 최소 15/62=24.19%). F 전체 대상 수용률은 ACCEPTED+명확한 조건부 종료 허용 건수 / 70로 따로 산정하고, **아직 0/70 승인**으로 고정하지 않는다. 과거 시나리오 검증을 인수한 뒤 산정.
- G 판정률: dispositions 지정 행 / 해당 종류 분모, VERIFIED률: VERIFIED 건수 / 동일 분모. HOLD·CONFLICT·N/A는 완료 판정과 별개 열. 모든 유형을 더해 총합 한 개의 %를 만들지 않는다.
- H: 8개 종료 게이트 묶음 별 확인표(참/거짓/보류); 전체 INT-4 점수는 조건이 충족되지 않으면 '미산정/종료 보류'로 유지.
- 분자 0이 실제 미실행인지 '확인되지 않음'인지 구분. 새 계획 생성은 학습/렌더 완료도 증가가 아님.
