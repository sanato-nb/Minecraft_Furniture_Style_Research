# TEX03-R002 — 1-1-03 금속·금속부품 · 정적 UV 실제 RGBA 교차 측정

- Minecraft Java Edition **1.21.11**. 작성일 2026-11-13.
- **엄격 범위:** 1-1-03 고정 **16개** 텍스처만. 공식 전체 연구 **v38 유지**.
- **이번 새로운 증거:** v4 및 `TEX03-R001`의 독립 SHA/PNG·RGBA 원본 검증 위에서 추출 미러 모델 템플릿 **13개를 다시 직접 취득**하고, 각 요소의 면별 정수 UV 원문과 PNG 이진 alpha 마스크를 실제 결합해 **145개 정적 모델 템플릿 면**에서 사용하는 화소수를 계산함. 별도 `cube` 부모 모델 1개는 이전 R001에서 읽고 확인된 Git 객체 SHA를 출처 원장에 기록.
- **성격:** 비공식 추출 미러의 정적 JSON+RGBA 검증. 마인크래프트 **실제 인게임 렌더링이 아님**. 모델 면 145개는 16개 텍스처에 대한 모델 템플릿 면 기록의 합계이며, 회전/상태 조합 수 또는 고유 PNG 화소 수와 다름.
- **Mojang 공식 client.jar SHA 인증:** 여전히 **0/16**. 인게임 정적 화면 검증 **0/16**. 애니메이션·키프레임·움직임 연구 보류.

## A: 선행 원장 복구·교차 검사

이 단계의 [TEX03-R001 결과](../TEX03-R001/REPORT.md)에 있는 16개 비공식 미러 PNG의 SHA·RGBA·5개 알파 마스크를 재사용했으며, 이전 실측을 **신규 PNG 16개**로 다시 중복 집계하지 않았다. R001의 `ALPHA_MASKS.txt` Git SHA `c81e5306a21a9306bc70b81429a50de7857b7d7b`. 추가 13개 부모/직접 모델 JSON의 실제 경로·Git blob SHA는 `SOURCE_MODEL_MANIFEST.json`에 각각 기록.

## B/C: 실제 PNG와 UV 알파 화소 교차

방법: 각 모델 템플릿의 선언된 정수 UV `[u1,v1,u2,v2]`를 읽고 `min/max`를 적용해 16×16 PNG의 정수 좌표 `[minU,maxU) × [minV,maxV)` 범위의 RGBA 알파를 **실제 샘플링**하였다. 반대 방향·회전으로 인해 UV 좌표 순서가 뒤집힐 수 있으나 샘플에 **포함되는 원본 픽셀 위치 집합**은 같다. UV를 명시하지 않은 `cube`의 기본 전체면 16×16은 부모 `cube` 모델 선언의 16×16 요소에 근거해 처리.

- 사용한 모델 템플릿 면 정의 총 **145개**: 일반 `cube_all` 10텍스처×6면=**60**; `heavy_core` **6**; `template_anvil` **21**(body 20/top 1); 철다락문 3부모×6면=**18**; 철문 8부모×5면=**40**.
- 불투명/투명 샘플 합계는 중복 UV 영역의 **면별 화소 참조 횟수**로 계산. 동일 화소가 다른 면에서 사용되면 여러 번 세므로 **원본 PNG의 고유 4,096픽셀과 더하거나 비교할 수 없음**.
- **투명 픽셀을 하나 이상 포함한 UV 모델 면: 20/145**(구리 격자 6, 철다락문 6, 철문 상부 8). 나머지 125면의 참조 UV에는 투명 픽셀 없음.

### 새 발견 1 — heavy_core: PNG 투명 64픽셀과 실제 UV 참조는 별개

- PNG의 **오른쪽 아래 8×8 (64픽셀)**은 완전 투명.
- 실제 고정 `heavy_core` 모델 요소는 `[4,0,4]→[12,8,12]`; 동서남북 UV `[0,8,8,16]`, 위 `[0,0,8,8]`, 아래 `[8,0,16,8]`.
- **6면이 참조하는 영역은 총 6×64 = 384개의 UV 화소 참조이며 모두 불투명 (alpha0 0)**. PNG 투명 64픽셀을 ‘블록에 뚫린 구멍’이라고 판단하면 잘못된 해석.
- 이 판정은 정적 모델의 시각 자료 수준이다. 실제 게임의 조명·광택·충돌 경계를 인증하지 않음.

### 새 발견 2 — anvil_top: PNG 외부 투명 영역 미사용

- `anvil_top` PNG에는 좌·우 3열씩 **96/256 alpha0**.
- `template_anvil` 4번째 요소의 `up` 면 UV는 **[3,0,13,16]**. 가로 10×세로16의 **160픽셀 모두 alpha255**.
- 따라서 `anvil_top`의 **전체 PNG에 37.5% 투명 픽셀이 존재한다는 사실**만으로 실제 윗면이 37.5% 빈 것이라고 말할 수 없음. 실제 UV 사용 범위의 투명 비율은 **0%**.

### 새 발견 3 — 철다락문/철문의 넓은 면과 측면의 알파 마스크가 다르다

- `iron_trapdoor`: 3개 정적 부모 모델의 18개 면 중 **6개** 넓은 16×16 판면은 각각 **36개 alpha0**, 12개 3픽셀 두께 띠면은 **0개**. 6×36=**216** 투명 UV 참조.
- `iron_door_top`: 4개 정적 부모 템플릿의 20개 면 중 **8개** 넓은 16×16 판면은 **48개 alpha0**, 나머지 12개 테두리·두께 면은 **0개**. 8×48=**384** 투명 UV 참조.
- `iron_door_bottom`: 같은 방식의 20개 면은 **전부 불투명**, UV 알파 구멍 **0개**.
- `copper_grate`: `cube_all` 각 면이 16×16 전체를 참조하므로 **6면 모두 77개 alpha0**, 중복 사용 횟수 합 **462**. 독립된 투명 PNG 픽셀은 **77개**뿐.

### 새 발견 4 — 모루 본체의 몸통·윗면을 섞지 않기

- `template_anvil` 4요소 **총 21개 면**. `#body`를 쓰는 **20면**의 원본 UV 참조는 **1,188개** 모두 불투명. `#top`은 마지막 요소 윗면 **1개 / 160픽셀**, 모두 불투명.
- `anvil_top` PNG 자체의 빈 열은 실제 UV 외부이므로, 모루 상면이 비어 보이는 부분이 없다는 **정적 소스** 근거로 보존. 실제 인게임 단면·음영은 미검증.
