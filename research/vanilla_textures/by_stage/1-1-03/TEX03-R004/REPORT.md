# TEX03-R004 — 사용자 제공 1.21.11 정적 블록상태 63개를 실제 UV 모델 면 406개로 확장

**단계** `1-1-03` 금속·금속부품 · **작성일** 2026-11-13 · **기존 릴리스** TEX03-R001·R002·R003 모두 불변 · **전체 프로젝트 공통** `v38` 유지.

## A — 신규 검사와 선행 검사의 경계

이번에는 기존 PNG 16개의 SHA·색상·RGBA를 다시 분석하지 않는다. **새 분석 단위는 Minecraft Java 1.21.11 블록상태의 개별 변형(variant)을 실제 연결 모델/템플릿/UV 면에 대응시킨 '상태별 모델 면 참조'**다.

1. **사용자 제공 추출본 `1.21.11/`에서 blockstates JSON 14개를 새로 직접 가져와 파싱**했다. 각각의 Git Blob SHA-1이 이전 `TEX03-R003/USER_BLOCKSTATE_CROSSCHECK.csv` 및 비공식 미러 원장과 일치함을 검사했다.
2. 블록상태가 지정하는 **23개 고유 leaf 모델**은 R003에서 사용자 제공본의 파일 자체를 직접 검사해 미러와 해시가 일치하는 것으로 인증한 자료를 재사용했다. 모델의 부모 및 텍스처 경로는 R003의 모델 39개 원장에서 확인했다.
3. **UV 픽셀 단위 투명도**는 기존 `TEX03-R002/UV_ALPHA_FACE_CENSUS.csv`의 **145개 템플릿 면 실측 기록**을 사용했다. 해당 모델/템플릿의 Git SHA-1이 사용자 추출본과 일치하는 것을 R003 및 새 분석 시 다시 대조했다.
4. 상태별 단일 모델을 탐색해 `blockstate → leaf model → parent template → texture → UV face`로 연결했다. 63개 상태 모두 실제 템플릿까지 연결되고, 연결 실패 0건.

따라서 이번에 새로 측정한 내용은 **63개 개별 상태를 따라가는 406건의 정적 면 참조 관계**이며, 기존 R001 RGBA 픽셀 4,096개 또는 R002 템플릿 면 145개를 다시 신규 측정했다고 주장하지 않는다.

## B/C — 파일 무결성 및 PNG 샘플 데이터의 적용

- 원본 사용자 GitHub `1.21.11/`의 PNG 16개, blockstates 14개 및 model JSON 39개는 R003에서 **69/69 Git Blob SHA-1 일치**, PNG는 직접 SHA-256 **16/16 일치**로 이미 확인.
- 이번은 **정적 상태 14개 JSON 재취득/파싱 후 원본 SHA 재확인** 작업. PNG 신규 SHA 재계산 또는 신규 RGBA 디코딩은 0건.
- R002의 UV 면별 투명화소 개수는 원본 PNG 바이트·모델 정의가 동일하다는 R003 해시 근거로 승계. UV 좌표 배열은 모델 로컬 기준이며, 상태별 x/y 회전은 별도 필드로 보존했다.

## D3/E — 63개의 상태를 406개 템플릿 면 참조로 실제 풀어낸 결과

|---|---:|---:|---:|---:|
| `iron_block` | 1 | 6 | 0 | 0 |
| `copper_block` | 1 | 6 | 0 | 0 |

| `copper_grate` | 1 | 6 | 6 | 462 |

- **고정 대상 16개 PNG 모두** 하나 이상의 정적 모델 면 참조로 추적됨. 14개 블록상태는 텍스처 16개와 동일한 숫자가 아니다. `anvil`은 `anvil`·`anvil_top` 2개 텍스처를, `iron_door`는 `iron_door_bottom`·`iron_door_top` 2개를 사용한다.
- 전 상태·전 모델 면의 UV 범위 총 **53,392 화소 참조**. 그중 **3,150 참조**가 투명값. **이는 서로 다른 PNG 픽셀 3,150개가 아니라, 동일 UV 픽셀이 여러 상태와 면에서 중복 참조되는 *횟수*다.**
- 전체 406개 상태별 모델 면 참조 중 alpha=0 포함 면 70개. **이 숫자 역시 게임 화면에 실제 렌더되는 면 수가 아니다.** 면 가려짐, 월드 회전, 이웃 블록 면 제거, 광택/조명, 시야 여부는 계산하지 않았다.

### 철문 — 상·하단 모델의 차이가 상태 전체에 어떻게 나타나는가

- `iron_door`의 32개 정적 상태(4 facing × upper/lower 2 × hinge 2 × open 2)는 고유 leaf 8개와 5면짜리 부모 템플릿 8개로 연결된다. **상태별 템플릿 면 참조 160개.**
- `half=upper` **16개 상태에서만**, 상태당 **2면 × 48 alpha0 화소 = 96 투명 UV 참조**. 전체 32개 alpha0 포함 면, 투명 샘플 1,536회.
- `half=lower` **16개 상태**는 상태당 alpha0 참조 **0개**. 하지만 상·하부가 게임에서 어떻게 연결되어 보이는지는 인게임 확인이 필요하다.
- `facing`, `hinge`, `open` 속성은 연결 leaf와 회전 메타데이터를 변화시키더라도 **각 half의 alpha0 참조 합계는 변하지 않는다**. 열림/닫힘을 시간 애니메이션으로 분석한 것이 아니라, 정적 상태 JSON의 두 결과만 비교했다.

### 철다락문 — 16개 정적 상태 전수 검사

- `iron_trapdoor` 16개 상태(4 facing × top/bottom 2 × open 2), 3개 부모 템플릿이 사용된다.
- 각 상태에서 UV 판면 2개는 **각각 36개 alpha0 화소**, 나머지 4개 측면은 alpha0 참조가 **0개**. 따라서 **상태당 6면 / 투명 포함 2면 / 투명 UV 참조 72회**이고, 전체 96면·32면·1,152회.
- `open=true/false`는 정적 두 모델의 선택 차이. 문이 실제로 움직이는 시간·프레임·애니메이션은 연구하지 않았다.

### 모루·구리 격자·Heavy Core

- `anvil` 4방향 상태 × 모델 21면 = **84면**. `anvil` 본체 80면, `anvil_top` 윗면 4면. R002에서 확인한 사용 UV는 **전부 불투명**.
- `copper_grate` 1상태 × 6면 = **6개 투명 포함 면**. 각 면이 동일 PNG 77개 alpha0 픽셀을 참조해 총 **462회**.
- `heavy_core` 1상태 × 6면 = **6개 모두 UV 범위에서 불투명**. PNG에 alpha0 64픽셀이 있다는 기존 사실과 실제 모델 UV 참조는 구별 유지.
