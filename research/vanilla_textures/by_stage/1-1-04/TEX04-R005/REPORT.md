# TEX04-R005 — 9색 양털의 색상 치환·국소 패턴 방향·정적 모델 상태 비교

> 2026-11-13 · 단계 `1-1-04` 전용 · 이전 `TEX04-R004` 유지 · 프로젝트 전역 `v38` 불변.

## 이번 새 연구가 무엇인지

**직접 입력 원본:** 사용자가 client.jar을 추출해 업로드한 GitHub `1.21.11/assets/minecraft/`. 이 채팅에서 9개 PNG를 GitHub 이진(base64)으로 실제 다시 읽어 Python에서 디코드했고, SHA-256·PNG 청크 CRC·16×16 RGBA 불투명 여부를 검사했다. 9/9의 SHA-256은 LIVE STATE/R003와 일치했다. 9개 leaf model, 9개 blockstates, 세 공유 부모 JSON도 직접 읽어 상속·face·UV 필드 구성을 검사했다.

**새로운 분석:** 기존 R002의 색상쌍 상관과 반복 이음매를 다시 신규 성과로 세지 않고, (a) 백색 명도→타색 RGB 채널별 최소제곱 1차 변환의 잔차, (b) 36개 모든 색상쌍의 인접 명도 변화 부호 보존, (c) 백색 무늬에 대한 D4(90/180/270° 회전과 4가지 반사) 변환 경쟁, (d) 9종 모델/상태 구조의 색상별 동형성만 비교했다.

## A: 출처 및 측정 분모

- 고정 대상 원본 PNG **9종**. 기존 9×256=**2,304 고유 픽셀**을 R001에서 이미 계측했으며 이번에 다른 2,304픽셀로 **중복 가산하지 않는다**.
- 새 고유 PNG·새 모델 face **0**. 기존 R003 정적 9 leaf+9 blockstate+3 parent JSON 및 54면 근거 **계승**.
- 이번 신규 결과 레코드: 색상별 9행, 공간 변환 72행(각 8변환), 두 색상 간 경사 부호 36행, 모델·상태 9행 = **126행**. 별도 CSV 네 개에 저장.
- 기존 R004 SHA-384→MANIFEST→SF (30 파일)의 CRLF 재구성 연결은 계승. 별도 RSA 인증이나 JAR 전체 공식 SHA1 인증 성공을 주장하지 않는다.

## B–D: 직접 정량 결과

**측정 정의:** 각 픽셀의 8-bit RGB 명도 `Y=0.2126R+0.7152G+0.0722B` (sRGB encoded channel에 곱하는 가중합; 선형광 변환이 아님). 인접차는 좌→우 16×15=240개, 상→하 15×16=240개/텍스처. 36색쌍×480=**17,280건 후보** 중 쌍의 양쪽 차이가 모두 0이 아닌 비교 **16,404건**(가로 7,933, 세로 8,471)을 평가했고, 모든 유효 비교에서 증가·감소 부호가 일치했다. **명도차가 0인 876건은 일치 판정에서 제외**했으므로 17,280건 전부 유효했다고 주장하지 않는다. 이는 국소 명도 순서가 보존된다는 의미이지 RGB 값이 동일하거나 색상별 RGB가 완벽한 치환식이라는 의미는 아니다.

**기준 화이트와 RGB 채널별 최소제곱 선형 적합:** 각 색상 픽셀의 `R/G/B = a·white_Y+b`를 256 위치에서 맞췄다. 전체 3채널 잔차 RMSE 최솟값(비백색)은 `cyan` **0.78739**, 최댓값은 `purple` **4.56436** (채널값 0–255 척도). 흰색 스스로도 백색 명도에서 개별 채널 재구성이라 RMSE가 **0.25423**이며, 색상 팔레트마다 개별 RGB 데이터가 있다. 단일 보편 RGB 변환 공식이라고 보지 않는다.

**패턴의 D4 방향:** 백색 Y 16×16을 무회전·90°·180°·270°·좌우/상하 반사·전치·역전치 총 8개로 변형하여 각 색상의 Y와 Pearson을 비교했다. **9색 모두 identity가 8개 중 최고**였다. identity 상관은 **0.90303542(purple)~1.0(white)**, 모든 색에서 차점은 회전 180°로 **0.26142308~0.28192320**. 따라서 색상별 패턴이 90도 또는 반사되어 재사용된 흔적은 이 16×16 픽셀 대조에서 확인되지 않았다. 이 결과는 실제 3D 면에서의 UV 방향이나 게임 화면의 방향을 인증하지 않는다.

**팔레트 인덱스 주의:** 색상별 index PNG의 인덱스가 같아도 각 PNG의 RGB 팔레트가 다르다. 백색과 같은 위치 인덱스 수는 `black=0/256`, `blue=154/256`, `yellow=24/256` 등으로 달라서 index equality는 색상 동일성 또는 패턴 동일성 지표가 아니다.

## E: 사용자 원본 정적 모델·blockstate 재확인

9색 leaf JSON은 전부 `parent=minecraft:block/cube_all`, `textures.all=minecraft:block/<color>_wool`. 9색 blockstate는 전부 `variants: {"": {"model": "minecraft:block/<color>_wool"}}` 1개뿐이다. 공유 부모 `cube_all→cube→block`의 `cube`에는 `from=[0,0,0]`, `to=[16,16,16]`인 1개 요소와 위/아래/동서남북 6개 face가 있다. 6면에서 `uv` 및 `rotation` 명시가 없고, blockstate에서 `x`, `y`, `uvlock`을 명시하지 않는다. 색상별로 추가된 기하·회전·variant의 차이는 **정적 JSON 소스상 0**. 기존 54면 face·암시적 UV 근거는 **계승**이며 새 면이 생긴 것은 아니다. Minecraft 실제 렌더러의 기본 face-local UV orientation·조명·샘플링 및 인게임 회전은 본 정적 데이터만으로 인증할 수 없다.

## F: 제외와 미완료를 분리

사용자 요청에 따라 **Mojang 공식 client.jar 전체 SHA-1 및 공식 배포 메타데이터 인증은 연구 필수 항목/완료 분모에서 제외**한다. 이는 검증에 성공했다는 의미가 아니다: 공식 JAR 인증 **0/9** (역사적 사실 유지). R004 SHA-384 자료도 PKCS#7 검증이 아니다. 게임 실행·스크린샷·실측의 새 증거가 없으므로 **인게임 정적 렌더 검증 0/9** 유지. 애니메이션 전면 보류, 프로젝트 좀보이드 변환/가구 제작 제외.
