# TEX04-R006 — 신규 9개 아이템 정적 모델 라우팅 검증 + R005 재현 코드 정오표

## 새로 직접 읽은 소스 (R005에 없는 신규 검증)

사용자 제공 GitHub `1.21.11/assets/minecraft/items/{color}_wool.json` 9개를 직접 열어 UTF-8 JSON으로 구문 분석하고, 각 소스의 Git blob SHA를 `ITEM_MODEL_9_SOURCE_LINKS.csv`에 남겼다. 이번 것은 **새 PNG가 아니라, 기존 9색 양털의 아이템 표시용 JSON 소스 파일 9개와 정적 참조 9건**이다.

- 9개 모두 최상위 필드가 `model`이고, `model.type = "minecraft:model"`.
- 9개 모두 `model.model = "minecraft:block/{해당 색}_wool"`로, R005에서 본 해당 색 block leaf 모델을 가리킨다.
- 아이템 정의의 관찰된 9개 JSON에는 다른 분기·랜덤 선택·아이템 상태에 따른 대체 모델이 기재되어 있지 않다. 이는 **이 9개 소스의 정적 JSON 사실**로만 해석하며, 게임 전체의 상황별 표시/조명/렌더링 방법까지 배제한 것은 아니다.
- 직접 확인한 신규 소스 파일: **9개**. 신규 모델 참조: **9개**. 신규 고유 PNG **0**, 신규 픽셀 **0**, 신규 모델 face **0**. 기존 R001 2,304픽셀/R003 54면/R004 30파일 SHA384 체인 및 R005 126건 새 지표는 **계승만** 한다.

## R005 재현 스크립트 오류 발견 및 정오표

발행된 `TEX04-R005/REPRODUCE_R005.py`의 PNG signature 검사는 실수로 역슬래시를 한 번 더 이스케이프한 `b"\\\\x89PNG\\\\r\\\\n\\\\x1a\\\\n"` 리터럴을 사용한다. 이 리터럴은 8바이트 PNG 시그니처가 아니라 17바이트 ASCII 역슬래시 포함 문자열이다. 따라서 R005의 재현 스크립트는 해당 `assert raw[:8]` 지점에서 실패한다. **R005의 직접 측정 결과·CSV 원본과는 별개인, 공개된 재현 코드의 결함**이다.

R005 파일은 절대로 덮어쓰지 않고, 이 릴리스에 원본에 대한 수정판 `REPRODUCE_R005_FIXED_PLUS_ITEM_GATE.py`를 새로 두었다. 수정 코드는 PNG signature를 `b"\\x89PNG\\r\\n\\x1a\\n"`로 정정하고, 새로 확인한 아이템 정의 9개의 JSON `model.type`/`model.model` 검사를 추가했다. 재현 시 루트는 사용자가 제공한 `1.21.11/` 디렉터리로 지정한다.

**실행 검증 범위:** 결함과 수정안의 Python 바이트 리터럴을 직접 계산해 각각 17바이트와 8바이트임을 확인했다. R005 지표 원본은 사용자 제공 PNG 9개를 직접 Python에서 디코딩해 실측했다. 다만 여기 게시한 **수정판 스크립트 전체를 GitHub 업로드 후 외부 사용자의 원본 디렉터리에서 끝까지 재실행했다고 주장하지 않는다.**

## 검증 및 제한

- `SOURCE`: 사용자 추출 디렉터리. 9개 아이템 JSON 직접 확인.
- `UV`: 아이템 JSON은 기존 색상별 block leaf로 링크됨; 추가 UV 또는 model geometry가 생겼다고 세지 않음.
- `RUNNING GAME`: 실제 GUI/인벤토리/블록 화면 스크린샷 검증은 **0/9**로 유지.
- `OFFICIAL`: 사용자 정책상 공식 client.jar 전체 SHA1/공식 메타데이터 인증은 **필수 완료 분모에서 제외**, 공식 검증이 성공했다는 뜻은 아님.
- 애니메이션·가구 모델 제작·PZ 변환 보류.
