# TEX04-R001 — Minecraft 1.21.11 직물·양털 9개 원본 미러 재검증

**검증일:** 2026-11-13 · **담당 단계:** `1-1-04`만 · **신규 결과 버전:** `TEX04-R001` · **전체 기존 체크포인트:** `v38` 유지.

## 요약 및 계수의 의미

- A–E의 정적 소스 검사: **양털 9/9개**, 새로 받은 **PNG 바이너리 9개**를 SHA-256 재계산, PNG 모든 청크 CRC-32 대조, RGBA 디코딩 후 픽셀별 재측정. 기존 v4의 9개 기록과 SHA 및 주요 계측 수치 일치.
- 실제 **독립 고유 RGBA 픽셀 2,304개(9×256)** 조사. 모두 16×16, PNG indexed-color PLTE, 256/256 완전 불투명.
- 정적 연결: **9개 blockstate + 9개 모델 + 2개 공통 템플릿** 확인. 정육면체 6면 × 9개 = **54개 소스 기반 면·텍스처·암시적 UV 연결**. 면별 참조 texel 총수 13,824은 중복 참조량이며 2,304개와 합산하지 않는다.
- F 공식 Mojang `client.jar` 해시/버전 원본 인증 **0/9**, 실제 게임 정적 장면 확인 **0/9**. 현재 근거 수준은 **`mirror_sha_pixel_checked`**일 뿐 공식 인증이 아니다.
- **G** 보고서, 출처별 CSV, RGBA 지표, 정적 UV 원장, 요약 JSON, 방법 기록과 단계 인수인계 상태를 저장함. 다른 분류의 성과와 합산 금지.

## A — 레거시 재사용과 중복·출처 조사

`STATE.json`·독립 단계 HANDOFF·상세 작업표·`v4_150/01_누적150종_픽셀측정.csv`·150 번호 원장에서 동일한 9개 `texture_id`, 원본 경로, v4 SHA-256이 일치한다. v4의 관찰 근거 유형은 `mirror_png_pixel_measurement`이고 **공식 JAR 검증은 아니었다**. v35의 16PNG-v4 교차표와 v36 544모델 과거 SHA 표에는 선택 `*_wool` 경로가 0개였으며, v37 화로/용광로, v38 오크 선반 계측은 본 분류에 중복 집계하지 않았다.

## B — 원본 바이너리 새 검사

- 미러 브랜치: [`InventivetalentDev/minecraft-assets` / `1.21.11`](https://github.com/InventivetalentDev/minecraft-assets/tree/1.21.11).
- 파일별 SHA-256 일치 **9/9**, 실제 파일 바이트: 360~399바이트, PNG 청크 구조는 9개 모두 `IHDR;PLTE;IDAT;IEND`, 청크 CRC 전부 통과.
- 9개 Git blob SHA는 **원본 PNG SHA-256과 해시 알고리즘·대상 의미가 다른 Git 객체 식별자**다. `SOURCE_LEDGER.csv`에 각각 별도 기록.
- **원본 공식성 미확인:** 단지 버전명이 `1.21.11`인 추출 미러의 파일이며 Mojang 공식 JAR과 대조하지 않음.

## D2 — 미세 패턴·저대비·방향성·반복

- RGB 인접 변화량: 가로 **4.3861~9.9417**, 세로 **7.9458~17.9042** (8비트 RGB 채널의 평균 절댓값). 세로/가로 비 **1.7648~1.8116**, 전 색상에서 세로 방향 색 변화가 더 크다. 따라서 **균일 무방향 랜덤 노이즈**로 단정할 수 없다.
- 9색의 256개 위치별 밝기 순위 Spearman 상관: 36쌍 중 **0.999237~0.999991**; 형태가 강하게 상응하지만 PNG 팔레트·실제 RGB 값이 같지는 않음.
- 밝기 상대 변동계수: 흰 0.05286, 검정 0.35514. 절대 명암 폭과 **기본색 대비 상대 명암**을 별개로 해석할 것. 검정을 일률적으로 '낮은 대비'라고 처리할 수 없다.
- 인접 RGB 정확 일치 비율은 **0.03750~0.05833**. 대체로 미세 색 변화가 풍부한 정적 16×16 패턴이며, 실/직조 방향·두께 같은 실제 물성은 이미지 단독으로 증명할 수 없다.
- 가장자리 이음매 차이도 `RGBA_METRICS.csv`에 기록. 특정 UV 반복 경계의 실제 인게임 시각적 무봉합 여부는 아직 정적 장면으로 검사하지 않았으므로 보류.

## D3 — 소스 사실 vs 가구용 디자인 가설

**검증된 사실:** 각 양털은 16×16 불투명 팔레트 이미지, 유사한 위치별 미세 무늬, 하나의 블록 전면에 동일 텍스처를 쓰는 정적 JSON 구조를 가진다.

**디자인 가설 / 확정 금지:** 추후 가구의 쿠션, 베개, 패브릭 좌면에 '저해상도 다색·잔무늬' 표현을 응용할 수 있다. 실제 쿠션의 봉제선, 푹신함, 섬유 길이, 광택, 현실 물성, 방석 UV 배치 규칙을 양털 PNG로부터 사실처럼 추론하지 않는다. 실제 가구 모델링/변환 작업은 진행하지 않음.

## E — 정적 blockstate → 모델 → UV 근거

- 각 `blockstates/{color}_wool.json`의 `variants[""]` → `minecraft:block/{color}_wool`.
- 각 `models/block/{color}_wool.json` → 부모 `minecraft:block/cube_all`과 `textures.all= minecraft:block/{color}_wool`.
- 공유 `cube_all.json`의 6면 texture slot은 모두 `#all`, `cube.json` 원소는 `from=[0,0,0]` ~ `to=[16,16,16]`, 6면 중 각 면 `cullface` 지정.
- `cube.json`의 face에는 **명시적 `uv` 배열이 없다**. 16×16 전체 면을 사용하는 **암시적 기본 UV `[0,0,16,16]`**로 해석했다. 완전 면 샘플링 범위는 원본 PNG x=0..15, y=0..15.
- 면마다 별도의 PNG가 존재하거나, 54개 면을 게임 화면에서 실제로 관찰했다는 주장은 하지 않는다. 전체 54행의 면별 상속·슬롯·UV·모델 해시는 `UV_FACE_LEDGER.csv`에 저장.

## F — 미인증·재확인 목록

- 공식 Mojang Java 1.21.11 `client.jar` 원본, 런처 버전 메타데이터, JAR 내 PNG와 미러 SHA-256 9개 대조: **미실시**.
- 인게임 양털 9색을 고정 조명/카메라/리소스팩 조건으로 촬영해 정적 PNG·블록 면 렌더와 비교: **미실시**.
- GPU 보간, 밉맵, 생물군계/조명 영향과 실제 거친 표면 느낌: 원본 PNG·JSON만으로 확정 불가.
- **애니메이션 프레임, 키프레임, 움직임 연구 전면 보류**. 기존 동적 자료는 삭제하지 않았다.

## G — 저장된 결과물과 다음 단계

`SOURCE_LEDGER.csv`는 파일 SHA·바이트·Git 객체·검증 tier를, `RGBA_METRICS.csv`는 실제 재측정 값을, `UV_FACE_LEDGER.csv`는 54면 정적 source chain을, `SUMMARY.json`은 기계 판독 상태를 보존한다. 같은 단계의 다음 결과는 GitHub `STATE.json` 재조회 후 `TEX04-R002`를 사용한다. 다음 중점은 공식 JAR와 인게임 정적 인증이다. 전체 `v38`과 다른 1-1-xx 단계는 갱신하지 않았다.
