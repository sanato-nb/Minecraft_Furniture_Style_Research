## C/D2 — 512개 2×2 조합 전수 재계산, 오차의 의미
두 PNG에 대해 이미지 평면에서 0°,90°,180°,270° 시계방향으로 돌린 4종을 생성한다. 각 텍스처에 대해 2×2 타일의 4^4=**256개** 조합, 합계 **512개** 조합을 계산했다. 각 조합의 4개 인접 경계에 16 RGB 픽셀쌍, 총 **64개 3채널 RGB 픽셀쌍**을 비교.
- 경계 MAE: **4 × 16 × 3 = 192개 채널 절대차의 합 / 192** (0~255, 낮을수록 색 맞춤).
- RGB 완전 일치 픽셀쌍: 각 경계의 대응 두 RGB 3채널이 전부 동일할 때 1개로 센다(64쌍 중 몇 개인지).
- 0~270° 두 회전 사이의 모든 4×4 수평/수직 MAE와 완전일치 16쌍 계수는 `EDGE_SEAM_PAIRWISE.csv`, 총 512개 조합·방향 가설·각 면 점수는 `TOP_FACING_2X2_512_COMBINATIONS.csv`.

| 검사항목 | 검정 유광 | 흰색 유광 |
|---|---:|---:|
| 최적 이미지 시계방향 2×2 `[TL,TR,BL,BR]` | `[180,270,90,0]` | `[0,90,270,180]` |

## D3/E — 모델 블록 상태와 이미지 평면 회전의 대응 가설

R001에서 직접 검수한 정적 `template_glazed_terracotta.json`은 `up` UV=[0,0,16,16], UV rotation=0이고, 두 유광 블록의 `blockstates`는 `south→model_y=0`, `west→90`, `north→180`, `east→270`. UV 방향 자체와 모델 Y축 회전은 별개의 변환이다.

- 화면 위쪽을 북(-Z)으로 보는 통상 수평 좌표에서 오른손좌표계 모델 Y축 회전 `y`를 PNG 이미지 시계방향 `cw = (-y) mod 360`으로 연결한 **수학적 가설**에 따라 최적 배치의 `[TL,TR,BL,BR]` facing 후보는 다음과 같다.
- **검정**: `north / west / east / south`; **흰색**: `south / east / west / north`.
- 반대 뷰 투영 `cw = y` 민감도 검사를 적용하면 **검정**: `north / east / west / south`, **흰색**: `south / west / east / north`.
- **절대 주의**: 이것은 게임 렌더러의 면별 최종 UV 투영과 렌더 변환을 구동해 검증한 결과가 아니다. 위 두 후보를 인게임 확정 방향으로 사용하면 안 된다. 결과는 직접 PNG 색 자료 + R001 정적 JSON에서 **추론한 연결 후보**뿐이다.
- 원본 모델은 면마다 서로 다른 `rotation` 값을 갖고 있으므로 옆면은 상단 이미지와 같은 회전으로 단순 복사하지 않는다. R001의 UV_FACE_ROTATIONS.csv를 우선 참고.
