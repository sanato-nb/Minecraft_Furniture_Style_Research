# TEX06-R008 — 애니메이션 연구 보류 해제 및 테라코타 8종 프레임·메타데이터 실측

**Minecraft Java 1.21.11 · 1-1-06 도기·유광도기 · 2026-11-13 · R007 계승 · 전체 v38 불변**

## 범위 변경 (최신 사용자 요청)
사용자 요청 **"그럼이제 애니메이션하자"**에 따라 **이 1-1-06 전용 단계의 애니메이션 연구 보류를 해제**했다. 그 대신 **인게임 검증·Mojang 공식 압축 JAR SHA-1 인증은 기존 사용자 지시대로 연구에서 계속 제외**한다. 실제 애니메이션이 없는 재질에 프레임/키프레임/재생속도를 임의 생성하지 않는다.

## A — 1차 원본 8개 직접 검사 (새 증거)
GitHub `sanato-nb/Minecraft_Furniture_Style_Research`의 사용자 추출본 `1.21.11/assets/minecraft/textures/block/` 안에 존재하는 **고정 8 PNG 원본 바이너리(base64)를 직접 읽어** PNG signature, 각 IHDR/PLTE/IDAT/IEND 및 CRC32를 전수 재검사했다. **8/8 모두 가로16×세로16**, APNG `acTL` 청크 **0/8**, 모든 파일이 1개의 16×16 정적 프레임으로 구성된다. 이전 R007의 사용자 PNG SHA256 검증 결과를 계승하며 **이번 R008에서는 독립 SHA256을 다시 계산했다고 주장하지 않는다**. 파일별 Git blob SHA 및 바이트 수는 `SOURCE_ANIMATION_AUDIT_8.csv`.

각 8개의 `<texture_id>.png.mcmeta` 상대 경로를 **저장소 실제 파일 요청으로 직접 조회했으나 모두 404 Not Found(0/8)**. Minecraft 기본 리소스팩에서 흔히 쓰는 `animation.frametime`, `animation.frames`, `animation.interpolate` 정의가 해당 8종에는 없다. 기존 R003/R004에서 이 8종 블록·아이템의 모델/상태 JSON은 정적 모델·facing 회전으로 연결됐으며, 이는 프레임 애니메이션 선언과 다르다.

### 고정 8종 결론
`terracotta`, `white_terracotta`, `orange_terracotta`, `blue_terracotta`, `green_terracotta`, `yellow_terracotta`, `black_glazed_terracotta`, `white_glazed_terracotta` = **8/8 소스 정의상 정적**, 애니메이션용 그림 프레임 추가 **0**, 메타데이터 **0**, 키프레임/타임라인 **해당 없음**. 블록의 특정 `facing`으로 무늬가 회전돼 보이는 것은 프레임 재생이 아니다.

## B — 같은 추출본의 실제 애니메이션 양성 대조군 (이 단계 8개에는 불포함)
`*.png.mcmeta` 파일을 정상 읽을 수 있는지 검증하기 위해 **단계 외 다른 5종의 원본 PNG·JSON을 직접 열어** 프레임 슬롯 수와 재생 메타데이터를 확인했다. **이 5종은 1-1-06 완료 개수 및 텍스처 8종에 절대로 더하지 않는다.**

| 단계 외 대조 텍스처 | PNG 해상도 | 원본 16×16 프레임 슬롯 | 메타데이터 재생 순서 길이 | frametime (tick) | 특징 |
|---|---:|---:|---:|---:|---|
| water_still | 16×512 | 32 | 32 (암묵적) | 2 | 전체 32프레임 순서 재생 |
| lava_still | 16×320 | 20 | 38 (명시적) | 2 | 앞뒤 왕복형 프레임 배열 |
| fire_0 | 16×512 | 32 | 32 (명시적) | 1 (기본값) | 16부터 시작해 0으로 돌아가는 재생 순서 |
| sea_lantern | 16×80 | 5 | 5 (암묵적) | 5 | 5프레임 순서 재생 |
| prismarine | 16×64 | 4 | 22 (명시적) | 300 | `interpolate=true`, 반복 선택 프레임 |

5개 `.mcmeta`의 출처 blob SHA·재생 조건은 `ANIMATED_POSITIVE_CONTROLS_5.csv`에 보존. 표의 tick·보간 여부는 **자산 파일 선언**, 실제 게임 실행에서 측정한 FPS나 물리 시간은 아니다. 프리즈머린의 22개는 독립 PNG 프레임 22개가 아니라 **원본 4개 프레임 인덱스의 재생 순서 항목 22개**다.

## C — 재현과 경계
- `REPRODUCE_ANIMATION_SOURCE_AUDIT.py`는 사용자 추출본 디렉터리를 루트로 실행하여 8개 PNG의 서명·CRC/청크·해상도·사이드카 메타데이터 부재를 확인하고, 5개 대조군의 `.mcmeta` 내 `animation` 설정과 실제 PNG 프레임 인덱스 범위를 검사한다. Python 표준 라이브러리만 필요.
- R007까지의 8종 정적 RGBA·UV 연구는 그대로 유효하다. 이번 새 증거는 `8개의 animation sidecar 부재`와 `8개의 단일 PNG 프레임 및 APNG 부재`, 다른 단계의 `5개 양성 대조`다. 이미 검증한 동일 PNG를 새 고유 화소 또는 새로운 고유 텍스처로 누적 계산하지 않는다.
- 이 결과로 확인한 것은 **Minecraft 1.21.11 제공 추출 자산에서 해당 텍스처의 기본 PNG/메타데이터 기반 프레임 애니메이션 부재**다. 엔진 커스텀 렌더·모드·외부 리소스팩에 의한 임의 시각 변화까지 증명한 것은 아니다. 사용자가 제외한 인게임 캡처를 요구하지 않는다.
- 이 8종에서는 후속 **실제 애니메이션 프레임 연구 대상이 0종**이므로 필요한 애니메이션 과업은 완료. 물·용암·불 등 단계 외 실제 애니메이션은 별도 적절한 단계에서 연구. 원본 모델 연구 전체 완료라는 주장은 아니다.
