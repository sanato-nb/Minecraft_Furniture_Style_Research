# TEX07-R006 — 사용자 제공 콘크리트 PNG의 방향성·공간 자기상관·최대 경계 이상치 실측

2026-11-13 · Minecraft Java 1.21.11 · 범위 **1-1-07의 지정 7개 콘크리트 텍스처만**. R005 이후 **신규 공간 지표를 실제 픽셀에서 계산한 증거 기반 릴리스**. 글로벌 v38, 다른 1-1 단계, R001–R005 불변.

## 1. 조사 근거와 중복 방지

- GitHub `1.21.11/assets/minecraft/textures/block/{white,black,red,blue,green,yellow,gray}_concrete.png` 7개를 연결된 GitHub에서 **base64 원본 바이트로 직접 확보**. 독립 Python 3 + NumPy + Pillow에서 디코드하고 SHA-256, Git blob SHA-1 및 **PNG 모든 청크 CRC32/최종 IEND** 재계산 후 7/7 기존 사용자 추출본과 일치. 크기 153~227 bytes, 각 16×16 RGBA 변환 알파 255.
- 원본 `models/block/<color>_concrete.json` 7개와 `cube_all.json`, `cube.json`, `block.json`, `blockstates/white_concrete.json`을 직접 다시 읽음(정적 JSON 11개 재열람). 7색 블록 모델은 모두 `parent=minecraft:block/cube_all` 및 각 `textures.all`에 해당 색만 선언. 다른 6색의 blockstate·item JSON은 **이번 릴리스에서 새로 검사했다고 주장하지 않음**(R003 31파일 조사에서 계승).
- **입력으로 새롭게 추가된 고유 PNG 0개**, **이미 검증됐던 7개 PNG 재열람**, **이전 42면 전체 UV 참조를 새 관측 42면으로 중복 산정하지 않음**. 신규 작업은 동일 원본 픽셀 1,792개에 대한 *새 공간 지표 7행*의 계산이다.
- 직접 계측 코드의 원본 바이트 입력은 GitHub 연결에서 받은 PNG 파일이며, 공개된 출력에는 원본 PNG 바이너리를 복제하지 않는다. 동일 경로/해시를 사용해 `REPRODUCE.py`로 재계산 가능.

## 2. 신규 측정 정의 — R002 경계 평균과 별개

각 PNG의 sRGB 정수 채널에 `Y=.2126R+.7152G+.0722B`를 적용한다. 이 `Y`는 **8비트 sRGB 가중값이며 선형 광도나 실제 화면 휘도가 아니다**. `Y_std_population`는 256픽셀 모집단 표준편차; `Y_range`는 최댓값−최솟값.

- `luma_corr_wrap_x1/y1`: 평균 제거 휘도를 ±1픽셀 **순환 이동**한 뒤 공분산/원 휘도 분산으로 정규화. 두 방향의 단기 노이즈 연관도를 비교.
- `best_nonzero_toroidal_corr`: (dx,dy) 0~15 중 (0,0)을 제외한 **255개 토러스 이동**에서 최대 정규화 자기상관 및 해당 오프셋. 7개 PNG로 총 1,785개 이동 평가. 양 끝이 실제로 연결된다고 가정하는 **분석용 순환 샘플링**이며 화면 보간 증거가 아니다.
- `max_lr_seam_Y`: 원본 16개 행의 오른쪽 끝↔왼쪽 처음 값 절대차 **최대값**, `max_tb_seam_Y`: 16개 열의 아래 끝↔위 처음 **최대값**. 두 종류 합 224개 경계쌍.
- `max_interior_adjacent_Y`: 가로 내부 240쌍과 세로 내부 240쌍의 절대 휘도 차이 중 최대. `*_seam_pairs_gt_max_interior`: 이 내부 최대값을 **엄격히 초과하는** 경계쌍의 수.
- `identical_row_pairs/identical_column_pairs`: 서로 다른 16개 행 또는 열 사이의 **정확한 RGB 전체 일치쌍** 개수(각 120개 조합). 기존 R002 평균 경계 비율과 달리 최대값·상관·완전 반복을 독립 감사.

- **7개 모두 경계 32쌍 중 내부의 최대 인접 휘도차를 엄격히 초과한 사례 0**. 따라서 이번의 *최대값 기준*에서는 별도 심각한 원본 PNG 경계 이상치를 발견하지 못함. 다만 R002의 red·blue·gray에서 특정 방향의 **평균 seam/internal 비율이 1 초과**였다는 관찰은 그대로 유효하며 이번 결과와 모순되지 않는다.
- 7색 `Y_range`는 **2 또는 3**, 모집단 `Y_std`는 **0.532111(gray)~0.995220(black)**. 원본 색면의 미세 변동은 매우 작다. 픽셀 채널 가중 수치일 뿐 실제 조명/디스플레이 체감 대비가 아니다.
- 255개 비영점 이동 최고 상관은 각 PNG에서 **0.127647~0.201964**, 정확히 동일한 행·열 쌍은 7개 모두 0. 이는 원본 16×16 내부에서 관찰된 수치다. 16픽셀 단위로 텍스처를 반복 배치하면 원본 패턴 전체가 되풀이된다는 **수학적 재사용**과 게임 화면의 육안 검증은 다르다.
- 신규 오류 확정: **0건**. 후속 테스트 후보: 실제 16×16 반복 블록 표면과 기하 면 경계에서 red·blue·gray 평균 이음 신호가 시각적으로 나타나는지, 외부 조명·밉맵·리소스팩 변화 없이 정적 캡처로 확인. 우선순위 후보일 뿐 소스만으로 실제 오류/정상 동작을 확정하지 않는다.

## 4. E UV·상태의 근거 경계

이번 직접 재열람에서 7개 색상별 block model이 여전히 동일한 `cube_all` 부모와 색상별 `#all` 슬롯을 사용한다. R004에서 분석한 공통 `cube` **6면×7색=42면 선언**, UV 명시 0 / 기본 풀큐브 [0,0,16,16] 파생 42, 면별 `cullface`와 공유 display 7컨텍스트는 그대로 **역사 자료에서 계승**. 이번 R006에서 **새 모델 기하 0개, 새 face 선언 0개, 새 UV 좌표 0개**. 텍스처의 순환 이동 분석은 게임 엔진이 어떤 방향으로 실제 UV 샘플링하는지 재현하지 않는다.
