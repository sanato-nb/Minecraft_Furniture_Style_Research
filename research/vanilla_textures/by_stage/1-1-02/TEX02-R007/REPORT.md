# TEX02-R007 — 정적 모델 회전의 면별 UV 좌표·정적 픽셀 이음새 후속 검증

**날짜:** 2026-11-13 · **한정 범위:** `1-1-02` 석재·벽돌 고정 표본 17개 · **새 고정 PNG 추가 0개** · 사용자 제공 `1.21.11/` 직접 파일 최우선. 기존 `TEX02-R006` 후속이며 `v38` / 타 단계 무변경.

## 신규로 실제 진행한 항목

1. 사용자 추출 `1.21.11/assets/minecraft/blockstates/`의 **17개 JSON**, `models/block/`의 기본 17개 모델·대체 모델 2개·공유 부모 7개, 총 **43개 JSON 경로를 직접 열람·원문 확인**. 각 Git blob SHA는 `SOURCE_JSON_SHA_LEDGER.csv`에 저장. 신규 고유 구조 발견 수와 파일 재열람 수는 구별한다.
2. 기존 R004의 **31 선언/186면**을 계승해, 각 면의 **world 법선 방향뿐 아니라 U/V 이미지 축의 두 벡터, 2×2 부호 행렬 및 네 모서리의 `(u,v)`**를 이번에 계산. **새 좌표 집합 186개(각 4 꼭짓점, 744 좌표쌍)**이며 R004 기존 186면을 신규 186면으로 중복 증가시키지 않는다.
3. 새로 투영한 **UV 방향 조합은 8종**. 186면 기준 분포: `[1,0;0,1]` 116면, `[-1,0;0,1]` 26면, `[-1,0;0,-1]` 10면, `[1,0;0,-1]` 10면, `[0,-1;1,0]` 8면, `[0,1;-1,0]` 4면, `[0,1;1,0]` 8면, `[0,-1;-1,0]` 4면. 모든 행에서 `|det|=1`, UV 꼭짓점은 0 또는 16.
4. 원본 PNG 중 **기존 6개**(`stone`, `deepslate`, `deepslate_top`, `bricks`, `stone_bricks`, `deepslate_bricks`)를 재해독하여 바이트 SHA-256/CRC/불투명 16×16을 확인하고, world 북쪽 면의 **소스 투영 이미지를 이용한 새 134개 인접 후보**를 계산했다. 134 × 16 = **2,144 경계 픽셀 쌍 / 6,432 RGB 채널 차이**. 6개는 R006에서 사용된 **기존 이미지**, 신규 PNG 추가 0개. R006의 이전 192개 가상 2D 변환 비교는 신규 결과로 재가산하지 않는다.
5. 134개는 선언된 동등 재질·축 속성 안에서 순서 있는 조합만 비교: stone 4²×2=32, deepslate axis=x/y/z 각각 4²×2=32(96 합계), 벽돌 세 텍스처 각각 1²×2=2(6 합계).

## 소스 해석 대 수학적 가정의 경계

**소스 원문에 명시된 사항:** 모델 `cube`과 `cube_mirrored`은 6면 큐브; `cube_mirrored`의 6면 모두 `uv=[16,0,0,16]` 명시. `cube_all`·`cube_column` 등 부모를 통해 #all/#side/#end를 텍스처 경로에 연결. `stone`의 기본/미러·Y180, `deepslate`의 axis=x/y/z 회전·미러 상태. `bricks`, `stone_bricks`, `deepslate_bricks`는 상태 회전 분기 없음. `deepslate` axis=x 원본 동일 선언 index 0=2, 1=3은 **기존 R004 발견 2건**.

**본 R007 계산에서만 둔 가정(인게임 인증 아님):** 자동 UV가 생략된 cube 면의 표준 축을 north(-X,-Y), south(+X,-Y), east(-Z,-Y), west(+Z,-Y), up(+X,+Z), down(+X,-Z) (각각 U,V)로 둠. 회전 부호는 `X90: up→south`, `Y90: north→east`, **X 먼저 Y**. 월드 면당 정규화한 접평면 좌표에 투영하여 픽셀 중심 좌표를 매핑. 실제 `FaceBakery`, UV 잠금(`uvlock`), 텍스처 보간, 랜덤 선택, 조명과 컬링을 구현하지 않았다. 따라서 8종 행렬은 **명시적 가정 하의 계산 결과**이지 엔진 결과/스크린샷 검증이 아니다.

## R006 대비 새로 해결한 빈틈과 아직 남은 문제

- R006의 `R90_screen_CW` 등 4개 일반 2D 변환과 실제 blockstate X/Y 회전은 혼동 위험이 있었다. R007은 **모델 face → 월드 face → UV U/V 접평면 → PNG 픽셀**을 구분해 기록했고, R006만으로는 빠진 대각 전치/수직 반전 등 8개 방향 행렬의 존재를 소스 기반으로 도출했다.
- **고정 표본 17개**, 기존 총 PNG 17/17, RGBA 4,352픽셀, 31 선언/186 연결/중복 2개는 **계승**. 이번 6 PNG 재해독·43 JSON 열람·186 좌표 투영·134 비교만 이번 턴의 별도 성과이다.
- **F 인게임 정적 렌더 0/17, A–G 전체 완료 0/17** 유지. 정적 스크린샷/렌더러 동작 실측 부재. Mojang 전체 JAR SHA-1 공식 인증은 사용자 지시에 따라 연구·완료 기준 **제외(성공 아님)**. 애니메이션 전면 보류, PZ 변환·3D 가구 구현 금지.
- 다음 후보 `TEX02-R008`에서는 라이브 STATE 재조회부터 하고, 렌더 엔진 코드 혹은 인게임 캡처 없이 이 UV 투영을 **게임 화면 확인 완료**로 승격하지 말 것.
