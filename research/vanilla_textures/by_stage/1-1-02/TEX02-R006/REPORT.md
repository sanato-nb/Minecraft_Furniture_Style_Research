## 이번 작업에서 실제 새로 수행한 계산

1. 기존 17개 고정 PNG 중 **5개**(`bricks`, `stone_bricks`, `deepslate_bricks`, `deepslate`, `stone`)와 기존 보조 PNG **1개**(`deepslate_top`)를 원본 `1.21.11/assets/minecraft/textures/block/`에서 직접 다시 열었다. **새로 고유 표본에 추가한 PNG 0개**, 대상 17개 불변.
2. 해당 6개 파일 각각 SHA-256 재계산, PNG 청크 CRC 일치, 16×16, 256 RGBA 픽셀 불투명 확인. 이번 재열람은 총 **1,536 RGBA 픽셀**이며, 과거 R001의 17개/4,352픽셀·R003의 전체 PNG 무결성 검사와 **중복 누적하지 않는다**. 바이너리 SHA는 과거 기록과 일치.
3. **JSON 18개 직접 열람**: 블록상태 5개, 명명된 모델과 공유 부모 모델 13개. 경로별 Git blob SHA를 `JSON_SOURCE_LEDGER.csv`에 기록. 기존 R004의 전체 31 선언/186면을 다시 신규 실적으로 세지 않음.
4. 6장에 대해 **4×4×2 = 각 32개**, 총 **192개 가상의 2D 경계 접합**을 픽셀에서 새로 계산했다. 비교는 경계 16개 픽셀 × 3개 RGB 채널의 절댓값 차이 합계/48. 총 3,072 경계 픽셀 쌍(9,216 채널 차이)을 계산했지만, 픽셀 쌍은 재사용되므로 원본 고유 픽셀 수와 혼동 금지. `HYPOTHETICAL_UV_SEAMS.csv`에 192행 저장.
5. 변환: `I` 원본; `H_UV_reverse` 좌우 픽셀 반전(`[16,0,0,16]`에 대응하는 **면 내부 U 좌표만** 단순화); `R90_screen_CW`, `R180_screen` 2D 화면상 회전. **이는 실제 모델 회전·uvlock·면 버텍스·조명을 재현하지 않은 가상 인접 배치**이다. 재현 코드는 `REPRODUCE_SEAMS.py`.

**반례와 한계:** `I` 타일 오른쪽 경계와 좌우 반전 `H_UV_reverse` 타일 왼쪽 경계는 정의상 같은 x=15 열이므로 이 구성의 좌우 RGB 차이는 전 파일에서 정확히 0이다. 이는 전형적인 **인위적 2D 경계 동일성**이며 렌더러가 반전 모델을 그 방식으로 배치한다는 주장, 실제 줄눈 연속성·조명·UV 인증이 아니다. `stone_bricks`/`deepslate_bricks`의 원본↔180° 상하 0도 특정 대칭/픽셀 짝의 결과이지 게임에서 그 회전 상태가 선언된 것은 아니다.

## 원본 JSON에서 확인한 회전·UV 사실과 별도 추론

- `bricks.json`, `stone_bricks.json`, `deepslate_bricks.json` blockstate는 **각 1개 기본 variant**만 선언한다. 각각 `cube_all` 부모의 `#all` 슬롯을 사용. **블록상태의 90°/180° 회전 분기가 없다.** 위 가상 회전 숫자를 실제 벽돌 랜덤 회전으로 설명하면 잘못이다.
- `deepslate.json`은 `axis=x/y/z`의 X/Y 회전과 `deepslate_mirrored`를 명시한다. `cube_column`의 `#side`는 `deepslate.png`, `#end`는 `deepslate_top.png`를 가리킨다. `cube_mirrored`은 6면 전부 명시 UV `[16,0,0,16]`을 가지며, `cube_column_mirrored`은 그 부모를 사용한다.
- `deepslate axis=x` index 2는 0, index 3은 1과 정확히 중복(선행 R004에서 확인한 **기존 2건**, 신규 중복 발견 아님). `stone`은 기본/미러 및 Y180 조합 4개를 선언한다.
- R004 `world_face_math_hypothesis`는 모델 면의 **법선 방향**에 대한 수학적 가설이다. 그 열만으로 UV의 화면상 U/V 방향, 렌더러의 회전 부호·`uvlock` 처리, 이웃 블록 줄눈 픽셀의 실제 대응, 조명/필터/시야를 결정하지 못한다. 특히 deepslate axis 회전 ↔ 위 `R90_screen_CW`는 같은 변환이라고 주장할 수 없다.
- 공식 Mojang 전체 `client.jar` SHA-1·메타데이터 인증은 사용자 요청에 따라 **연구/완료 분모에서 제외**; 인증 완료라고 주장하지 않음.
- 실제 Minecraft **인게임 정적 스크린샷/실측 0/17, 미검증**, A–G 전체 완료 0/17 그대로. 애니메이션·Project Zomboid 변환·가구 3D 모델 제작은 제외/보류.
