# TEX02-R011 — 원본 1.21.11 회전 그룹 검증과 R007 월드면 방향 32건 정정

**연구 단계:** `1-1-02` Minecraft Java 1.21.11 석재·벽돌 17개 고정 표본

**연구 성격:** 기존 가정을 무조건 유지하지 않고, 사용자 제공 클라이언트 `.class`를 확인하여 **기존 R007의 일부 기하학적 투영 오류를 식별한 교정 릴리스**. **Minecraft 게임을 실제 실행하거나 GPU 렌더 데이터를 관찰한 것은 아니다.**

## 1. 원본 클래스의 실측 근거

GitHub 사용자가 올린 추출물 `1.21.11/`에 있는 새 클라이언트 클래스 2개를 바이너리/base64로 **직접 열람**했다.

- `f.class` (Git blob `f2723f067abf293075e66021711ce37387c92def`, 11,957 bytes): 그룹 `f`의 **48개 원본 signed-permutation 회전/반사 상수**를 클래스 초기화 바이트코드에서 직접 판독. 관련 고정 상수 `f.a, f.b, f.c, f.d, f.l, f.r, f.s, f.u`의 원본 이름·축 순열·부호 반전 비트를 확인. `Matrix3f.scaling(...).mul(h.b())` 조합으로 그룹 행렬을 생성하는 메서드 근거.
- `h.class` (Git blob `c4594ee6c1938cf051fcb5968a3c108788ffe1ac`, 5,699 bytes): **6개 축 순열** 정수를 확인. `h.a=(0,1,2)`, `h.b=(1,0,2)`, `h.c=(0,2,1)`, `h.d=(2,0,1)`, `h.e=(1,2,0)`, `h.f=(2,1,0)`. `Matrix3f.zero().set(column,row,1)` 조립 경로 근거.
- 지난 R009와 R010에서 열람했던 `g.class` (blob `f4883aaac8f997dceb60b8f5e9a076e7a16c6fef`)·`inm.class` (blob `672b186c8a8457082fec756114b443a48dc151d1`)를 다시 참조했다. **이전 원본은 신규 2개에 재가산하지 않는다.**
- `g.class`의 `g.a(gx,gy,gz)` 메서드는 `Z ∘ (Y ∘ X)` 순으로 회전 그룹을 합성한다. 이름은 `x,y,z` 좌표 순서지만 **JSON `90`에 쓰이는 `g.b`의 X/Y/Z 축 내부 그룹 별칭은 모두 NEG 회전**이다: X `f.Y → f.s = ROT_90_X_NEG`, Y `f.ab → f.u = ROT_90_Y_NEG`, Z `f.ae → f.w = ROT_90_Z_NEG`.
- 지난 R010에 확인한 `inm` 일반 ModelState는 `f.b()` 3×3 회전 행렬을 `Matrix4f(Matrix3fc)`와 `i` 위치 변환으로 전달하고, `uvlock=false` 경로의 면 UV 보정 행렬은 항등행렬이다. 즉 **모델 좌표 회전**과 **UV 잠금 회전**을 구별해야 한다.

GitHub 소스 blob 및 R007/R010 중간 자료에 대한 참조는 `SOURCE_LEDGER.csv`에 기록. **Mojang 전체 JAR SHA-1 인증은 완료 기준 제외**이고 인증했다고 표시하지 않는다.

## 2. 17개 블록/31개 상태에 등장하는 원본 회전 행렬 5개

다음은 사용자 제공 `f/h/g` 클래스 초기화 및 행렬 합성 로직에 근거한 **3×3 모델 좌표 회전행렬**. 행은 모델 공간 벡터 `(X,Y,Z)`에 대한 출력 `(X',Y',Z')` 순서. 전체 행렬은 `ROTATION_GROUP_MATRICES_5.csv`에 포함.

| blockstate (x,y,z) | f 그룹 상수 | X' | Y' | Z' | 등장 변형 |
|---|---|---|---|---|---:|
| (0,0,0) | f.a = IDENTITY | X | Y | Z | 19 |
| (0,180,0) | f.c = ROT_180_FACE_XZ | −X | Y | −Z | 4 |
| (90,0,0) | f.s = ROT_90_X_NEG | X | Z | −Y | 2 |
| (90,180,0) | f.r = ROT_180_EDGE_YZ_POS | −X | Z | Y | 2 |
| (90,90,0) | f.l = ROT_120_PPP | Y | Z | X | 4 |

위 행렬 5종 모두 행렬식 +1. 이 5종은 R010에 이미 기록된 31개 blockstate의 (x,y,z) **원본 튜플 재사용**, 새로운 상태 수 0.

**방향 정정 사례:**
- `deepslate axis=x`, 모델 `x=90,y=90`: 로컬 `down` → 원본 그룹 행렬에서는 `west` (R007은 `east`), 로컬 `up` → `east` (R007 `west`), 로컬 `north` → `down` (R007 `up`), 로컬 `south` → `up` (R007 `down`). 로컬 east/west의 월드 방향은 이전 결과와 일치.
- `deepslate axis=z`, `x=90,y=0` 및 `x=90,y=180`: 위와 유사하게 각 90도 회전의 부호 해석 때문에 일부 up/down/north/south 대응이 역전됨.

## 3. R007 186개 월드면 방향을 전수 대조해 오류 32건 식별

`TEX02-R007/FACE_UV_WORLD_CORNERS.csv`의 186개 로컬 면/월드 면 관계에 R010의 동일 blockstate id/property/index를 대응시킨 뒤, 5개 소스 파생 회전 행렬로 로컬 법선 벡터를 곱하여 결과를 재생성했다.

| 그룹 | 검사 면 | 기존 R007와 일치 | 서로 다름 |
|---|---:|---:|---:|
| IDENTITY | 114 | 114 | 0 |
| ROT_180_FACE_XZ | 24 | 24 | 0 |
| ROT_120_PPP, `deepslate axis=x` | 24 | 8 | 16 |
| ROT_90_X_NEG, `deepslate axis=z` | 12 | 4 | 8 |
| ROT_180_EDGE_YZ_POS, `deepslate axis=z` | 12 | 4 | 8 |
| **합계** | **186** | **154** | **32** |

- `WORLD_FACE_AUDIT_186.csv`: 기존 186면 각각의 R007 방향 / 소스 회전 결과 / 차이 여부.
- `R007_WORLD_FACE_CORRECTIONS_32.csv`: 차이가 있는 32면만 별도 추출. 실제로 32건 모두 `deepslate`, `axis=x` 16건 / `axis=z` 16건.
- **교정 값은 모델 회전 그룹의 source-derived mathematical result**다. 실제 게임의 186개 baked quad 정점/UV 숫자를 추출하거나 렌더링을 시행해 확인한 결과라고 주장하지 않는다.
- 이전 R007 UV 코너 수치, R007의 134개 가상 이음새 수치 자체를 **자동 수정·확정하지 않는다.** 월드면 방향 154건이 일치한다는 사실이 이 154건의 최종 UV 코너값까지 입증하지는 않는다.

## 4. R007의 134개 가상 이음새에 미치는 영향

`TEX02-R007/SOURCE_PROJECTED_NORTH_FACE_SEAMS.csv`의 기존 134행 가운데 `deepslate axis=x` 32건 + `axis=z` 32건 = **64개 행을 재투영 필요로 분류**하여 `R007_NORTH_SEAM_REEVALUATION_64.csv`에 보존한다.

**64건이 반드시 수치 오류라는 뜻은 아니다.** R007의 전체 면 회전 기준 중 일부가 실제 소스의 회전 부호와 다르므로, 이 축 그룹의 north-facing 합성 이미지/UV 방향 해석을 R011 단계에서 **소스 검증된 값으로 사용할 수 없다는 뜻**이다. 나머지 70건 역시 인게임 측정으로 승격하지 않는다.

**중요:** 이번에는 PNG 픽셀을 다시 디코딩/측정하지 않았으므로 새 이음새 측정 0건이다. R007의 기존 결과를 삭제하거나 새 실적으로 중복 가산하지 않는다.
