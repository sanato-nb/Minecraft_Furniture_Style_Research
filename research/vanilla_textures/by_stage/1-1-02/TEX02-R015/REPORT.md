# TEX02-R015 — 블록 좌표→기본 렌더 시드→48-bit 난수→가중치 모델 선택의 원본 코드 경로 검증

- 작성일: 2026-11-13
- 연구 단계: `1-1-02`; 기존 17종 Minecraft Java 1.21.11 석재·벽돌 타일셋의 정적 모델 선택 추적
- 직접 주 증거: 사용자 제공 개인 GitHub `1.21.11/`의 원본 클래스 바이너리. 공개된 1.21.11 이름 매핑은 추적 대상을 찾는 보조 자료로만 사용하며, 아래 opcode·원본 SHA 판단은 **사용자 저장소 원본**에서 재확인했다.
- 기존 표본 17 PNG, 31 변형 선언, 19 선택 그룹, 모델 186면, 134개 합성 이음새, R011 방향32, R012 UV40/합성 seam64, R014 744개 vertex는 모두 **계승**한다. R015 신규 PNG·픽셀 실측·게임 실행 결과는 **0개**.
- 공식 Mojang JAR 전체 SHA-1 인증은 요청에 따라 단계 완료 필수 조건에서 제외되어 있으며 성공을 주장하지 않는다. 게임 자체를 실행하거나 GPU 베이크/렌더된 UV 및 실제 랜덤 선택 결과를 측정하지 않았다.

## 1. 원본에서 새로 확인한 월드 렌더 호출 경로

이번에는 이전 R013 `ioj/cbn` 가중치 선택 코드 **바깥쪽 실제 블록 렌더 준비 루프**까지 확인했다. 핵심적으로 원본에서 새로 직접 열람한 관련 클래스는 **10개**(`hpw,htp,hpy,hpv,eog$a,eog,bgj,eur,euf,evf`), 이전에 이미 조사한 `bgr,hqh,cbn,cbn$c,ioj` 5개와 R013 31-슬롯 CSV를 연결했다. `SOURCE_SHA_LEDGER_16.csv`는 원본 15개 클래스+선행 CSV 한 개의 SHA를 담고, `SEED_MODEL_DISPATCH_EVIDENCE_24.csv`는 24개 원본 method/호출 근거를 보존한다.

### A. 월드의 블록 파괴 오버레이 / `hpw.class`

`hpw.class`의 `a(Leoh;Lis;Ldvq;Lfzm;Lfzp;)V` (82바이트) 메서드:

1. 블록 모델 `hpv.b(blockstate)`를 얻는다.
2. `eoh.b(BlockPos)`로 그 블록상태의 렌더 시드를 얻는다.
3. **`bgr.b(seed)`로 난수 생성기 `hpw.e`를 재설정한다.**
4. 선택 부품 리스트를 비우고 `hqh.a(bgr,List)`를 호출해 변형을 선택한다.
5. 그 리스트를 `hpy`에 넘겨 tessellate한다.

가중치 선택 자체는 R013에서 직접 확인한 `ioj.a(bgr,List)` → `cbn.b(bgr)` → `bgr.a(totalWeight)`로 이어진다.

### B. 일반적인 월드 청크 메시 제작 / `htp.class`

`htp.class`의 `a(Ljw;Lhtn;Lfzr;Lhpd;)Lhtp$a;` (473바이트)에서는 청크에 들어 있는 블록 위치를 순회한다. 해당 메서드 내부에서 새 `bgr.a()`로 RNG를 마련하며, 각 모델형 블록 처리 시 **`eoh.b(BlockPos)` → `bgr.b(seed)` → `hpw.a(blockstate)` → `hqh.a(bgr,List)`** 순으로 모델 부품을 모은다. 이어 모아진 리스트를 `hpw.a(blockstate,pos,...,List)`에 전달한다. 따라서 **청크 전체에서 무작위로 진행하는 연속 난수 스트림**이 아니라, 각 블록 위치에서 **다시 시드를 맞춘 뒤 선택**하는 코드를 확인했다.

같은 블록/위치/리소스/선택지 조건에서 기본 시드가 같다면 청크 재빌드와 블록 파괴 오버레이의 첫 선택 슬롯도 일치하는 구조다. **이는 bytecode 정적 결론이며 실제 게임을 다시 그려 테스트한 것이 아니다.**

## 2. 기본 `BlockState.getSeed(pos)`의 실제 좌표 해시

`eog$a.class`의 `b(Lis;)J` (13바이트)는 블록상태의 소유 블록 `dzq.a(BlockState,BlockPos)`에 가상 호출을 위임한다. **따라서 블록 하위 클래스가 메서드를 재정의할 여지가 있다.** 기본 구현은 `eog.class`의 `a(Leoh;Lis;)J` (5바이트)로, 오로지 `BlockPos`를 `bgj.a(Vec3i)`에 넘긴다. `bgj.class`의 `a(Vec3i)` (16바이트)는 X/Y/Z 세 좌표를 읽고 `b(III)J` (35바이트)로 호출한다.

원본 `bgj.b(III)J`의 CP 상수를 실제로 검증:
- `3129871` — **x축 곱은 Java 32-bit `int` 곱셈으로 먼저 overflow**한 다음 long으로 확장.
- `116129781L` — z축 64-bit 곱.
- `42317861L`, `11L` — 제곱/선형항의 long 연산.
- 최종 **부호 있는 64-bit 산술 오른쪽 시프트 16비트**.

따라서 정확한 기본 경로 계산식:

```text
t = signed64(signed32(x * 3129871) XOR signed64(z * 116129781) XOR y)
renderSeed = signed64(t*t*42317861 + t*11) >> 16
```

이 기본 구현의 입력은 좌표이며 **월드 생성 시드나 월드 객체를 받지 않는다**. 단, 원본 `eog$a`가 실제로는 소유 블록의 가상 메서드로 위임하기 때문에, 연구 대상 17 블록의 **구체 서브클래스가 기본 시드를 상속하는지를 전부 클래스별 검증한 상태는 아니다.** 모드/리소스팩에 의한 재정의도 미포함이다. 그래서 아래 예상표는 전부 **default `eog` seed 가정**을 표시한다.

## 3. 원본 기본 RNG와 가중치 모델 선택을 연결

`bgr.class`의 `a():bgr`는 최초 생성 시드 `evf.a():J`를 통하여 `a(J)`를 호출한다. **`a(J)`는 `new eur(seed)`를 사용**한다. 그런데 청크 및 파괴 오버레이에서는 선택 직전 `bgr.b(positionSeed)`로 재설정하므로 `evf`의 임시 생성 시드는 해당 모델 선택의 첫 무작위 index에 영향을 주지 않는다.

`eur.class`의 `b(J)V`(41바이트) / `c(I)I`(52바이트)에서 확인한 상수는 `25214903917L`, `11L`, `2^48-1`이다. `euf.class`의 `a(I)I`(64바이트)에서 **bound가 2의 제곱인 경우**의 분기를 소스로 확인했다. R013의 본 표본 4개 배열은 모두 4개 슬롯 × weight1(총 가중치 4)이라 다음 **첫 번째 bounded random**을 쓴다.

```text
mask = (1L << 48) - 1
rngState0 = (renderSeed XOR 25214903917) AND mask
rngState1 = (rngState0 * 25214903917 + 11) AND mask
next31bits = rngState1 >>> 17
chosenIndex = (4 * next31bits) >> 31    # 0, 1, 2, or 3
```

- 위 식은 Java overflow/shift 규칙을 적용한 **소스 계산**이다. 처음 하나의 `cbn` 선택에서 쓰는 난수 소비만 포함하며, 추가 모델 선택/다른 renderer 또는 다중 `multipart`의 RNG 사용 순서를 일반화하지 않는다.
- 31개의 source slot 중 목록 4그룹은 `stone` 1그룹과 `deepslate axis=x/y/z` 3그룹. 동일한 기본 renderSeed와 동일한 첫 `nextInt(4)` 호출이라면 **선택 slot 번호가 4그룹에서 동일**할 수 있으나 모델의 ID·회전/UV는 다를 수 있다.
- `deepslate axis=x`는 R013에서 4 slot 중 짝수 0/2가 normal, 홀수 1/3이 mirrored로 **구조 중복**이라 실질 구조 선택 확률 2/4씩이다. 본 계산은 확률과 관측 빈도를 구분한다.

## 4. 재현표: Y=64 가상 7×7 좌표 49곳의 첫 모델 선택

`x,z=-3,-2,-1,0,1,2,3`, `y=64`에 대해 **기본 렌더 시드 49개·`eur` 첫 48비트 내부상태와 31비트 난수·0~3 선택 슬롯**을 계산해 `DEFAULT_POSITION_SEED_GRID_49.csv`에 저장. 각 좌표를 `stone`, `deepslate axis=x/y/z` 선택지 4그룹에 연결한 **196개의 실제 소스 모델 ID/회전/UVLock 대응 결과**를 `FIRST_WEIGHTED_MODEL_CHOICE_196.csv`에 저장.

| 가상 좌표 (x,y,z) | 원본 기본 위치 해시 렌더시드 | 첫 선택 슬롯 |
|---|---:|---:|
| (0,64,0) | 2644866 | 3 |
| (1,64,0) | 133335324866887 | 3 |
| (0,64,1) | -30368174053401 | 3 |
| (-1,64,0) | 133335324865837 | 2 |
| (0,0,0) | 0 | 2 (추가 독립 checkpoint) |

- 49개 좌표의 첫 슬롯 분포는 **0=6, 1=12, 2=19, 3=12**. 특정 작은 가상 좌표 격자의 결과일 뿐 일반 확률·독립성·인게임 경험적 분포가 아님.
- **49좌표 중 서로 다른 기본 renderSeed 39개**. `POSITION_HASH_COLLISIONS_10.csv`에 **좌표가 다르지만 동일 시드인 정확히 10쌍**을 열거했다. 예: `(-3,64,-3)`와 `(3,64,3)`는 동일 기본 시드 `-47851527403462`, 첫 선택 슬롯 1. 가까운 위치가 반드시 다른 무늬를 갖는 것은 아님.
- 원본을 읽고 계산한 것이며 실제 월드의 모든 블록/시드 재정의 여부를 확인하거나 스크린샷에서 이 일치성을 측정한 것이 아니다.

## 5. 월드 밖 단일 블록 렌더 방식은 다르다

`hpw.class`의 `a(Leoh;Lfzm;Lhon;II)V` (107바이트)는 위치 인자를 받지 않고 `hpy`의 단일 블록 렌더 모델 함수로 이어진다. `hpy.class`의 `a(Lfzm$a;Lfzp;Lhqh;FFFII)V` (123바이트)에는 **`ldc2_w #362 = 42L` → `bgr.a(42L)` → `hqh.a(bgr)`**가 직접 있다.

따라서 **해당 함수에 4개 weighted `hqh` 모델이 주어졌다고 가정하면** 고정 시드 42의 첫 선택 slot은 **2**다. `NON_WORLD_FIXED_SEED42_MODELS_4.csv`는 위 4개의 hypothetical model group에서 slot2의 소스 모델+회전을 기록했다. **이것이 deepslate 아이템을 실제로 axis=x/y/z 각 모델로 렌더한다는 뜻은 아니다.** 실제 게임 인벤토리의 기본 블록상태 경로는 별도 검증이 필요하다. 핵심은 **월드 배치 블록과 미리보기 단일 블록 renderer가 동일한 위치 난수를 쓰지 않는다**는 코드상 차이다.

## 6. 독립 검증, 범위 및 다음 단계

- 원본 관련 클래스 **10개를 새롭게 직접 조사**했으며, 사용/재사용 원본 소스 SHA 원장 16행, 경로 근거 24행을 생성. 새 픽셀/PNG/게임 내 측정 없음.
- 계산은 연결된 GitHub 원본 바이너리의 CP constant/bytecode 및 기존 R013 CSV를 직접 읽고 **JavaScript BigInt**로 수행했다. 별도 Python 계산으로 `(0,64,0)`, `(1,64,0)`, `(0,64,1)`, `(-1,64,0)`, `(0,0,0)`, `(10,64,20)` 체크포인트와 49좌표 분포, **39개 고유 시드/10쌍 중복**을 독립 계산하여 일치시켰다.
- `VERIFY_R015_POSITION_SEED.py`를 오프라인 표준 Python 재현기로 작성하고 **15개 원본 클래스 Git SHA·원본 바이트코드 조각·R013 CSV SHA·49/196/10/4 표를 로컬 재생성할 수 있게** 구성했다. 사용자 저장소의 원본 `1.21.11/` 전체가 현재 Python 로컬에 장착되어 있지 않아 **이 코드의 실제 종단 간 실행은 수행하지 않음**. 수학 원형은 별도 Python으로 직접 테스트함.

**미해결:** 연구 대상 17개 모든 블록에 대한 실제 서브클래스 `getSeed` 재정의 점검; 모드팩/다른 모델 경로의 RNG 소비; 실제 월드 seed/위치별 렌더 결과 빈도; 실제 atlas 허용 및 GPU 이미지/조명/텍스처 이음새. 이처럼 완료 조건은 계속 **F 인게임 정적 검증 0/17, A–G 완전 완료 0/17**이다.

다음 `TEX02-R016` 후보: **17개 표본이 실제 사용한 블록 하위 클래스별 `getSeed` override 여부와 원본 리소스팩 model atlas 등록을 확인**하고, 기본 시드 조건부에서 벗어날 수 있는 예외를 제거 또는 명시한다. 더 이상 독립적인 소스 연구가 없고 실제 게임 캡처가 필요한 순간에는 새 리비전만 생성하지 말고 사용자에게 요청한다. 전역 `v38`과 다른 단계 및 불변 R001–R014 파일은 수정하지 않았다.
