# TEX05-R002 — 유리 6종 원본 PNG 경계·알파 반복 독립 검증 및 공식 JAR 준비 감사

> 2026-11-13 · Minecraft Java 1.21.11 · 1-1-05 **유리 6개만** · 이전 `TEX05-R001` 보존 · 공식 전역 `v38` 불변. **게임 렌더/공식 JAR 검증을 완료했다는 주장이 아니다.**

## 이번 신규 작업 요약

1. 이미 R001에서 읽은 **동일 6개의 추출 PNG 파일**을 별도의 Python/Pillow 계산으로 다시 열어 6×256=**1,536개 RGBA를 재검산**했다. 이 6개를 신규 원본 파일 6개로 다시 세지 않는다.
2. PNG별 좌측 열 x=0과 우측 열 x=15를 y=0..15에서 16쌍 비교, 최상단 y=0과 최하단 y=15를 x=0..15에서 16쌍 비교. 각 비교에서 **전체 RGBA 동등**, **알파만 동등**, **RGB 3채널 절댓값 차이 평균**을 따로 계산했다. x/y 인접 화소 알파 변화 횟수(각 방향 240쌍)도 계산했다.
3. 제3자 보관소 `PrismLauncher/meta-upstream`의 Minecraft 1.21.11 버전 매니페스트와 버전 JSON을 직접 읽고, 파일 내용의 SHA-1을 계산했다. 이 값이 매니페스트가 기록한 버전 JSON SHA-1과 **일치하지 않는다는 검증 실패를 새로 확인**했다. 이는 공식 저장소 직접 인증이 아닌 **미러 출처 문제**다.
4. 향후 사용자가 적법하게 설치한 `client.jar`가 있을 때 로컬에서 Mojang 공식 HTTPS 매니페스트/버전 JSON을 직접 조회하고 SHA-1/크기 및 6 PNG 내부 SHA-256을 비교하는 **검증 스크립트**를 준비했다. 공식 JAR 원본 바이너리를 저장소에 올리지 않는다.
5. 1-1-05의 D3/F(공식 인게임 정적 render layer/정렬, 공식 client.jar)는 모두 **pending**이다. 애니메이션 연구 보류.

## A — R001 실측과 기존 v4 수치 교차 대조

- R001 `SOURCE_LEDGER.csv`의 6개 SHA-256은 이번 `REPRODUCE_EDGE_AUDIT.py`로 재해시한 6개 PNG와 같았다. 원본 출처는 기존 `1.21.11/` 추출 미러이며 공식 JAR은 아니다.
- v4 표본 원장의 `glass` 좌우 경계 RGB 평균 차이 `40.9583`, 상하 `38.4583`이 이번 독립 수치 `40.9583333333` / `38.4583333333`와 소수 넷째 자리까지 일치한다.
- 착색 5종의 같은 두 값은 모두 `0.0`. 단일 RGB이면서 공통 알파 마스크를 가진다는 기존 주장을 경계 검사로 추가 검증했다.
- v4 측정, R001 및 R002 재검산은 **같은 6개 텍스처**를 다루므로 모집단은 계속 6개다.

## B/C/D1/D2 — 원본 RGBA 정량 재확인 및 새 경계 검사

| PNG | 좌우 RGBA 동일 /16 | 상하 RGBA 동일 /16 | 좌우 알파 동일 /16 | 상하 알파 동일 /16 | 좌우 RGB MAE | 상하 RGB MAE | 가로/세로 알파 전환 /240 |
|---|---:|---:|---:|---:|---:|---:|---|
| `glass` | 2 | 1 | 16 | 16 | 40.958333 | 38.458333 | 38 / 38 |
| `red_stained_glass` | 16 | 16 | 16 | 16 | 0 | 0 | 38 / 38 |
| `black_stained_glass` | 16 | 16 | 16 | 16 | 0 | 0 | 38 / 38 |
| `blue_stained_glass` | 16 | 16 | 16 | 16 | 0 | 0 | 38 / 38 |
| `green_stained_glass` | 16 | 16 | 16 | 16 | 0 | 0 | 38 / 38 |
| `white_stained_glass` | 16 | 16 | 16 | 16 | 0 | 0 | 38 / 38 |

- `glass`(무색): 사방 가장자리 알파=255와 좌우·상하 맞은편 알파가 모두 일치하지만, 맞은편 **RGB까지 같은 쌍은 가로 2/16·세로 1/16**. RGB 3채널 평균 절댓값 차이는 좌우 약 40.9583, 상하 약 38.4583.
- 착색 `red/black/blue/green/white_stained_glass` 5종: 각 파일의 모든 경계 픽셀은 색이 한 가지이고 alpha=163이므로 맞은편 경계의 **전체 RGBA가 16/16 일치**. 알파(102·155·163)의 내부 구조는 5종 모두 같고 가로·세로 인접 전환 각 **38회/240쌍**.
- 6종 모두 알파 가로·세로 인접 전환이 38회이다. 무색에서는 alpha0→255, 착색에서는 102→155 또는 163인 변화로 **같은 전환 횟수라도 같은 광학 효과를 뜻하지 않는다**.
- RGBA 경계 비교는 **같은 PNG 스프라이트의 반복 배열 수치**다. 인접 블록 경계의 실제 렌더링·면 컬링·게임 조명·아틀라스 UV 샘플링을 관찰한 결과가 아니다.
- 픽셀별 좌표·원래 65개의 윤곽/강조 위치는 불변 R001 `ALPHA_MASKS.md`, `PIXEL_RGBA.csv`에서 확인 가능하다.

## E — 정적 모델·UV 관련성

- R001에서 검증한 6개 leaf 블록모델 → `cube_all → cube`, 36개 상속 면의 기본 `[0,0,16,16]` UV 구조와 모순되지 않는다. 이번 새 경계 분석은 **PNG 각 면 전체를 반복 적용할 경우**의 2D 가장자리 데이터이며 원본 정적 면 UV 36개를 추가 완성량으로 다시 세지 않는다.
- 실제 게임 인접 유리의 면 컬링, 텍스처 경계 표시 여부, 정렬, render layer·유리 색·조명은 아직 인게임 관찰 없음.

## F/D3 — 제3자 메타데이터에서 확인한 정보와 공식 인증 경계

**PrismLauncher GitHub의 제3자 보관본**을 기준으로 파악한 1.21.11 출시 메타데이터:
- 1.21.11 `releaseTime`: `2025-12-09T12:23:30+00:00`.
- 매니페스트에 수록된 공식 버전 JSON 링크는 `https://piston-meta.mojang.com/v1/packages/812ee7fdfdf648bb872f7a1dca33718de4e786b4/1.21.11.json`, 기대되는 버전 JSON SHA-1은 `812ee7fdfdf648bb872f7a1dca33718de4e786b4`.
- 그러나 실제 받은 PrismLauncher 미러 `mojang/versions/1.21.11.json` 71,914 bytes의 원시 SHA-1은 `eecf92276648e276e0b108a1f14fff2316ae805c`로 **불일치**. SHA-1 계산 구현은 `abc` 알려진 테스트값과 해당 파일 Git blob SHA-1 재구성으로 교차 검증했다. **사본을 공식 버전 JSON의 바이트 동일 파일로 볼 수 없음.**
- 미러 버전 JSON이 적어둔 클라이언트 JAR: SHA-1 `ba2df812c2d12e0219c489c4cd9a5e1f0760f5bd`, 크기 `31,152,600 bytes`, 링크 `https://piston-data.mojang.com/v1/objects/ba2df812c2d12e0219c489c4cd9a5e1f0760f5bd/client.jar`. 이 값은 **인증된 실제 로컬 JAR 검증값이 아닌, 미러에 기록된 후보 지문**이다.
- 이번 환경에서는 Mojang 공식 메타데이터/클라이언트 바이너리를 직접 취득하지 못했다. `official_client_jar_authenticated = 0/6`, `ingame_static_verified = 0/6`. **F/D3 보류**.
- `VERIFY_OFFICIAL_CLIENT.py`: 로컬 JAR을 인수로 받을 때만 공식 HTTPS 매니페스트 → 실제 버전 JSON SHA-1 → `downloads.client`의 SHA-1·크기 → JAR ZIP CRC → JAR 내부 이 단계 6 PNG의 SHA-256을 순차 검사한다. 공식 API를 실제 이용하고 검증하기 전까지 성공이라고 쓰지 않는다. 기본 무인수 실행은 `pending`이다.

## G — 신규 증거 파일 및 인수인계

- `REPORT.md`: 본 A–G 분리 보고서.
- `SOURCE_LEDGER.csv`, `EDGE_RGBA_AUDIT.csv`: 6종 SHA 재검증·경계 쌍 일치·RGB MAE·알파 전환.
- `SUMMARY.json`: 신규 계산 결과와 여전히 미검증인 범위.
- `METADATA_PROVENANCE.json`: 제3자 버전 매니페스트 및 1.21.11 JSON 원본 지문, SHA 불일치, 클라이언트 다운로드 지문과 공식 검증 상태 구분.
- `REPRODUCE_EDGE_AUDIT.py`: 로컬 미러 PNG의 SHA/RGBA 경계 정량을 재현하는 Pillow 스크립트. 이 실행 환경에서 실제 6 PNG를 이용해 실행 통과.
- `VERIFY_OFFICIAL_CLIENT.py`: 사용자 제공 **적법한 로컬 client.jar**의 공식 사이트 검증을 위한 별도 준비 도구. 이번 환경에서는 인게임·공식 JAR 검사를 실행하지 못함.

**단계 경계:** R001 불변, R002 신규 결과 폴더만 생성, 단계 전용 STATE/HANDOFF 외 수정 금지. 다른 단계, 루트 HANDOFF/PROGRESS, 공식 전체 `v38` 변경 금지. 차기 실제 신규 증거가 확인되면 STATE를 재확인한 뒤 `TEX05-R003` 사용. 애니메이션 연구 전면 보류.
