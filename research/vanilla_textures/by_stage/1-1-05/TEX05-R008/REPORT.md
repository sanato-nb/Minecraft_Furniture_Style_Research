# TEX05-R008 — 유리 6종 텍스처 애니메이션 연구 (보류 해제)

> 2026-11-13 · Minecraft Java 1.21.11 · 1-1-05 전용 · 인게임·Mojang 전체 JAR 인증 제외 유지 · 이전 R001–R007 불변

## 1. 사용자 변경 지시와 증거 기준
사용자가 '보류한 애니메이션을 하자'고 명시하여 이 유리 단계의 애니메이션 소스 연구를 재개했다. 고정 대상은 `glass`, `red_stained_glass`, `black_stained_glass`, `blue_stained_glass`, `green_stained_glass`, `white_stained_glass` 6종이다. 다른 독립 재질 단계는 수정하지 않는다.

## 2. 실제 유리 PNG 6종 재검사
사용자가 제공한 `1.21.11/assets/minecraft/textures/block/`의 여섯 원본 PNG를 base64 바이너리로 직접 취득하고 IHDR과 PNG 청크 체인을 전수 파싱했다. 6종 모두 16×16×8bit이며 세로 16×16 프레임 슬롯은 각각 **1개**. 각 PNG의 청크는 **IHDR, IDAT, IEND**뿐이고 APNG 전용 `acTL`, `fcTL`, `fdAT` 청크는 **6/6 없음**. 기존 R005와 같은 원본 Git blob SHA를 확인했고 새로운 PNG로 재계수하지 않았다.

실제 `glass.png.mcmeta`는 `{"texture":{"mipmap_strategy":"mean"}}` 설정이며 **animation 키가 없음**. 착색 유리 5종의 대응 `*.png.mcmeta` 각각은 GitHub 원본 경로에서 404로 부재를 재확인했다. 즉 **고정 6종 모두 저작된 프레임 애니메이션 메타데이터 없음**.

## 3. 양성 대조 — 원본에서 애니메이션이 있을 때의 형태
비교군으로 동일한 사용자 추출 저장소에서 `water_still`, `lava_still`, `fire_0` 세 PNG 및 각 `*.png.mcmeta`를 직접 조사했다. 이들은 **유리 고정 6종에 포함되지 않는다**.

- 물: PNG **16×512** → 16×16 프레임 슬롯 **32개**. mcmeta `animation.frametime=2`; 별도 `frames` 배열은 미기재.
- 용암: PNG **16×320** → 슬롯 **20개**. `animation.frametime=2`; 명시된 `frames` 시퀀스 **38항목(0부터 19까지 갔다가 1로 복귀)**, 고유 인덱스 20개. 38항목을 실제 PNG 프레임 수로 오해하지 않는다.
- 불: PNG **16×512** → 슬롯 **32개**. `animation.frames` **32항목(16–31 다음 0–15)**. `frametime` 속성 미선언이므로 구체적인 기본 tick 길이를 소스만으로 확정하지 않는다.
- 양성 대조 3개도 APNG 청크는 없었다. 따라서 APNG 부재만으로 판단하지 않고 **시트 프레임과 mcmeta animation 유무를 함께 확인해야 한다**는 대조 근거가 있다.

## 4. 판정 및 한계
**유리 6/6종의 텍스처 스프라이트 애니메이션 저작 여부 조사 완료; 애니메이션 정의 0/6.** 기본 자료에 2프레임 이상의 유리 스프라이트 시트나 동작 시퀀스가 없어, 이 대상의 기본 텍스처는 프레임 애니메이션이 없는 정적 텍스처로 분류한다.

이 결론은 **게임 코드의 시간에 따른 효과·블록 상태 전환·리소스팩 교체·셰이더 변형·GPU 화면 출력이 전혀 없다**는 주장이 아니다. 이들은 별도로 검증하지 않았고 인게임 검증은 사용자 지시로 제외됐다. 기존 소스 분석에서 확보한 1,536개 원본 픽셀, 36면 UV, 유리 관련 누적 **37개 정적 경로**는 계승한다. 대조군의 PNG+mcmeta **6경로는 유리 37개에 가산하지 않는다.**
