# TEX11-R011 — 목재 문 7종의 전체 모델 면 실제 RGBA/UV 원본 분석

**2026-11-13 · 단계 1-1-11 · 이전 TEX11-R010 · 다음 번호 TEX11-R012(새로운 근거가 생길 때만)**

## 출처와 새 작업
- 사용자가 Minecraft Java 1.21.11 설치본 JAR에서 추출해 제공한 GitHub `1.21.11/`를 주 원본으로 사용했다. **문 PNG 14개(7목재×위/아래)를 다시 직접 디코딩**, 모든 PNG chunk CRC, indexed RGB palette/tRNS, zlib DEFLATE, scanline filter, 실제 RGBA 16×16 텍셀을 검사했다. **14/14 CRC·디코딩 통과, 원본 3,584 RGBA 텍셀, PNG 바이너리 합계 3,162바이트**. 이 14개는 기존 연구 범위의 파일로, 새 PNG 추가 수 0.
- **실제 leaf model JSON 56개, 공유 문 template JSON 8개, 실제 blockstate JSON 7개(224 상태 variants)**를 직접 조회/검증했다. 리프는 `textures.top`과 `textures.bottom`가 해당 재질 `<wood>_door_top/bottom`을 참조하는지 확인했고 템플릿 `elements[0]`의 공간 범위 `[0,0,0]→[3,16,16]`도 검증.
- **280개 전체 모델·면의 UV 좌표를 각 PNG 실제 픽셀에 연결해 새롭게 전체 영역 RGBA 샘플링**. 56모델×5면, 각 모델은 16×16 넓은 면(west/east) 2개, 3×16 좁은 면(north/south) 2개, 16×3 가장자리 면(up 또는 down) 1개로 총 656참조. **280 면 패치 / 36,736 UV source-texel 참조 사용**. 참조 중복 허용이며 고유 물리 텍셀 수가 아님.
- **R008과의 중복 구분:** R008은 넓은 west/east UV 방향과 윗/아랫면 경계 1행을 비교했지 **넓은 면 전체 16×16을 실제 RGBA로 채워 측정한 것은 아님**. 이번 R011에서 넓은 면 **112패치/28,672 전체 텍셀 샘플**을 수행했고, 이전에 면별 실샘플이 없던 **좁은 면 168패치/8,064 참조**를 새로 채웠다. R007의 PNG 경계 112쌍과 R008의 상태-면 224건을 독립 신규 원본 픽셀 수에 중복 산입하지 않는다.

## 모든 문 정적 상태별 UV·컬링 메타데이터
- 원본 blockstate 7목재×32 = **224개 정적 상태**, 각 state 5면을 원본 y회전과 결합해 **1,120개의 상태·면 투영 원장 / 146,944 UV 텍셀 반복 참조 사용**을 작성. 회전 면 normal/cullface, 실제 source UV, source PNG·leaf·template Git blob SHA와 `UV_rotation` 90/270 정보를 보존. 수학적 법선 투영 오류 0건.
- 원본 템플릿에서 **56개 모델의 east 면에는 `cullface` 키가 없고 다른 4면은 키가 있음**. 이는 소스의 cullface *지정 여부*이며 Minecraft 실제 엔진에서 face가 보이거나 정상/오류라고 판정한 결과가 아니다.
- 완전 투명(alpha 0) 픽셀이 있는 전체 모델 UV 패치는 **48/280**개. 전부 큰 **west/east** 면이며, **north/south/up/down의 168 좁은 면에 알파 0이 나타나는 패치는 없음**. 또한 **모든 280패치에서 부분 알파(1..254) 픽셀 0건**. 이것은 source texture 값이지 runtime alpha test/필터 처리 결과가 아니다.
