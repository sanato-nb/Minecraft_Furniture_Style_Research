# TEX11-R007 — 실제 사용자 PNG 픽셀 이음새 및 정적 UV 텍셀 재현

**날짜:** 2026-11-13 · **단계:** 1-1-11 · **고정 원본:** 31 PNG · **이전:** TEX11-R006 · **다음:** TEX11-R008

## 직접 수행하고 확인한 원본 검증

- **주 원본:** 사용자가 Minecraft Java 1.21.11 JAR에서 추출해 제공한 GitHub `1.21.11/`. 고정 PNG **31개 모두 직접 불러와** chunk CRC, DEFLATE/zlib, PNG 스캔라인 필터와 인덱스 팔레트/투명도 디코딩. 파일 SHA-256을 독립 재계산해 기존 v4 기록과 **31/31 일치**. 합계 **8080 바이트, 11776 RGBA 텍셀**. 이전 R003과 동일 대상 재검사이며 신규 텍스처 31개 추가로 중복 계산하지 않음.
- **원본 JSON:** 실파일 `models/block/` 템플릿 **12개**와 선택된 리프 **24개**를 직접 조회해 texture 슬롯/parent/face UV를 읽었다. R004의 127 leaf와 114 face, R006의 544상태·4,320면은 이전 수치 그대로 계승(새로 완료한 전체 원장이라 주장하지 않음).
- **신규 실측:** 문 위·아래 **112 경계 텍셀 쌍**, 다락문 36 + 선반 35 = **71 UV 면 패치 / 13936 참조 텍셀**, 17개의 정적 방향성·대칭 후보 비교.

## D1 — 문 위아래 실제 RGBA 경계

- 정상적으로 놓였을 때 *상단 파일* `<wood>_door_top.png`의 **마지막 행(y=15)**과 *하단 파일* `<wood>_door_bottom.png`의 **첫 행(y=0)**이 공간상 인접하므로, 해당 **16열의 실제 RGBA 픽셀**을 비교했다. 상단 경계 x좌표를 15−x로 뒤집은 후보와 직접(x=x) 후보를 함께 측정했다.
- 색상 지표는 둘 다 불투명한 열에서 RGB 채널 절댓값 차 합의 평균이다. 완전히 같은 RGB여야 접합된다는 전제는 없으며, **알파 경계 및 시각적 무늬는 게임 실측을 거쳐야 확정**된다.

| 목재 | 직접 alpha 불일치 /16 | 동일 RGBA /16 | 직접 RGB L1 평균 | x반전 alpha 불일치 /16 | 반전 RGB L1 평균 |
|---|---:|---:|---:|---:|---:|
| oak | 0 | 10 | 33.9375 | 0 | 97.9375 |
| acacia | 0 | 2 | 121.6875 | 0 | 126.5625 |
| spruce | 0 | 2 | 82.875 | 0 | 99.625 |
| birch | 0 | 10 | 27.625 | 0 | 82.375 |
| cherry | 4 | 7 | 23.5 | 4 | 55.3 |
| bamboo | 0 | 3 | 114 | 0 | 137.875 |
| mangrove | 0 | 9 | 34.375 | 0 | 60 |

- **R006의 112 문 쌍**은 기하 정렬이고, **R007의 112개**는 픽셀 열 대조이다. 수가 같더라도 다른 검증 단위이며 중복 합산 불가.
- [문 7쌍 원본 top+bottom 정적 이미지](DOOR_SOURCE_SEAM_PREVIEW.svg)는 단순 2D 조립 증거이다. 인게임 렌더가 아니다. `DOOR_SEAM_PIXEL_DETAIL.csv`의 112행에 실제 RGB·alpha 좌표 보존.

## D2/D3/E — 템플릿 실 UV 기반 정적 16/32px 샘플링

- JSON `elements[].faces[].uv`를 원본 PNG 가로/세로 해상도 /16으로 환산하고, 감소하는 U/V도 역순 nearest-neighbor 텍셀로 직접 샘플링. 이 결과는 소스 UV 평면 추출이며 게임 GPU·카메라 측면 표시가 아니다.
- **다락문 12종:** 실제 리프의 `parent`를 따라 `template_trapdoor_*` 또는 `template_orientable_trapdoor_*`로 나눠 닫힌 아래 `up`, 닫힌 위 `down`, 열린 정적 `north` 면 총 **36 UV 패치**를 실화소로 추출. 각 PNG의 좌우/상하 alpha/RGBA 대칭성도 독립 측정.
- **선반 5종:** 32×32 atlas의 body `south`/`up` 및 front `center/left/right/unconnected/unpowered` = **35 패치**. 참나무는 고정 PNG 내 이번 실화소 조사에 포함되지만 **전역 v38 참나무 선반의 이전 32 정적 상태**를 R006의 544 상태에 합치지 않는다.
- **방향 후보:** 각 목재 선반의 *서로 다른 원본* left/right 전면 영역을 direct와 오른쪽 X반전 두 방식으로 수치 비교. 단, **left/right가 서로 다른 디자인 영역**이므로 유사도가 더 높은 방향을 게임에서 올바른 방향이라고 확정할 수 없다.

| 선반 | 직접 동일 RGBA | 반전 동일 RGBA | 직접 RGB L1 | 반전 RGB L1 | RGB 수치상 후보 |
|---|---:|---:|---:|---:|---|
| oak_shelf | 80/128 | 75/128 | 2927 | 1269 | flip |
| spruce_shelf | 83/128 | 83/128 | 1321 | 675 | flip |
| birch_shelf | 80/128 | 77/128 | 2577 | 1121 | flip |
| cherry_shelf | 81/128 | 77/128 | 2645 | 1409 | flip |

- `UV_FACE_PIXEL_SAMPLES.csv`는 71개 패치의 Git blob SHA, 템플릿·face·UV 좌표·실샘플 크기/alpha/반전 여부를 기록. `UV_ORIENTATION_CANDIDATES.csv`에는 선반 5개 정량 대안과 다락문 12개 RGBA/alpha 대칭성 기록.
- [원본 선반 아틀라스+샘플링한 7 UV 패치, 5종](SHELF_FACE_UV_RASTER.svg) SVG는 텍셀 단위 색상 비교용이며 인게임 렌더링 결과가 아니다.

## 연구 범위·보류 원칙

- **기존 근거 계승만:** 31 PNG, 127 leaf, 블록상태 원본 512규칙, 544 정적 상태/672 모델 인스턴스/4,320면, 문 상·하 기하 정렬112. 참나무 선반 v38 별도.
- **이번 신규:** 112개 경계 픽셀 대조, 71개 face UV 패치(+ 13936 참조 텍셀), 17개 방향 후보. **인게임 정적 시각 자료 0/31, 검증 0/31**.
- 실제 Minecraft 화면에서 facing/half/hinge가 지정된 상태, 표면 좌우 반전·컬링·alpha test·GPU 필터·조명은 미검증. RGB 경계 불일치만으로 렌더 오류 확정 금지.
