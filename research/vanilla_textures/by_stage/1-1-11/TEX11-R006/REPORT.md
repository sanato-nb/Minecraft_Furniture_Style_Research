# TEX11-R006 — 사용자 제공 Minecraft 정적 모델 상태별 회전·투영 재현

**연구일:** 2026-11-13 · **단계:** 1-1-11 목재·구조부품 · **고정 PNG:** 31 · **이전:** TEX11-R005 · **다음:** TEX11-R007

## 연구 범위 및 검증 층

- **주 원본:** 사용자가 Minecraft Java Edition 1.21.11 설치본 `client.jar`에서 직접 압축 해제했다고 밝힌 `1.21.11/assets/minecraft/` 폴더.
- R003 사용자 원본 PNG 31개 SHA/CRC, R004 사용자 원본 JSON 리프 127개 직접 파싱, blockstate 23개 512 source rule, 템플릿 21개 114 UV face 및 25 element의 **실제 소스 검증 원장**을 입력으로 사용한다.
- **R006 신규 연구:** 과거에 개별 source 정의로만 점검했던 블록상태·리프·템플릿의 관계를 조합해 **각 정적 상태에서의 회전 후 공간 좌표·면 방향·UV 픽셀 범위·모델 개수**를 새로 계산하였다. 이는 앞 회차 512 source rule의 동일 재검사를 신규라고 부풀리지 않는 독립적 파생 검사이다.
- **공식 Mojang 원본 JAR SHA-1 인증은 R005에서 사용자 요청으로 필수 연구에서 제외**했다. 이 회차에서 원본 JAR 바이너리나 메타데이터 인증을 요구·시도하지 않았으며, **실제 인게임 렌더 검증은 별개로 미완료**.

## A. 연구 스코프 / 중복 방지

| 구분 | 세부 내용 |
|---|---|
| 독립 단계 blockstate | 문 7, 다락문 12, 비참나무 선반 4 = **23 파일** |
| 독립 정적 상태 | 문 224 + 다락문 192 + 비참나무 선반 128 = **544 상태** |
| 정적 모델 인스턴스 | 문 224 + 다락문 192 + 선반 256 = **672 인스턴스** |
| 인스턴스에 연결된 면 | 문 1,120 + 다락문 1,152 + 선반 2,048 = **4,320 면** |
| 참나무 선반 예외 | 참나무 선반 7개 leaf와 과거 v38의 32개 정적 조합은 역사적 자료로 계속 **별도 참고**, 위 544 상태에 합산하지 않음 |
| 고정 대상 PNG | **31개**(문 상·하 14, 다락문 12, 선반 5). R004에서 31 PNG 모두 leaf 재질 슬롯에 연결됨 |

정적 상태 544는 R004의 **정의 규칙 512개**와 단위가 다르다. 선반 24개 multipart 규칙마다 하나의 최종 상태가 아닌, 4 방향×2 전원×4 연결 상태로 **32개의 조합/재질**을 평가하여 본체+조건부 전면 패널 **2개 모델을 동시에 적용**했다. 선반은 비참나무 4재질만 이번 신규 상태 조합에 포함한다.

## B. 실제 조합 및 정적 좌표 변환

1. R004 `STATIC_STATE_MODEL_LINKS.csv` 원장을 기반으로 7문×32, 12다락문×16 상태명을 직접 각각 분리하고, 선반 4종은 `when.AND` 규칙을 각 `facing/powered/side_chain` 조합에 적용하여 **모델 참조 2개가 정확히 선택되었는지 검사**했다.
2. 선택 모델의 `LEAF_MODEL_DIRECT_AUDIT.csv` 기록에서 사용자 추출본의 `parent`·`textures` 슬롯을 해석하고, `MODEL_ELEMENT_GEOMETRY.csv`의 템플릿 원래 `from/to` (각 0..16)을 조합했다.
3. **검사 전용 회전 규약:** 각 요소의 꼭짓점 좌표를 블록 중심 **(8,8,8)** 기준으로 옮겨, 각 JSON blockstate에 명시된 **X 다음 Y 회전**을 오른손 좌표계 기준 90° 배수로 적용한 뒤 되돌렸다. 이는 소스 공간에서의 수학적 일관성을 확인하기 위한 규약으로, **Minecraft 엔진 구현과 실제 화면까지 동일함을 증명한 것은 아니다**.
4. 각 면의 정적 방향 법선/지정된 `cullface`를 똑같이 회전하여 표준 N/E/S/W/up/down 방향에 매핑한다. `TEMPLATE_UV_FACE_VALIDATION.csv`의 UV는 `uv × texture_size / 16`으로 픽셀 좌표로 환산한다(문/다락문 16px, 선반 32px). 개별 면의 `face_rotation` 값은 따로 보존한다. 이 회차는 **GPU 샘플러·UV 보간·픽셀 색상까지 rasterize하지 않는다**.
5. 정적 투영으로 나온 **544 상태 / 672 모델 배치 / 4,320 face 인스턴스**를 독립 CSV에 저장. 검사에서 모델 좌표가 블록 [0,16] 범위를 벗어난 경우 **0**, 유효한 텍스처 슬롯 해결 실패 **0**, UV가 대상 PNG 범위를 벗어난 경우 **0**, 회전 법선·cullface 방향 미해결 **0**, 누락된 부모 모델 또는 소스 증거 **0**, 선반 모델 2개 조건 실패 **0**.

## C/D. 문 위·아래 모델 접합의 신규 공간 검증

- 7개 문 재질 × facing 4 × hinge 2 × open(정적) 2 = **112개** 동일 문의 아래/위 상태 조합을 생성.
- 각 조합에서 아래 모델의 XYZ footprint / Y 회전과 위 모델의 footprint / Y 회전이 같은지 비교하고, 아래 요소의 최상단 Y=16과 위 요소의 최하단 Y=0이 **서로 인접한 블록 경계에서 접촉 가능한지** 비교.
- **112/112개에서 XZ 점유 범위·회전·상/하 위치가 일치**했다. 이 검사는 **기하학적 정렬만** 다루며, 원본 PNG의 픽셀이 경계에서 같은 색으로 이어지는지 또는 transparent alpha가 실제로 끊기지 않는지 확인한 결과가 아니다.
- 결과 `DOOR_HALF_ALIGNMENT.csv`의 조합별 좌표/회전/판정을 근거로 남김.

## E. 파생 결과 파일

- `STATIC_STATE_COVERAGE.csv`: **544 상태**, 상태 속성, 정적 모델 수, 배치 면 수와 누락 여부
- `ROTATED_MODEL_INSTANCES.csv`: **672 모델 인스턴스**, 원본 leaf·템플릿·회전·세계좌표 경계와 유효성
- `ORIENTED_FACE_PROJECTION.csv`: **4,320 면**, 정적 world face normal/cullface/투영 XYZ 범위, 픽셀 UV 경계, 원본 재질 PNG, 면 고유 회전, 소스 기반 검증
- `DOOR_HALF_ALIGNMENT.csv`: **112 문 상·하 조합**, 동일 방향·히지/열림 상태에서 footprint·회전·상하 접촉 확인
- `INGAME_STATIC_TEST_MATRIX.csv`: **31 PNG**별 실제 게임에서 확인해야 할 정적 테스트 상태, 필수 시각 체크, 증거 확보 여부
- `SUMMARY.json`: 수치 및 검증 한계. 이번 보고서와 별도로 전 회차 R001~R005는 불변.

## F. 실제 게임 검증 — 아직 0/31

- **인게임 렌더 검증은 미완료 0/31**. 모델과 UV가 원본 파일을 기준으로 회전 후 블록 범위 안에 남는다고 해도, 실제 엔진의 렌더링, 조명, UV 보간·텍스처 필터링·alpha test·컬링·문양의 눈에 보이는 접합 결과를 증명하는 것은 아니다.
- `INGAME_STATIC_TEST_MATRIX.csv`는 문 14개 PNG, 다락문 12개 PNG, 선반 5개 PNG의 **전 항목을 상태 `in_game_verified=false`**로 보존한다. 실제 게임에서 해당 구조물을 여러 방향/상태로 배치한 화면과 설정 근거가 확보될 때 해당 항목만 갱신해야 한다.
- **oak_shelf 주의:** 고정 31 PNG 중 참나무 선반은 기존 v38의 leaf/32상태 증거로 참조했다. 이번 R006 신규 544 상태·4,320 면에는 참나무 선반 상태가 포함되지 않는다. 그러나 31개 PNG별 시각 검수 목록에는 **참나무 선반을 포함**한다.

## G. 완료 기준과 다음 작업

- **소스 기반 정적 분석:** R003~R006의 31 PNG 참조, 127 leaf, 512 상태 규칙, 114 template UV face, 544 실제 상태 조합, 4,320 정적 면까지 일관성 분석.
- **다음 TEX11-R007:** (a) 실파일 텍스처 샘플링/정적 이미지 재현을 통해 상·하 PNG의 눈에 보이는 접합, 다락문 프레임/선반 front-panel UV 역전 후보를 찾아 기록; (b) 실제 게임 스크린샷 등이 확보되면 31 PNG 테스트 매트릭스 중 증거 있는 항목만 인게임 검증. 실제 게임을 실행하지 않으면 해당 인증을 완료 처리하지 않음.
- 공식 원본 JAR 인증은 **다음 단계나 완료 분모에 넣지 않음**. 애니메이션·좀보이드 변환·실제 가구 모델링 제외. 역사적 R001~R005 및 전역 v38 변경 금지.

**해석상 주의:** R006은 3D 변환 결과를 CSV에 기록한 **소스 기반 정적 투영 연구**이며, 실행 가능한 마인크래프트 게임 엔진 렌더러·가구 3D 모델·인게임 스크린샷 결과가 아니다.
