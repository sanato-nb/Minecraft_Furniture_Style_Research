# TEX01-R006 — 고정 목재 18 PNG의 D4 방향 변환 비교 및 oak_log_top 로컬 UV 180° 전 화소 검사

2026-11-13 · 단계 **1-1-01** 전용 · 사용자 제공 `1.21.11/` 원본 PNG/JSON 기반. TEX01-R001–R005는 읽기 전용 계승. 전체 v38 및 다른 단계 변경 없음.

## A/B/C · 신규 실험을 위한 원본 대조, 과거 측정과 구별

- 사용자 GitHub `1.21.11/assets/minecraft/textures/block/` 원본 **18 PNG**를 바이트로 해독해 SHA256을 단계 STATE 및 R004 기록과 **18/18 일치** 확인. PNG 서명, **총 72개 청크 CRC32**, RGBA 디코딩/16×16/알파 255도 18/18 통과.
- 원본 **4,608 RGBA(18×256)**는 R001의 기존 고유 픽셀을 재사용한 것. 새로운 소스 PNG나 새로운 고유 픽셀은 **0**. R004의 132면/792 RGB 앵커 조회, R005의 19,584 거리 기반 비교 및 72면 법선 투영 역시 **신규 실적으로 재가산하지 않음**.
- R005의 이웃 픽셀 간격 d=2·4·8 통계와 달리, 이번에는 **정적 이미지 전체의 방향 변환 민감도**를 새로 검사한다.

## D2 · 18 이미지 × 7개 비자명 D4 변환 = 126개 새 비교

각 16×16 소스 RGB를 기준으로 `rot90`, `rot180`, `rot270` (반시계), `flip_lr`, `flip_tb`, `transpose`, `anti_transpose`의 **7개** 변환을 실행했다. 항등 변환은 제외했다. 각 원본-변환 이미지의 **256개 동일 좌표**를 비교하여 한 채널이라도 RGB가 다르면 변경 픽셀로 표시하고, RGB 각 채널 절댓값 차이의 평균(MAE)을 계산했다.

- 새 정적 비교 **126개** = 18 PNG × 7변환. 픽셀 좌표쌍 비교 **32,256회** = 126×256 (원본 4,608 고유 픽셀 좌표를 여러 번 참조한 것).
- 18 PNG 모두 180° 회전 이미지가 원본과 **완전히 같지는 않음**. 변경 픽셀 수 범위 **100–256 /256**.
- 기존 R004에서 RGB 색상 클래스 공간 배치가 완전 동일했던 9개 판자(`oak`, `spruce`, `birch`, `dark_oak`, `cherry`, `jungle`, `pale_oak`, `crimson`, `warped`)는 이번 180° 변경 좌표 수도 **모두 220/256**으로 동일. 이는 개별 PNG의 RGB값이 같다는 뜻이 아니다.
- R004의 근접 변형인 `mangrove_planks`는 **216**, `acacia_planks`는 **222**픽셀 변경. `bamboo_planks`는 **246**, `bamboo_mosaic`는 **256/256** 변경.
- `oak_log`와 `spruce_log`는 180° 변화 **각 206/256**으로 대응. RGB 변경 강도(MAE)는 각각 **26.3229**, **11.7604**로 다르다.
- 모든 PNG·모든 변환의 픽셀 변경 수와 RGB MAE, 소스 SHA256은 `PNG_D4_ORIENTATION_18.csv`에 보존.

**제한:** 이 7개 변환은 **소스 PNG의 가상 이미지 비교 실험**이다. 18종에 해당 변환들이 모두 게임 블록상태에서 실행된다고 주장하지 않는다. R002의 가상 인접 회전 이음새 72조건이나 R005의 거리기반 RGB 비교와도 분모가 다르다.

## D3/E · oak_log_top 단면의 실제 소스 UV 180° 관련 새 전 화소 근거

원본 `cube_column_horizontal.json`의 **로컬 up 면만** `rotation:180`; `oak_log_horizontal.json`이 해당 `#end` 슬롯에 `oak_log_top`을 지정하며 blockstate `axis=x/z`가 수평 모델을 사용한다. R005 72면 표에서 고정 18 PNG 범위에 해당하는 180° 로컬 UV **2면**이 바로 이 단면에 연결된다.

이를 정적 **소스 텍셀 인덱스 순열** `(u,v) → (15−u,15−v)`로 모델링해 원본 256 RGB 좌표와 전수 대조했다.

- `oak_log_top`: **100/256 좌표의 RGB가 다름**, 동일 **156/256**. 180° 변화의 MAE는 **5.0182 RGB 코드값**.
- 기존 R004의 6점 앵커 위치에서 실제 차이가 나는 좌표는 중심 `(7,7)`, `(8,8)` **2/6개**이고 네 모서리는 같음. 이번 검사는 단면 전체 256개 좌표로 확대해 중앙과 외곽의 비대칭을 수치화한 것. 이전 R004 RGB 6점을 새 6개 원본으로 **중복 가산하지 않음**.
- 단면의 정확한 16행×16열 변경 위치 256bit 마스크는 `OAK_LOG_TOP_ROT180_MASK.json`에 저장. 행 우선, 첫 비트 `(0,0)`, 1이면 원본·180°변환 RGB 불일치.
- 3개 연관 JSON(`cube_column_horizontal`, `oak_log_horizontal`, `oak_log` blockstate)을 GitHub에서 직접 다시 읽어 blob SHA와 상속/UV 슬롯을 대조. **이미 R001/R005에 포함된 정적 JSON 파일이므로 신규 고유 JSON 0개**.

**엔진 판정 경계:** 180° 소스 텍셀 변환 결과는 **로컬 UV의 수학적 이미지 투영**이며 게임 엔진의 최종 월드 UV, 텍셀 샘플링 필터, 광원, 컬링과 구분한다. 이번 연구에서 실제 인게임 정적 렌더를 관찰한 수는 여전히 **0/18**이다.
