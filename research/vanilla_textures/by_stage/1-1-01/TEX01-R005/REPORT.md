# TEX01-R005 · 목재 18 PNG 다중 거리 결 분석 및 원목 3축 모델 면 방향 투영

2026-11-13 · 단계 **1-1-01** 전용 · 이전 R001–R004 불변 · 전역 v38 및 타 단계 변경 없음.

## 연구 출처와 중복 배제

사용자 제공 Minecraft Java 1.21.11 JAR 추출 폴더 `1.21.11/assets/minecraft/`를 1차 소스로 사용하였다. GitHub의 **18 원본 PNG 바이너리**를 직접 Base64 해독해 SHA-256을 이전 STATE/R004와 **18/18 일치**시켰고 PNG 시그니처·청크 CRC(총 **72청크**)와 16×16 RGB 디코딩을 다시 확인했다. 이 과정에서 재사용한 **4,608개 원본 픽셀**을 신규 고유 픽셀 4,608개로 이중 가산하지 않는다. R001의 기존 4,608 RGBA/18 PNG와 R004 132개 로컬 모델면·792 RGB 참조는 **기존 실적 계승**이다.

**18개 정적 JSON을 직접 재조회**(4 원목 blockstate, 8 리프 모델, cube/cube_all/cube_column/cube_column_horizontal 네 템플릿, bamboo_mosaic blockstate/리프). Git blob SHA와 원본 경로는 `SOURCE_JSON_AUDIT.csv`에 기록했다. 원본 18개는 기존 R001의 **43개 JSON에 속하는 재검사**이므로 새로운 고유 JSON 추가 개수는 **0**이다.

## 신규 PNG 정량 검사 — 2·4·8 텍셀 거리

각 원본 `I[y,x,c]`(16×16×RGB)에 대해, d=2/4/8, `H_d = mean(|I[y,x,c]-I[y,x+d,c]|)` (`x+d<16`), `V_d = mean(|I[y,x,c]-I[y+d,x,c]|)` (`y+d<16`)로 구했다. 각각 RGB 세 채널 절대 차이의 평균, 경계 래핑 없음. 한 파일당 d=2는 448쌍, d=4는 384쌍, d=8은 256쌍; 총 **18×1,088 = 19,584 RGB 픽셀쌍 비교**. H/V 평균 108개 및 V/H 비 54개를 `PNG_SPATIAL_LAG_METRICS.csv`에 저장. 이들은 **파생 측정/비교 횟수**이고 신규 고유 PNG/픽셀 수가 아니다.

- **판자 12종**: d=2의 V/H는 **2.2076–3.1053(12/12가 1 초과)**. 그러나 d=4는 **0.7522–0.9331(12/12가 1 미만)**. 1픽셀 거리의 결 방향 특성을 모든 주파수/거리로 일반화하는 것은 오류.
- d=8 판자는 11/12가 V/H <1. 예외 `bamboo_planks`는 **1.0363**.
- `oak_log`: d=2 **0.6922**, d=4 **1.2075**로 부호 반전. `stripped_oak_log`: d=2/4/8 각각 **0.6964/0.6017/0.5012**로 세로 방향 변화가 지속적으로 작음.
- `birch_log`는 **1.4693/1.1287/0.7634**, `bamboo_mosaic`는 **0.9919/0.9614/1.0200**(d=2/4/8).

이 값은 소스 RGB 코드 값이며, 인게임 광원/필터링/최종 월드 텍스처 방향은 측정하지 않았다. R002의 **가상 90° 회전 타일 이음새 72조건**과도 다른 새 실험이다.

## 신규 JSON 모델-로컬 → 월드 면 법선 투영

원본 `cube_column`은 `cube`의 0..16 요소/6면을 상속하고 `#end`(로컬 down/up)와 `#side`(로컬 4옆면)를 지정한다. 수평 모델 `cube_column_horizontal`은 6면을 직접 선언하며 **로컬 up 면에만 UV `rotation:180`**을 갖는다. 이는 R002에서 전체 이미지/가상 인접 타일을 180° 회전한 것과 다르다.

`oak_log`, `spruce_log`, `birch_log`, `stripped_oak_log`의 실제 blockstate `axis=y`에는 모델 회전값이 없고, `axis=z`는 `x:90`, `axis=x`는 `x:90, y:90`을 선언한다. **원본 JSON 자체에 `uvlock` 필드는 없음**(엔진 기본 처리 확인을 뜻하지 않음).

방향 벡터의 정수 90° 회전을 **Rx 후 Ry**로 적용한 *수학적 소스 투영*은 원목 끝단 `#end`의 월드 법선을 다음처럼 대응한다.

| 축 상태 | 원목 단면이 대응하는 월드 면 | 월드 up/down 질감 | 180° 로컬 up이 대응하는 면 |
|---|---|---|---|
| `axis=y` | `down / up` | `#end` | 없음 |
| `axis=z` | `north / south` | `#side` | `south` |
| `axis=x` | `west / east` | `#side` | `east` |

**4원목 × 3상태 × 6로컬면 = 72행**의 행별 `source_blockstate`, 원본 blob SHA, parent, 로컬 face, 계산된 월드 face, 슬롯, 범위 내 여부, UV rotation 0/180을 `MODEL_AXIS_WORLD_FACE_MAP.csv`에 저장. 이 중 고정 18 PNG에 연결된 54면, 범위 밖 3종 단면 PNG로 연결된 18면(직접 RGB 미측정). 원본 로컬 up UV 180°는 총 8면(고정 PNG 연결은 oak_log_top 2면).

`bamboo_mosaic` 블록은 `cube_all` 상속과 단일 기본 blockstate가 확인되며, 원본 파일의 해당 기본 상태에는 모델 회전값이 없다. 판자 12종·mosaic의 기존 78면 정적 참조는 R001/R004 계승; 이번 72 원목 월드 투영에 **재가산하지 않았다**.

**중요:** 계산된 월드 face는 JSON 회전값에 적용한 **법선 수학투영**이다. 실제 Minecraft 베이크 로직의 face UV 기준축, 최종 texel 샘플링, uvlock 적용, 컬링, 광원 및 **인게임 정적 화면 검증은 실시하지 않았다.** 이전 R004 132면 RGB 앵커는 세계 텍스처 렌더값이 아닌 소스 로컬 UV 샘플로 그대로 유지한다.
