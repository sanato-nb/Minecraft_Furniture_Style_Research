# TEX01-R004 — 목재 판자 팔레트 구조 정밀 비교 + 정적 모델 면별 원본 RGB/UV 6점 연결

2026-11-13 · 단계 1-1-01 · 대상 18 PNG · 이전 R001/R002/R003 보고서·CSV·커밋 불변 · 통합 v38 유지.

## A/B/C — 새 색상 공간 배치 비교

사용자가 직접 JAR을 압축 해제해 GitHub에 올린 1.21.11/assets/minecraft/textures/block/ 원본 18 PNG를 현재 로컬 이미지로 다시 읽고 SHA256을 R001의 독립 검증 기록과 18/18 대조하였다. 기존 RGBA 4,608개 실측을 새 실적으로 다시 세지 않는다.

각 RGB 픽셀은 원본 이미지 위에서 (x=0→15, y=0→15) 순서로 스캔해 최초 등장한 색마다 0,1,2...의 **정규화된 색상 클래스 번호**를 매겼다. RGB 색값 자체를 비교하지 않고 이 256개 클래스 번호의 동일 좌표 배치를 비교했다. source SOURCE_LEDGER.csv는 클래스 수와 전체 256-bit mismatch mask를 담는다. mask는 row-major 256bit, 왼쪽 첫 비트가 (0,0), 세 번째 바이트부터 다음 행으로 연속한다. 1은 표준 대비 클래스 불일치, 0은 일치.

- oak_planks와 **256/256 완전히 같은 7색 배치**: oak, spruce, birch, dark_oak, cherry, jungle, pale_oak, crimson, warped의 9 판자 PNG. **이 9종은 각기 다른 RGB 팔레트를 가진 별도 PNG 파일**이며 바이너리 중복이 아니다. 이를 9×7=63 RGB 항목으로 CANONICAL_PLANK_RGB_LUT.csv에 새로 추출했다.
- mangrove_planks: 동일 클래스 배치 **254/256**, 불일치 **(12,14),(13,14)** 2픽셀.
- acacia_planks: 동일 클래스 배치 **252/256**, 불일치 **(9,8),(1,12),(11,12),(11,13)** 4픽셀.
- bamboo_planks: 동일 클래스 배치 **20/256**, 불일치 236픽셀. 소스 색상 종류 10개로, 공통 7색 판자 구조에 속하지 않는다. 236곳의 전체 위치는 SOURCE_LEDGER.csv 비트마스크로 보존.
- oak_log/spruce_log: 서로 6색 배치 클래스를 256/256 동일한 좌표에 갖는다. **색값 자체는 다름**.

이번 신규 결과는 기존 R001의 '9종 동일' 관찰을 9×7 정확 RGB 팔레트 대응표, 맹그로브·아카시아의 차이 좌표, 대나무의 전체 비트 마스크로 확장했다. 팔레트 인덱스 번호는 PNG 내부 PLTE 엔트리 인덱스가 아니라 **RGB 최초 등장 기준의 분석상 클래스**이다.

## D3/E — R001 모델면 150개와 PNG 원본 6좌표 RGB의 정적 연결

R001 MODEL_UV_FACE_MAP.csv의 150개 실제 정적 모델-로컬 면 참조를 그대로 재사용하면서 이번에는 각 면에서 참조하는 **원본 PNG의 실제 RGB hex 값 6개**를 직접 연결했다. R001 CSV SHA: 3aef76586c418b8fa54a22a7ce9526c195a40827. 기존 면 참조를 새 모델면 150개로 중복 합산하지 않는다.

샘플 위치는 PNG 원본의 TL=(0,0), TR=(15,0), BL=(0,15), BR=(15,15), C77=(7,7), C88=(8,8). 각 PNG의 직접 추출 RGB 6점은 ANCHOR_SOURCE_RGB.json에 출처 SHA와 함께 저장했다. 총 18×6=**108 고유 PNG 좌표 조회**를 132개의 범위 내 모델 로컬면에 정적 결합하여 132×6=**792개 면별 RGB 조회 결과**를 생성했다. **792는 고유 픽셀 개수가 아니라 참조 면에 재사용된 값의 수**다.

- 고정 범위 18 PNG에 연결되는 로컬면 **132/150**: 각 면의 해상 텍스처 SHA, 블록상태 축, 로컬 UV 회전, 6점 원본 RGB 값 생성 완료.
- 고정 범위 밖 원목 단면인 spruce_log_top, birch_log_top, stripped_oak_log_top에 연결되는 **18/150**: 참조 경로와 원본 모델 sha만 기록하고 **RGB 샘플 빈칸**으로 유지; 외부 PNG를 신규 측정하지 않음.
- JSON 모델의 명시적 로컬 면 UV rotation=180은 **8면**, 이 가운데 고정 대상인 oak_log_top 2면만 RGB 샘플을 실제 180도 좌표변환해 기록. 180도 변환 좌표 (u,v)→(15−u,15−v): 네 모서리 TL↔BR, TR↔BL, 중심 C77↔C88. 나머지 6면은 외부 원목 단면이라 RGB 없음.
- blockstate x/y 회전은 CSV에 **원본값 그대로 별도 보존**. 월드 공간에서 합성된 최종 표면 UV, 컬링, 광원 결과를 추론하거나 실제 게임 렌더라고 주장하지 않는다.

기존 cube/cube_all/cube_column의 UV는 16×16 **암시적 좌표**로, 이 6점 샘플링은 소스 모델-로컬 UV상의 색상 데이터 대응 관계일 뿐 게임 엔진이 픽셀을 똑같이 채택했다는 증거는 아니다.
