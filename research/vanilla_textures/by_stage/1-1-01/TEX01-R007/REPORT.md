# TEX01-R007 — D1 확대: 원목 4종의 옆면·단면 원본 PNG 직접 대조

2026-11-13 · 사용자 명시 지시 **「확장해서해줘」**에 따라 1-1-01 D1의 종별 원목 단면 증거를 확장함. 원래 대상 **18종은 그대로**, 별도 **보조 PNG 3종**을 추가. 이전 TEX01-R001~R006의 기록은 불변. 인게임, 애니메이션, 공식 JAR SHA 인증은 사용자 요청에 따라 연구 범위 밖.

## A/B — 직접 확인한 신규 원본과 보존할 기존 표본

- 1차 출처: 사용자 제공 Minecraft Java 1.21.11 추출 원본 저장소의 `1.21.11/assets/minecraft/textures/block/`. 직접 GitHub에서 해당 파일 Base64 바이너리를 취득한 뒤 해독. 보조 새 원본 **`spruce_log_top.png`, `birch_log_top.png`, `stripped_oak_log_top.png` 3개**에 대해 SHA256, PNG 4청크 CRC32 각각 검증. 16×16 팔레트 PNG로 RGBA 디코드 및 **알파 255/255**. 이번에 새로 읽은 고유 원본 텍셀은 **3×256=768개**.
- 비교 대조를 위해 기존 18개 중 **5개**(`oak_log_top`, `oak_log`, `spruce_log`, `birch_log`, `stripped_oak_log`)도 원본 바이트 SHA256/CRC 확인하고 디코드. 총 **8파일·32 CRC 청크·2,048 화소 좌표**를 다루지만 고유 *추가* PNG는 3개, 신규 고유 소스 픽셀은 768개뿐. 기존 고유 18 PNG/4,608 원본 픽셀은 중복 누적하지 않는다.
- 8파일 해시 및 PNG Git blob SHA를 `D1_SOURCE_PNG_LEDGER.csv`에 증거로 남김. 기존 18 PNG와 별개 보조 3개로 표시; 원래 고정 표본이 자동으로 21개로 교체된 것은 아님.

## C/D1 — 실제 원본 텍셀 기반 4쌍 전수 비교

원본 RGBA의 RGB 코드값으로 계산. `Y = 0.2126R+0.7152G+0.0722B` (0~255, 감마 보정 전 sRGB 코드값 가중합; 물리적 선형 휘도 아님). `S=(max(R,G,B)-min(R,G,B))/max(R,G,B)` (검정이면 0). 모든 16×16 픽셀 평균. `Y_std`는 모집단 표준편차. 인접 1픽셀 H/V 대비는 RGB 3채널 절대차 평균, 경계 래핑 없이 각 방향 240쌍. 같은 좌표 옆면/단면 RGB MAE는 픽셀마다 3채널 비교한 단순 숫자 비교이며 모델의 인접 텍스처 접합/물리적 연속성을 뜻하지 않는다.

| 수종 | 옆면 평균 Y | 단면 평균 Y | 단면−옆면 Y | 옆면 평균 S | 단면 평균 S | 옆면 V/H(d=1) | 단면 V/H(d=1) |
|---|---:|---:|---:|---:|---:|---:|---:|
| 참나무 oak | 87.7344 | 124.4695 | +36.7351 | .535160 | .521085 | .2899 | 1.0003 |
| 가문비나무 spruce | 40.6659 | 84.0007 | +43.3348 | .720418 | .570380 | .3008 | 1.0226 |
| 자작나무 birch | 214.9974 | 179.1680 | −35.8294 | .042661 | .300232 | 2.0303 | 1.0068 |
| 껍질 벗긴 참나무 stripped_oak | 147.0017 | 132.3572 | −14.6445 | .516473 | .520725 | .4908 | 1.0692 |

**새로 확인한 특징:** 단면이 항상 더 밝다는 일반화는 반례 2종(자작나무·껍질 벗긴 참나무) 때문에 틀림. 자작나무의 옆면은 특히 낮은 평균 채도(.042661)로, 단면(.300232)과 다른 색상 분포. 참나무·가문비나무·껍질 벗긴 참나무 옆면의 d1 V/H는 1 미만(세로 차이 평균이 가로보다 작음); 자작나무 옆면만 2.0303으로 반대. 4개 단면의 d1 V/H는 1.0003~1.0692 범위. 이는 **이번 16×16 원본의 방향 통계**이지 엔진에 배치된 최종 UV/광원 비교가 아니다.

전수 원본 RGB의 같은 좌표 일치 수는 참나무 13/256, 가문비나무 1/256, 자작나무 4/256, 껍질 벗긴 참나무 0/256. 각 수종의 단면 180° 가상 변환 시 RGB 불일치 좌표 수는 차례로 **100, 98, 108, 92 /256**. R006의 참나무 단면 100은 **기존 기록 교차 검증**이므로 추가 고유 실적이 아님. 4쌍의 256×3 = **3,072 옆면/단면 RGB 채널 절대차 비교**와 해당 평균을 이번 직접 검사에서 기록. 비교 수량은 새로운 고유 PNG/텍셀 개수와 구별.

행별 세부 수치(명암 표준편차, RGB 고유색 개수, 수평·수직 채널차, 채도차 및 UV 회전 민감도)는 `D1_SIDES_ENDS_4PAIRS.csv`에 보존.

## E — 모델 상속·끝면 슬롯의 원본 JSON 근거

직접 다시 읽은 사용자 출처의 **4개 `blockstates/*_log.json`**, **4개 세로 `models/block/*_log.json`**, **4개 수평 `models/block/*_log_horizontal.json`**. 세로 모델의 `parent: minecraft:block/cube_column`, 수평 모델의 `parent: minecraft:block/cube_column_horizontal`, 양쪽 `#end=*_log_top`, `#side=*_log` 연결을 4수종 모두 검증. 템플릿 `cube_column`과 `cube_column_horizontal` 두 파일도 직접 검증. 소스 경로와 Git blob SHA는 `D1_MODEL_END_SIDE_LINKS.csv`에 보존. 이들은 기존 R001/R005의 정적 모델 연구와 겹치므로 **새 고유 JSON 발견 수를 증가시키지 않음**.

4개 원목 blockstates는 `axis=y` 세로 모델, `axis=z` 수평 모델 x90, `axis=x` 수평 모델 x90·y90 지정. `cube_column_horizontal`의 로컬 `up` 모델면 UV `rotation:180`; 따라서 원래 18개 밖에 있던 **새 단면 3종도** 이 소스 연결에 속한다. 180° RGB 변경 좌표(각 98/108/92)는 소스 이미지 순열을 직접 적용한 실측이며, **최종 월드 UV 베이크 수치를 인증하지 않는다.**

## 판정 및 경계

**D1은 원래 표본에서 실제 옆면이 지정된 원목 4종의 단면 증거를 보조 PNG 3개로 채워 이제 4/4쌍 분석 완료**. 이는 마인크래프트의 *모든* 목재 종·모든 블록을 조사했다는 뜻이 아니며, 기존 판자 12종 각각에 대응하는 임의 원목을 새로 추가한 연구도 아님. 기존 D2/D3 및 18 PNG A/B/C/E 측정은 보존한다.

**인게임 정적 검증과 Mojang 공식 JAR 인증은 완료 조건에서 제외**, 게임/광원/렌더 확인 주장 금지. 전역 v38, 타 단계 및 R001~R006 불변; 애니메이션, PZ 변환, 실제 가구 모델 제작 제외. 추가 실질 D1 공백이 없으면 사용자가 '계속해줘'라고 해도 반복 재측정을 하지 않고 완료/중단을 안내한다.
