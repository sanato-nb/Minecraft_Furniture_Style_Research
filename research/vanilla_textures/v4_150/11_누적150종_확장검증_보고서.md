## 3. 이번 신규 50종에서 직접 확인한 사실

### 3.1 16×16이 절대적인 유일 해상도는 아님

- 누적 150개 가운데 **145종은 16×16**, **5종은 32×32**로 디코딩되었음.
- 32×32의 5종은 `oak_shelf`, `spruce_shelf`, `birch_shelf`, `cherry_shelf`, `bamboo_shelf`.
- 각 32×32 텍스처는 **픽셀 수가 4배**이지만, 단순히 더 세밀한 가구 모델이라는 의미는 아님. 모델 JSON에서 UV 영역을 나눠 사용하는 **텍스처 아틀라스 형태**임.
- `oak_shelf.json`은 `template_shelf_body` 부모 모델을 지정함. 해당 템플릿을 실제 열어보니 `shelf_body`, `shelf_bottom`, `shelf_top`의 **직육면체 3개**를 정의하고 같은 PNG의 여러 UV 부분을 사용하는 구조였음.

### 3.2 투명 픽셀은 구멍·틀을 표현하는 방법 중 하나

- 신규 50종 가운데 **17종**이 알파값 0인 픽셀을 보유했고, **1~254의 중간 알파를 쓰는 신규 PNG는 0종**이었음.
- `acacia_door_bottom`/`acacia_door_top`: 투명 픽셀 **28.125%**씩.
- `oak_trapdoor`: 투명 픽셀 **14.0625%**.
- `anvil_top`: 투명 픽셀 **37.5%**.
- 단, 이는 스프라이트 픽셀 데이터 관찰일 뿐 **게임 렌더 계층(Cutout, Translucent)을 검증했다는 의미가 아님**.

### 3.3 같은 목재 계열도 구조물 종류에 따라 밝기·색상 구조가 달라짐

- `oak_planks`의 평균 밝기(기존 실측)와 `oak_trapdoor`(이번 새 실측)를 비교하면, **다락문이 약 31.95 낮음**. 다락문에 틀과 구멍을 표현했기 때문이라고 해석할 수 있으나 밝기 차이만으로 원인 확정 불가.
- `birch_planks` 대비 `birch_trapdoor`는 약 **19.34 높음**.
- 같은 목재라고 텍스처를 단순히 색상 교체만 해서 재사용한다는 일반화는 위험. 표면의 용도(평면 판자·문틀·창살 등)를 별도로 기록할 것.

### 3.4 텍스처 키 두 개가 동일한 PNG 바이트를 가질 수 있음

- `jukebox_side`와 `note_block`은 실제로 **SHA-256 값이 같음** (`ce5e56da299713779c49b55fcdb705fbdc1381d4f449615b932877ba13c9fabb`).
- 따라서 **150개는 텍스처 경로 수**이지 픽셀 내용이 모두 서로 다른 150종이라는 뜻은 아님. 이번 150종에서 서로 동일한 바이트를 갖는 쌍은 이 사례 1쌍을 발견함.
- 같은 텍스처라도 게임에서 쓰이는 블록의 역할이 동일하다고 볼 수 없음.

### 3.5 목재 부품 무늬 상관 분석은 형태 동일성을 의미하지 않음

- 신규 문·다락문·선반을 종류별로 비교한 **125쌍**에 대해 공통 가시 픽셀의 밝기 피어슨 상관계수와 알파 마스크 Jaccard(IoU)를 계산함.
- `oak_shelf` ↔ `birch_shelf`는 밝기 상관계수 약 **0.919**로 높음(알파 마스크 IoU 1.0). 동일 아틀라스 구조/무늬 유사도를 시사.
- `oak_door_top` ↔ `acacia_door_top`의 밝기 상관계수는 약 **0.629**로, 색상만 바꿔 동일 패턴이라고 보기 어려움.
- 상관계수는 픽셀 통계이며 실제 가구 모델의 부품 좌표나 UV가 일치하는지 알려주지 않음.

## 4. 모델 JSON 연결 — 02 작업 이전의 제한된 예비 확인

실제 미러의 모델 JSON을 소수 확인해 이번 텍스처가 3D 표면에 어떻게 적용되는지 연결했다. **02 바닐라 3D 모델 구조 분석 자체를 시작하거나 완료한 것으로 산정하지 않음**.

| 텍스처 사용 예 | 부모/템플릿 | 직접 읽은 근거 |
|---|---|---|
| 참나무 선반 (`oak_shelf`) | `template_shelf_body` | 3개 요소, 같은 32×32 텍스처의 UV 영역별 할당 |
| 참나무 다락문 (`oak_trapdoor`) | `template_trapdoor_bottom` | 요소 `(0,0,0) → (16,3,16)`, 면별 다른 UV 범위 |
| 참나무 문 (`oak_door_bottom` + `oak_door_top`) | `door_bottom_left` | 요소 `(0,0,0) → (3,16,16)`, 상하 텍스처 지정 |
| 통 (`barrel_top` / `barrel_side` / `barrel_bottom`) | `cube_bottom_top` | 상·옆·아래 텍스처 분리 지정 |

원본 모델 파일을 결과물에 복사하지 않았고, 위 표에는 구조의 파생 요약만 기록했다.

## 5. 측정 근거와 한계

- SHA-256과 `Pillow`로 검사한 신규 대상은 **비공식 GitHub 추출 미러 PNG 50개**임.
- 이전 100개의 기존 측정 기록은 v3 ZIP에서 계승하고, 현재 첨부된 100종 CSV와 **완전히 동일한 바이트**임을 재검사했음. 이번 턴에서 이전 100종 PNG 원본을 독립 수집하거나 직접 다시 검사하지는 않았음.
- 생산사 공식 `client.jar`를 다운로드/대조하지 못했으며, 게임 실행 화면의 렌더링·생물군계 색·광원·투명 효과를 관찰한 것도 아님.
- 원본 3D 오브젝트의 정체, 실제 크기, 충돌 판정은 텍스처 PNG만으로 검증할 수 없음.
- 32×32 아틀라스의 값은 한 가구면의 32×32 픽셀 표현이라는 뜻이 아니므로, 텍스처 이미지 크기와 UV 좌표를 함께 해석해야 함.
- 원본 텍스처와 모델 JSON의 재배포 권리를 확인하지 않았으므로, 공개/전달 ZIP에는 게임 파일 자체를 넣지 않음.

4. 이후 02 세부 작업에서 블록모델/부모 템플릿/UV/상태별 회전·방향을 본격적으로 분석.
