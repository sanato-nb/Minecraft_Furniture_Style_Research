# v14 — Handcrafted 16개 생성형 모델의 텍스처 바인딩 근거 연결 검사

- 연구일: **2026-11-12 (KST)**
- 범위: 1단계 세부 **04 가구 모드 텍스처·UV**의 근거 연결 감사. 03 모드 3D 구조 자료를 참조
- 고정 원본: `terrarium-earth/Handcrafted` `1.21.x` / `8d21d1665916850c3fa3bdaf1370c50ec2ca7035`
- **이번에 직접 실행한 신규 분석:** v12에 이미 실측되어 기록된 16개 생성형 모델의 텍스처 슬롯 JSON을 파싱하고 v13 실제 픽셀 분석 PNG 목록 및 Git SHA·해상도 기록과 **교차 결합**, 해당 원형 부모가 v13 UV 분석 7개에 포함되는지 대조.
- **이번에 직접 읽지 못한 자료:** 원본 제작자 저장소의 새 JSON/PNG 바이트. GitHub 커넥터에서 외부 원본 저장소를 가져올 수 없어 기존 GitHub 측정 레코드만 직접 파싱했다. 따라서 원본 face→PNG 실제 화소 또는 렌더를 새로 검증했다고 표시하지 않는다.

## 2. 모델별 연결 패턴

- `oak_chair_white`와 `cherry_chair_white`는 `wood` 및 `cushion` 양쪽이 v13 분석 PNG에 연결. 각각 `particle`은 `minecraft:block/...`이므로 현재 연구의 원본 Minecraft 파일 바이트 검사 범위 밖이다.
- `oak_bench_single_white` / `oak_bench_middle_white` 및 `oak_couch_single_white` / `oak_couch_middle_white`도 동일한 두 역할의 모드 PNG가 v13 표본에 연결된다.
- `oak_chair_black`의 `chair/cushion/black_cushion`은 v13 실측 목록 **밖**이다. 이것이 공식 소스에 존재하지 않는다는 뜻이 아니다.
- 테이블·책상·협탁 계열에서 `table/sheet/white_sheet` 경로는 **5회** 쓰이지만 v13 PNG 표본에 없다. 한 PNG를 직접 확인하면 여러 leaf의 증거 공백을 줄일 수 있다.
- `oak_fancy_bed_single_white_foot`는 `bench/cushion/none_cushion`, `fancy_bed/single/oak_fancy_bed`, `fancy_bed/sheets/white_sheet`의 3개 미측정 경로를 참조한다. `none_cushion`을 오타/버그라고 단정하지 않는다.
- `oak_shelf_left_1`는 모드 텍스처 5개가 전부 v13 표본 밖이라, 선반의 구체적인 화소·UV 연결 검증을 우선 보완할 수 있다.

## 3. 기존 다른 모드와의 확인 가능 범위 차이

v11 Another Furniture의 **33개 완성형 상속 모델** CSV에는 `texture_override_slots` **개수**만 저장되어 있고 슬롯별 실제 경로 JSON은 없다. 따라서 이 CSV만으로 Another Furniture 33종의 `face → texture ref → PNG` 연결을 사실처럼 채워 넣을 수 없다. 해당 모드의 **고정 커밋 원본 leaf JSON**을 확보한 뒤 계층 상속·`#texture` 순환 검출을 수행해야 한다.

v13의 UV **13 모델/571면** 수치는 픽셀 경계에 정렬되는지 확인한 **별도의 모델 단위 통계**다. 이번 v14에서 부모가 9개 leaf에 대응한다는 사실만으로 9개 leaf의 실제 픽셀 표본을 검증했다고 계산하지 않는다.
