## 범위 및 실적

고정 배정표 `D_ENTRY3_QUEUE_265.csv`의 처음 48개는 기존 `D_ENTRY3_SUBBATCH1_48_*`에 보존했다. 이번에는 **49~265행의 217개**(`bubble_column.json`~`dripstone_block.json`)를 원본 본문에서 읽고 Git blob SHA·JSON 구문을 확인했다. 원본을 16개 단위 snapshot 14개에 저장했다. 기존 48개와 중복 없이 **Entry3 265/265개**, D 누적 **373/1,168개(31.93%)**, 미조사 **795개**다. Entry4~6은 미실행이며 D 전체 종료를 선언하지 않는다.

variants 키는 원본 선언 상태로 기록했다. multipart는 원본 `when`의 AND/OR/`|`를 해석하고, 등장한 조건값의 직교 곱을 **분석용 정적 후보**로 전개했다. boolean에 한쪽만 보이면 반대값을 파생 후보에 포함했다. 조건에 나타나지 않는 게임의 등록 속성값과 실제 유효 상태 전체를 인증한 것은 아니다. 배열 `apply`는 동시 조립 대신 **대안 선택**으로 기록하고, 서로 다른 multipart 규칙의 적용 결과는 동시 부품으로 기록했다. `x`, `y`, `uvlock`, `weight`의 키 존재 여부와 원본 값을 선택 옵션마다 보존했다.

모델 401개의 경로·원본 SHA를 C 고정 범위 2,390행에 대조했다. C 직접 384개는 각 Entry의 모델·face·slot 원장에 연결했고, 나머지 17개는 범위표의 `E_EXCEPTION` 및 `1-2-E` 소관과 대조했다. face PNG 254경로는 원본 PNG SHA와 기존 C RGBA 원장의 SHA를 확인했다. 이 3,450면·1,630슬롯·254 PNG는 **기존 C 증거의 재사용**이며 D 신규 face·픽셀 측정은 0이다.

별도 재판정 스크립트가 217개 snapshot의 전문과 SHA, 상태 후보 1,560건의 조건 일치 및 옵션 3,335건의 모델·회전·명시 플래그를 다시 계산해 불일치 0을 확인했다. 401개 모델의 C 고정 범위 SHA와 E 담당 여부도 재확인했다. Entry3 전체는 앞선 48개의 독립 감사 PASS와 이번 217개 PASS 및 배정표의 1~265행을 합쳐 검사했다. 이번 217개 산출물과 재현 스크립트는 `D_ENTRY3_REMAINING_217_*`, `scripts/phase_1_2_d_entry3_remaining.py`, `scripts/phase_1_2_d_entry3_recheck.py`에 있다.
