# v35 — P1 정적 가구형 원본 검수: 종·케이크·벌통·벌집 15모델 / 71상태 / 16 PNG 전체 RGBA

> 2026-11-13 KST · v34 2,390개 블록 모델 전체 목록 중 **P1 544개 후보**에서 **15개를 이번 회차 실제 원본 JSON·관련 PNG까지 조사**했다. 사용자가 명시한 **애니메이션 분석 보류**를 계속 지켰다. [P1 544개 원본 SHA별 원장](12_p1_544_static_source_review_ledger.csv)은 v35 회차 조사 여부만 기록하며, v5–v34 과거 분석 완료 여부는 아직 전수 대조하지 않았다. **15/544는 이번 회차 소스 확인 범위이지 전체 분석 완료율이 아니다.**

## 1. 소스와 분류·수치 경계

- **사용자 저장소** `1.21.11/assets/minecraft/models/block` 실제 leaf 모델 JSON **15개**(종4·케이크7·벌통/벌집4)와 공용 부모 `orientable_with_bottom` 및 `cube` 모델 JSON **2개**를 원본 Git blob SHA 기준으로 조사. 조사한 leaf 15개는 v34 P1 544원장에 포함되어 있으며 **15/15 Git SHA 일치**를 재확인했다.
- 관련 **블록상태 JSON 4개**, 원본 `variants` **71행**(종16/케이크7/벌통24/벌집24)을 그대로 파싱. 원본 71행 전부 `uvlock` 속성 미기재 — **명시적인 false 71건이 아니다**. 회전·상태 선택은 source JSON의 고정 규칙을 읽은 결과이며 게임 런타임 입증은 아니다.
- 관련 PNG **16경로×16×16 = 원본 4,096 RGBA 픽셀** 직접 Base64→PNG inflate/필터/PLTE/`tRNS` 처리 후 해독. **불투명3,496 / 완전투명600 / 부분 알파0**. 이 16경로에는 **종의 particle 전용 `bell_bottom` PNG가 포함**되며 실제 JSON `elements[].faces`의 UV 실화소 샘플에는 포함하지 않는다.
- 이번 원본 소스 **고유 직접 선언 면 75면(종33/케이크42)**과 부모 `cube` **6원본 선언 면**을 확인. 벌통/벌집 네 leaf에서 공통 부모6면을 각각 적용하는 **24개 face×material 사용 기록**을 별도로 조사했다. 따라서 **소스 원본 face 선언 81면**(종33+케이크42+공통 cube6)과 **면별 재질 적용 99행**(종33+케이크42+벌 leaf 적용24)을 혼동하지 않는다.
- 전체 99 face×material의 원본 PNG 직사각형 조회 **10,900 texel-uses / 선택 영역의 알파255 10,900회 / 완전투명0회**. 직접 source explicit UV는 **종33면**; 케이크42면과 벌 leaf24면은 **기하·공통 cube에서 유도한 암시 UV**로 실사용 정확한 게임 엔진 좌표·winding·회전을 확인하기 전까지 `추론`으로 기록한다. 10,900회는 10,900종 고유 픽셀이나 화면 출력 픽셀을 뜻하지 않는다.

## 2. 종 — 설치용 받침 4종과 본체 렌더 범위의 분리

| 설치 상태(`attachment`) | 모델 | 원본 기하 요소 | 직접 선언 UV 면 |
|---|---|---:|---:|
| `floor` | `bell_floor` | 3 | 16 |
| `ceiling` | `bell_ceiling` | 1 | 5 |
| `single_wall` | `bell_wall` | 1 | 6 |
| `double_wall` | `bell_between_walls` | 1 | 6 |
| **서로 다른 4 원본 합계** | | **6** | **33** |

- `blockstates/bell.json`은 설치 방식4 × 방향4 = **16원본 선택 규칙**을 사용하며 source `y` 회전으로 지지대를 위치시킨다. **실제 종 본체의 완전한 3D 메시가 이 네 block model JSON에 포함되어 있다고 주장하지 않는다**. JSON은 종 지지대·결합부 구조의 데이터이고, **별도 block-entity/special renderer와 종 본체 geometry는 공식 client.jar에서 독립 검증 필요**.
- 네 JSON 모델의 33 source 명시 UV 면은 `dark_oak_planks`와 `stone` 원본 PNG를 참조했고 **총 724 texel-uses 전부 불투명**했다. `bell_bottom`은 `particle` 슬롯으로 선언되지만 모델의 33개 `faces[].texture` 슬롯에서 사용되지 않는다. 16×16 원본 `bell_bottom`의 **64불투명/192투명**은 PNG 자체 특성이지 종 지지대의 투명 UV면 수가 아니다.
- 실제 인게임 종 본체 형태·애니메이션·메시·충돌체 분석은 범위 밖 또는 미검증. [7 PNG의 전 RGBA](07_bell_cake_seven_png_rgba_full.csv) · [종33/케이크42면 UV 사각형·RGBA 실측](08_bell_cake_75_faces_png_uv_sampling.csv).

## 3. 케이크 — 7개 정적 형상의 경계가 2모델 단위씩 잘리는 단순 입체

- `blockstates/cake.json`의 `bites=0..6` **7개 source variants**는 `cake` 및 `cake_slice1..6` 각 **1요소·6면**의 독립된 원본 7 JSON 모델을 선택한다.
- 모든 케이크 모형의 소스 y=0..8 / z=1..15 / 오른쪽 경계 x=15는 동일하다. **왼쪽 경계 `from.x = 1,3,5,7,9,11,13`**으로 바뀌어 x 폭이 **14,12,10,8,6,4,2**로 줄어든다. 선택된 절단면은 `cake_inner` 텍스처를 사용한다. 동적 애니메이션 프레임을 본 것이 아니라 **서로 다른 일곱 고정 모델**을 비교한 것이다.
- 7×6 = **42 원본 선언면은 전부 UV 키 생략**. source `from/to`와 면 방향에 따른 공개 모델 규칙의 자동 UV 기하식으로 **42면의 선택 직사각형을 계산**해 실제 원본 PNG를 샘플링했다. 결과 **4,032 texel-uses 모두 불투명**. 원본 `cake_bottom`·`cake_top`은 각각 **196불투명/60투명**, `cake_side`·`cake_inner`는 각각 **112불투명/144투명**. 투명 영역은 PNG에는 존재하지만 소스 모델의 유도 UV 영역에 선택된 픽셀은 모두 불투명했다.
- 실제 게임 UV 방향·texture orientation·면 winding 및 컬링은 **미검증**, 기하식 자동 UV는 추론 단계. 케이크의 먹는 모션·상태 변화 과정을 연구한 것이 아니다.

## 4. 벌통·벌집 — 텍스처 선택만 바꾸는 4 leaf / 48 정적 상태

- `beehive_empty`, `beehive_honey`, `bee_nest_empty`, `bee_nest_honey` **4 leaf 모두 원본 `elements` 0개**, `orientable_with_bottom → cube`의 공통 **1 요소·6 원본 선언면**을 상속하고 PNG 슬롯만 달리 바인딩한다.
- `blockstates/beehive.json`와 `bee_nest.json`은 각각 **4 facing × honey_level 0..5 = 24행**, 합 **48 source variants**. 두 블록 모두 honey_level **0~4면 empty**, **5면 honey** 모델을 사용하며, 원본 방향 회전은 `y` 값으로 지정되어 있다.
- 공유 정육면체 원형의 **6면 × 4 leaf = 24 face×material 적용 기록**을 원본 PNG **9경로(2,304픽셀, 모두 불투명)**에 연결했다. 완전한 16×16 정육면체 면으로부터 **full-face UV를 추론**해 **6,144 texel-uses 모두 불투명**으로 계산했다. **새로운 독립 원본 기하 선언 24면이 아니다**.
- 전면 PNG 두 쌍을 직접 같은 픽셀 좌표별 RGBA 값으로 비교: `beehive_front` ↔ `beehive_front_honey`는 **256 중 24픽셀 다름/232 동일**; `bee_nest_front` ↔ `bee_nest_front_honey`는 **256 중 25픽셀 다름/231 동일**, 모든 대응 위치에서 alpha 값 변화 **0**. 소스 geometry가 아니라 앞면 PNG 재질만 변경되는 **정적 모델 상태의 원본 증거**다.
- [벌 PNG9의 전 RGBA](09_nine_bee_png_full_rgba.csv) · [벌 leaf 24면 상속 UV 실화소](10_four_bee_leaf_24_parent_face_texel_records.csv) · [꿀 유무 앞면 픽셀 24/25 차이](11_bee_honey_front_two_png_rgba_difference.csv).

## 5. 실제 소스 검증과 중복·진행률 기준

- v34의 파일명 기반 P1 544 후보 중 **이번 v35 회차에서 15 leaf JSON/Git SHA 직접 대조 및 관련 16PNG 읽기**. [P1 전체 544 원장](12_p1_544_static_source_review_ledger.csv)의 **529개는 이번 회차에서 확인하지 않음**이며 *과거까지 포함한 미분석 529개*로 읽어서는 안 된다. 15개 소스 SHA가 v34 P1 큐와 **15/15 일치**했고 파일명 기준 분류는 여전히 휴리스틱이다.
- 기존 v4 **선정 150종 PNG과 16경로 직접 중복 0**, [원본 v4 교차검사](13_sixteen_png_v4_150_overlap_crosscheck.csv). 이것은 과거 모든 v5–v34 PNG 조사를 확인했다는 뜻이 아니다.
- 위 PNG 중 **6파일**(`cake_top`, `cake_side`, `beehive_front`, `beehive_front_honey`, `bee_nest_front`, `bee_nest_front_honey`)은 별도 Python/Pillow의 `verify()`, 전 RGBA 분류 및 독립 SHA-256 해시로 재확인해 JSON/JS 원본 PNG 디코더의 픽셀 통계 및 front 24/25픽셀 차이와 일치. [독립 Pillow 6 PNG 검사](14_six_png_independent_pillow_sha256_rgba.csv). 나머지 10 PNG는 Pillow로 독립 검사하지 않았다.
- 이전 v34 전체 **2,390개 block model JSON / P1 544개** 모집단 자체는 변경되지 않았다. 본 단계가 요구하는 **공식 Mojang 1.21.11 client.jar 독립 획득·해시/원본 인증, 실제 인게임 정적 UV·광원·컬링·종 본체 특수 renderer 검증**은 미완료. 그러므로 최종 완료 판정 **0/5**, 전체 완료 퍼센트 **미산출**.
- 사용자 명시 지시에 따른 **애니메이션 분석 보류 계속 적용**. 종 흔들림·케이크 섭취 연출·벌 출입 동작 등 시간에 따라 달라지는 정보는 다루지 않았고 `bites/honey_level`의 정적 state 규칙과 원본 PNG만 조사했다.
- **후속:** P1 나머지 529개 중 과거 연구에서 이미 조사한 모델을 v5–v34 증거와 대조하여 **과거 조사 포함 검증 등급**을 재정립, P1 실제 가구 원형별 중복/상속을 줄여 정적 후속 검증, 공식 게임의 블록 모델 로더/종 본체 분리 렌더 경계 확인. 가구 모드 v24 기록 및 2단계 모델링 스타일 가이드 계획은 그대로 보존한다.
