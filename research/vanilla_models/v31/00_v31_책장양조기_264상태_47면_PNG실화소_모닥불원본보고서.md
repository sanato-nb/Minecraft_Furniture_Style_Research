# v31 — 끌로 조각한 책장·양조기 multipart 264상태 전수 평가 / 47원본 UV면·6PNG 실화소 / 모닥불 정적 구조

> 2026-11-13 KST · **바닐라 01/02 우선 연구** · 직전 v30. 근거는 사용자가 제공한 GitHub `1.21.11/assets/minecraft/` 원본 JSON/PNG/메타데이터. 원본 PNG/모델 JSON 자체는 연구 산출물에 복제하지 않는다. 게임 내 렌더링/공식 Mojang client.jar 검증은 **미완료**.

## 1. 끌로 조각한 책장 `chiseled_bookshelf`: 슬롯 6개를 개별 상태·장식면으로 구성

### 1-1. `multipart` 원본 52규칙, 256가지 입력 조건 조합 평가

`blockstates/chiseled_bookshelf.json`의 원본 규칙 **52개**를 개별 원본 조건 식/적용 모델/회전/`uvlock`까지 판독했다.

- **방향 4 × 슬롯 점유 비트 2^6=64 = 256개** 상태 입력을 실제 `when.AND` 조건으로 평가. 각 상태에서 **기본 `chiseled_bookshelf` 1모델 + 슬롯별 장식 모델 6개 = 7개 모델 적용**을 **256/256** 확인했다.
- 모든 상태에서 6개 슬롯 각각 정확히 **occupied 또는 empty 중 하나**가 선택됐다. 6 슬롯 중 선택 중복/누락 0. 이 결과는 **사용자가 제공한 blockstate JSON의 조건 엔진을 JS로 재현하여 평가한 계산**이지 공식 게임 런타임 검사가 아니다.
- 원본 **13개 모델 참조 경로** = 기본 1 + 슬롯별 occupied/empty 12. 조건별 모델 선택 적용은 **256×7=1,792**건(고유 원본 1,792개가 아니라 동일 원형 재사용).
- 본체 `uvlock:true`가 각 방향에 1규칙씩 **4개 원본 규칙에서 명시**되어, 256개 상태마다 적용 1회. 슬롯 장식 48규칙은 `uvlock` 키 **미기재**. 이를 명시적인 `uvlock:false`로 기록하면 안 된다.
- 슬롯 장식 모델 12개 **모두 자체 `elements` 0개**, 각 `template_chiseled_bookshelf_slot_<위치>`의 **6개 독립 템플릿**(각 1요소/1면)을 부모로 참조. occupied 또는 empty 두 leaf는 **공통 형상·UV와 서로 다른 텍스처 바인딩**만 사용한다.

### 1-2. 6칸 얇은 면의 원시 기하 및 텍스처 영역 정확 대조

- 기본 몸체 `models/block/chiseled_bookshelf.json`은 **1요소·5선언면**. 정면 빈 부분은 6개 별도 슬롯 템플릿으로 표현.
- 슬롯 템플릿 **6개×1요소×1면 = 6원본 선언면**은 모두 `from.z = to.z = 0`의 **0두께 평면**이다. 위·아래 2행(각 y 8단위), 각 행 3열(폭 6·5·5 단위)의 **전면 텍스처 면**을 구성한다. 이것은 **source JSON 좌표**이고 화면의 최종 컬링/면 방향 검증은 아니다.
- 슬롯 점유 시 `chiseled_bookshelf_occupied.png`, 비점유 시 `chiseled_bookshelf_empty.png`를 **같은 UV 직사각형**에 바인딩한다. 6칸 UV 면적은 **48+40+40+48+40+40=256 텍셀**, occupied 256회/empty 256회 모두 알파255.
- 몸체 5면에서 `chiseled_bookshelf_top` 2면×256=512, `chiseled_bookshelf_side` 3면×256=768. 기본 5면+6원본 슬롯 면 = **11고유 source face**. 두 재질 선택으로 **17개 face×material RGBA 대조행**.
- 총 source UV 실화소 **1,792 texel-uses**, **불투명 1,792/투명 0**. 이 합계는 책장 상태 256개 각각의 렌더 사용 횟수가 아니라 **기본 5면 + 슬롯 6면의 occupied/empty 양쪽 재질을 한 번씩 조사한 source face-material 표본**이다.

## 2. 양조기 `brewing_stand`: 병 3자리 개별 상태와 양면 0두께 표시판

### 2-1. `multipart` 7규칙, 8가지 입력 조건

- 원본 `blockstates/brewing_stand.json`은 **7개 규칙**: 항상 적용되는 본체 1개 + 3자리의 병 있음 `bottle0/1/2` 또는 없음 `empty0/1/2` 6규칙.
- **`has_bottle_0/1/2` 3비트 = 2^3=8개** 조합 평가, 모든 조합에서 **본체 1개 + 슬롯별 오버레이 3개 = 4개 모델 선택** 확인. **8×4=32** 조건별 모델 적용 기록, 고유 원본 32개 아님.
- 원본 `multipart` **7개 규칙 전부 `uvlock` 키 미기재**. source에 `false`가 있다고 해석하지 않았다.

### 2-2. 본체 4요소·24면과 병/빈자리 양면 판 6개

- 기본 양조기 `models/block/brewing_stand.json`은 **4요소/24명시 UV면**. 세 군데 받침과 중심 기둥의 원시 형상을 가지고 있다.
- `brewing_stand_bottle0/1/2`와 `brewing_stand_empty0/1/2` 6모델은 각 **자체 1요소/2면**. 모두 **z축 두께 0**이고 **양쪽 면의 반대 UV 선언(6역방향 면)**을 사용한다. 이 6개 양면 표시는 실제 병의 3D 둥근 메시 모델과 동일하지 않다.
- 6개 오버레이 원형 중 **4개는 최소 x=-0.41**로 소스 블록 좌표 범위 `[0,16]`를 일부 벗어난다. 이는 **원본 모델 좌표**이며 게임의 실제 충돌상자·시야 가시성을 입증하지 않는다.
- 양조기 `brewing_stand.png`는 **16×16 원본 PNG 중 완전 불투명130·완전 투명126픽셀**. `brewing_stand_base.png`는 **256픽셀 전부 불투명**.
- 모델 **7개의 36원본 선언면**을 PNG의 직접 UV 사각형에 대조해 총 **2,016 texel-uses = 불투명1,260 + 완전투명756**, 부분 알파0을 얻었다. 이 중 기본 양조기 24면/480 uses는 모두 불투명. 병 표시 3원형은 각각 2면×256 uses 중 102 투명, 빈자리 3원형은 각각 2면×256 uses 중 150 투명.

## 4. 모닥불 `campfire` — 켜짐/꺼짐에 따라 기하 형상이 달라지는 별도 사례(소스 단계)

이번 v31에서는 `template_campfire`, `campfire_off`, `campfire`, `soul_campfire` 원본 JSON과 `campfire/soul_campfire` 블록 상태 JSON, 불꽃 `.png.mcmeta` 2개를 직접 읽었다.

- 불꽃이 포함된 `template_campfire`: **7요소/32선언면** 중 **0두께 2요소**, 요소 회전 **2개**.
- 꺼진 `campfire_off`: **5요소/28선언면**, 0두께 요소 0개·내부 회전 요소 0개.
- `campfire`와 `soul_campfire` leaf는 각각 자체 요소 0개로 **공통 켜진 원형 `template_campfire`**을 상속하고 `#fire`·`#lit_log`를 각기 다른 PNG로 대입. 두 종류 모두 꺼졌을 때 **공통 `campfire_off` 원형** 참조.
- `campfire` 및 `soul_campfire` blockstate의 조건은 **각 8개 = 합계16개**. 불꽃 PNG `campfire_fire.png.mcmeta`, `soul_campfire_fire.png.mcmeta`는 `animation.frametime=2` 명시.
- **모닥불은 이번에 원본 요소·상태·메타데이터만 조사**했고 **애니메이션 PNG의 프레임별 실제 픽셀, 인게임 불꽃·조명/렌더 동작은 측정하지 않았다**. 그러므로 위 책장/양조기 47면·3,808회에 모닥불의 선언면을 혼입하지 않는다.
