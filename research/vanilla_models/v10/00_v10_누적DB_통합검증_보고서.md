**버전:** Minecraft Java Edition **1.21.11** · 2026-11-12  
**범위:** Stage 1의 02 바닐라 모델 구조 분석(진행 중)  
**자료:** [v8 SQLite](../../../data/MC_Furniture_Style_Stage1_Research_v8.sqlite), [v9 모델 CSV](../v9/01_특수모델_부품요약.csv), [v9 애니메이션 CSV](../v9/02_애니메이션_클립_실측.csv)

## 이번에 한 일

1. 기존 v8 SQLite를 로컬 복제하여 초기 데이터 유지.
2. GitHub에 존재하는 v9 CSV 2개의 Git blob SHA-1을 로컬 작업 파일과 비교하여 완전 일치 확인.
3. `special_model_layers_v9`(19행), `special_animation_clips_v9`(15행), `validation_audit_v10`(6행)을 신규 생성.
4. 기존 v8 데이터베이스의 테이블과 행 수 보존, `PRAGMA integrity_check = ok` 및 외래키 문제 0개 확인.
5. [v8→v10 SQL migration](../../../data/migrations/v8_to_v10.sql)을 GitHub에 게시하여 다른 채팅·컴퓨터에서 v10 데이터를 재현 가능하게 함.

## 구체적인 모델링 관찰

- 침대 모델: 머리와 발 부분 각각 본체 1·다리 2의 **3개 요소**. 각 모델 본체의 **로컬** 치수는 16×16×6.
- 일반 상자: 몸체 14×10×14, 뚜껑 14×5×14, 잠금장치 2×4×1의 **3요소**. 대형 상자는 좌우 모델을 각각 별도 3요소로 분리.
- 표지판: 세워진 형태는 2요소, 벽형은 1요소. 로컬 판 크기 24×12×2지만 모델 변환에서 **2/3 배율**을 적용하므로 완성 크기로 직접 해석할 수 없음.
- 매달린 표지판: 텍스처가 붙는 판과 체인을 별개 요소로 만들고 체인의 한 축은 **0**. 계량한 15개 0두께 요소에 기여.
- 셜커 상자: 바닥/뚜껑 각 1요소, 열림/닫힘 클립은 뚜껑 파트에 작용.
- 책: 7요소 중 일부가 두께 **0.005**로, **0두께 계수에서는 제외됨**.
- 종·장식 도자기·현수막: 중심 구조와 별도의 렌더링 레이어·면 요소를 혼합한 사례.

상기 수치는 `minecraft-entity-models`의 **비공식 추출 JSON 데이터**를 읽어 계산한 값이며 공식 `client.jar` 또는 인게임 렌더 직접 확인은 아니다.

## GitHub에서 직접 재현하기

기존 v8 DB는 원본 그대로 유지하고 SQL migration으로 추가한다.

```bash
cp data/MC_Furniture_Style_Stage1_Research_v8.sqlite /tmp/MC_Research_v10.sqlite
sqlite3 /tmp/MC_Research_v10.sqlite < data/migrations/v8_to_v10.sql
sqlite3 /tmp/MC_Research_v10.sqlite "PRAGMA integrity_check;"
sqlite3 /tmp/MC_Research_v10.sqlite "SELECT COUNT(*) FROM special_model_layers_v9;"
```

기대 출력: `ok`, `19`. Python으로 재구성하려면 [재현 스크립트](../../../scripts/rebuild_v10_db.py)를 사용한다.

## 검증 한계 및 단계 상태

- 공개 GitHub에는 **v8 SQLite + v10 증분 SQL**을 저장. v10 전체 SQLite 바이너리는 이 시점에 GitHub로 별도 업로드하지 않았다. 따라서 사용자는 migration을 적용해야 v10 DB를 얻는다.
- Mojang 공식 버전 게임의 `client.jar`와 비공식 추출본의 해시/바이트 직접 대조가 아직 없다.
- 바이옴 틴트·투명도·그림자·UV 매핑·애니메이션의 **게임 내 최종 화면 검증은 미완료**.
- 01 텍스처 표본 150/150은 **표본 달성 100%**이지 최종 작업 완료율이 아니다. 02도 모집단이 정의되지 않아 전체 완료 퍼센트를 임의로 매기지 않는다.
