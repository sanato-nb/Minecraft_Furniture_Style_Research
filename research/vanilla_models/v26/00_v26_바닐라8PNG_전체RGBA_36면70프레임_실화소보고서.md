# v26 — Minecraft 1.21.11 원본 PNG 8종 전체 RGBA 해독 및 36면·70프레임 UV 실화소 직접 분석

**일자:** 2026-11-13 KST · **연구 범위:** 상위 1단계 01 바닐라 텍스처 및 02 바닐라 모델/UV · **이전 체크포인트:** v25 · **가구 모드 신규 분석:** 없음.

## 0. 왜 이 작업을 했는가?

v25는 사용자 저장소의 `1.21.11/assets/minecraft/`를 직접 읽어 모델 JSON 32개, blockstate 8개, PNG **헤더** 8개와 .mcmeta 2개를 조사했다. 그러나 PNG **압축 데이터 내부 RGB/알파** 및 그 이미지를 참조하는 모델 **개별 face UV 내부의 픽셀 값**은 확인하지 못했다. 이번 v26은 **같은 8개 PNG를 실제 디코딩하고**, 그중 4개 텍스처를 참조하는 6개 JSON 모델의 면을 직접 연결해 이 빈틈을 보완한다.

공개 저장소에 있는 1.21.11 에셋은 공식 Mojang `client.jar`임이 증명된 자료가 아니다. 이번 단계는 **GitHub에 올라온 원본 bytes에 대한 직접 측정**이지 공식 JAR 인증/인게임 시각 검증이 아니다.

## 1. 원본 PNG 8종 전체 픽셀 재해독

| 원본 PNG | 크기 | RGBA 고유 색 (투명 색 포함) | 완전 불투명 | 완전 투명 | 부분 알파 |
|---|---:|---:|---:|---:|---:|
| block/oak_planks | 16×16 | 7 | 256 | 0 | 0 |
| block/dirt | 16×16 | 7 | 256 | 0 | 0 |
| block/composter_top | 16×16 | 5 | 112 | 144 | 0 |
| block/stonecutter_saw | 16×48 | 7 | 768 | 0 | 0 |
| block/lantern | 16×48 | 19 | 318 | 450 | 0 |
| block/oak_trapdoor | 16×16 | 7 | 220 | 36 | 0 |
| entity/chest/normal | 64×64 | 61 | 1,652 | 2,444 | 0 |
| entity/signs/oak | 64×32 | 15 | 840 | 1,208 | 0 |
| **전체 8 PNG** | **8,704 픽셀** | 서로 다른 이미지의 색상은 합산 금지 | **4,422** | **4,282** | **0** |

- 원본 파일마다 `Git blob SHA`, bit depth, color type, 크기, RGBA 색 수, 알파 분포를 [01 전체 화소 CSV](01_eight_png_full_rgba_pixels.csv)에 기록했다.
- 이번 v26에는 GitHub에서 `fetch_file(base64)`로 원본 이미지의 **전체 파일 bytes**를 읽었다. JS로 Base64 → PNG chunk(IHDR/PLTE/tRNS/IDAT) → zlib DEFLATE 및 PNG scanline filter 역연산 → RGBA 화소 변환을 수행했다. 인덱스 팔레트 PNG(4/8비트) 및 그레이스케일 PNG(8비트) 모두 해독했고, `IDAT` 해제 후 **스캔라인 크기 검산**과 `불투명+투명+부분알파 = width×height` 검산에 통과했다.
- **독립 검증 한계:** PNG 각 chunk CRC와 zlib Adler-32를 별도 검증하지 않았고, 동일 원본을 Pillow로 독립 end-to-end 재실행하지 않았다. 원본 해시/기존 측정치 교차검증 결과는 별도 기록한다.
- `block/composter_top`은 원본 256픽셀 중 **144픽셀이 완전 투명**하다. 이 수치는 곧바로 실제 화면의 투명한 면적 비율 또는 충돌 구멍 비율을 뜻하지 않는다.
- `stonecutter_saw` 및 `lantern`은 **16×48** 스프라이트이며 앞 단계에서 직접 읽은 `.png.mcmeta`에 따라 **16×16 프레임 3장**으로 나누어 분석했다(`frametime` 각각 1과 8).

## 2. 원본 모델 face→실제 PNG/프레임 UV RGBA 연결

선정 **6개 JSON 모델**의 명시적 `faces.*.uv`를 읽고, 모델 leaf의 텍스처 재정의/모델 자체 `textures` 슬롯을 결합했다.

| 모델 | 고유 모델 face | 검사한 face×frame 기록 | UV 영역 내 전체 텍셀 사용 | 완전 불투명 | 완전 투명 |
|---|---:|---:|---:|---:|---:|
| template_trapdoor_bottom | 6 | 6 | 704 | 632 | 72 |
| template_trapdoor_top | 6 | 6 | 704 | 632 | 72 |
| template_trapdoor_open | 6 | 6 | 704 | 632 | 72 |
| flower_pot (위쪽 dirt 1면) | 1 | 1 | 16 | 16 | 0 |
| template_lantern | 15 | 45 (3프레임) | 936 | 924 | 12 |
| stonecutter (톱날 양면) | 2 | 6 (3프레임) | 588 | 588 | 0 |
| **합계** | **36** | **70** | **3,652** | **3,424** | **228** |

- 모드 프로젝트 집계와 동일하게 **면 인스턴스/프레임을 중복 포함한 텍셀 사용 수**를 구분했다. 3,652는 3,652개의 서로 다른 소스 PNG 픽셀이 아니며, 화면에 렌더된 3,652개 픽셀도 아니다. 사용한 UV 사각형은 모델의 **명시적 UV**만을 대상으로 한다.
- [02 면·프레임별 실화소 CSV](02_selected_face_frame_original_rgba.csv) **70행**에는 모델 SHA/요소 번호/면 방향/슬롯/최종 PNG SHA/원래 UV 네 좌표/프레임/역방향 UV 여부/회전/cullface/투명도 및 RGBA 팔레트 통계를 저장했다.
- **UV 역방향 기록 19/70**, UV 면적 0 기록 **0/70**, 부분 알파 픽셀 사용 **0회**. 역방향 UV는 잘못된 UV가 아니라 좌표의 순서를 바꿔 매핑하는 소스 선언이다.
- 다락문 원형 `template_trapdoor_bottom/top/open`의 `#texture`는 v25에서 읽은 `oak_trapdoor_bottom/top/open` leaf의 `minecraft:block/oak_trapdoor` 바인딩으로 해석했다. 세 원형은 3가지 배치에 따라 UV 방향·영역이 다르지만 각 6면 전체의 샘플은 총 704회, 불투명 632/투명 72로 일치했다.
- 화분 `flower_pot`의 `#dirt`로 지정된 윗면 `UV=[6,6,10,10]`은 **16픽셀 전체 불투명**이었다. 화분의 `#flowerpot`를 참조하는 다른 **21면은 텍스처 미해독으로 미검증**이며 36면 표본에 넣지 않았다.
- 랜턴 `template_lantern`의 15개 선언 면을 3프레임 모두에 적용(45건), 톱날 `stonecutter`의 두 면을 각각 3프레임에 적용(6건). **애니메이션 스프라이트의 프레임별 원본 UV 영역**을 관찰한 것이지 렌더·콜리전·조명·실제 시간축을 테스트한 것이 아니다.
- `composter` 본체 `faces`는 **명시 `uv` 없이 자동 UV 규칙을 적용**하는 면들이 있어 이번의 '명시 UV 직접 텍셀' 70건에는 포함하지 않았다. 후속 분석에서는 자동 UV 산식을 별도로 검증해야 한다.

- [04 과거 v4 150종 데이터 교차검사](04_three_v4_texture_metrics_crosscheck.csv): `oak_planks`, `dirt`, `oak_trapdoor`은 v4의 기존 표본에도 있었음. **3/3** 파일 바이트 수·가로세로 크기·전체 픽셀 수·가시 픽셀 수가 v26 새 해독과 **일치**했다. v4에 저장된 SHA-256을 v26에서 별도로 새로 계산하지 않았으므로 SHA-256 재검증과 혼동 금지. 나머지 v26 PNG 5개는 v4의 150 텍스처 CSV에 동일 `texture_id`로 기록되지 않았다.
- 관련 v25 문서: [v25 이전 감사](../v25/00_v25_바닐라원본_모델상속상태PNG_직접검증보고서.md). **v25의 8 PNG 헤더 확인을 v26의 새 8 PNG 전체 화소 재해독으로 업그레이드**했으므로 v26 파일 수를 v25 누적 PNG 종류에 무조건 더하지 않는다.

## 4. 바닐라 모델링 방식에 대한 관찰 (확정 규칙 아님)

1. 같은 참나무 다락문 리소스가 **상태별 3개 부모 기하 모델**에 다른 UV 방향으로 사용된다. 가구의 여닫힘·회전 상태 표현 시 모델 상태/기하, 재질 UV 변환을 분리해 고려해야 한다.
2. `oak_trapdoor`은 원본 픽셀의 36/256이 완전 투명이고, 세 부모 모델의 각 6면에서 사용된 픽셀도 별도 계량할 수 있다. **부분 투명도 0**은 이 표본 8 PNG에만 유효하다.
3. `lantern` 아틀라스에는 프레임 전체에서 투명 픽셀이 많지만, 원형 템플릿 15면이 참조하는 **UV 사각형** 내부의 실제 투명도는 프레임별 합산에서 **12/936회**뿐이다. **PNG 전체 투명도와 물체 표면에 직접 쓰는 UV 부분의 투명도는 다르다.**
4. `stonecutter_saw`는 본체의 **0두께 요소** 1개가 양쪽 면에 애니메이션 PNG를 붙이며, 두 면의 UV는 반대 방향이다. 이러한 소스 선언이 실제 게임의 양면 시각 효과로 이어지는지 인게임 검증은 보류다.
5. `composter_top`은 완전 투명 영역이 많은 텍스처라는 사실은 확인했지만, 해당 블록의 암시적 UV를 실제 게임처럼 적용한 결과는 아직 확인하지 못했다.
