### 1-1. 텍스처 18원본 PNG의 전체 디코딩

선정된 PNG **18개 경로 모두 `fetch_file(base64)`로 전체 바이트를 취득**해 PNG IDAT를 해제하고 16×16 RGBA로 복원했다. **18×256 = 4,608개 원본 소스 픽셀**에 대해 **완전 불투명 3,582, 완전 투명 1,026, 부분 알파 0**을 측정했다.

- 이전 v4 **150개 선정 텍스처 표본과 겹치는 경로 5개:** `oak_planks`, `dirt`, `enchanting_table_side`, `anvil`, `anvil_top`. v4에 없었던 **13개 경로**는 기존 150종에 무조건 새 목표 수치로 가산하지 않는다.
- v26–v29에서 직접 다시 읽은 `oak_planks`, `dirt` 두 경로는 재사용으로 표시한다. 현재 v30 파일에서 전 바이트 해독한 18개 **모두가 프로젝트 전체 최초 시도**라는 뜻이 아니다.
- **PNG 자체**에는 투명 픽셀이 1,026개 있지만, 이번 **선정 모델의 명시된 UV 사각형**에 사용된 픽셀은 6,012회 모두 불투명이다. 즉, **PNG 전체 알파 비율과 실제 선택한 모델 표면의 알파 비율은 서로 다르다**.
- 투명도가 있는 대표 PNG: `grindstone_pivot` 196/256 투명, `grindstone_round` **160/256**, `grindstone_side` **112/256**, `flower_pot` 206/256, `enchanting_table_side` 64/256, `anvil_top` **96/256**, `chipped_anvil_top` 및 `damaged_anvil_top` 각각 96/256 투명. 이는 **파일 전 영역** 수치다.
- [09 v4 150종 중 5개 동일 경로 데이터 대조](09_five_legacy_v4_png_metrics_crosschecks.csv): **5/5** 파일 크기·가로세로·전체 픽셀·가시 픽셀 수 일치. SHA-256은 이 5종 전부 v30에서 독립 재계산한 것이 아님. `anvil_top`은 아래 `tRNS` 수정 후에야 가시 픽셀 **160**으로 일치했다.

## 2. 개별 모델링 구조 관찰 (원본 source 근거 등급)

### 독서대: 3요소 + 내부 요소 기울기 + 방향 회전

- `lectern`은 **자체 요소 3개/선언면 16개**. 몸체 상단 요소의 원본 `rotation.angle=-22.5`, `axis=x`, `origin=[8,8,8]`; **요소 내부 회전 1개**를 확인했다.
- 원본 `blockstates/lectern.json`은 `facing` 4방향에 `y=0/90/180/270` 원형 1모델을 적용. **모델 요소의 회전**과 **방향 블록 상태의 회전**을 구분해야 한다.
- 독서대의 놓인 책은 본체 source JSON의 3요소에 직접 기재되지 않는다. 이전 [v8 특수 렌더링 연구](../v8/00_v8_특수렌더_정적동적_비교보고서.md)는 `LecternBlockEntityRenderer`를 별도 경로로 확인했으나, v30에서 공식 게임 실행 화면/책 자세까지 재검증한 것은 아니다.

### 숫돌: 같은 모델을 바닥·벽·천장에 상태별 재배치

- `grindstone`은 **5요소/26명시 UV면**. `blockstates/grindstone.json` 원본에 `face=floor|wall|ceiling × facing=4`의 **12개 variants**가 존재하며 **`x` 회전 0/90/180과 `y` 회전 0/90/180/270**의 조합을 지정한다.
- 원본에 `element.rotation`이 없어도 `blockstate`의 회전으로 모델 설치 방향을 다양화하는 사례다. 다만 실제 텍스처 UV 보정, `uvlock` 렌더 효과, 부착 충돌체는 인게임 미확인.

### 화분: 내부 요소로 속 빈 느낌을 만들고 필요한 UV만 잘라 사용

- `flower_pot`은 **5요소/22면**, 원시 bbox **[5,0,5]–[11,6,11]**. `flower_pot.png` 전체에서 **206/256투명**하지만 **21개 `#flowerpot` 면의 UV**는 전부 불투명 픽셀만 사용. `#dirt` 1면도 불투명 원본 `dirt.png`를 사용.
- 장식용 작은 블록의 전체 PNG 배경은 많은 투명 픽셀을 포함할 수 있어도 실제 지정된 UV 사각형에서 필요한 영역만 사용한다는 근거다.
- 책상용 화분 등의 실제 게임 배치 크기/꽃 모델은 이번 분석 범위 밖이다.

### 마법 부여대: 정적 JSON 본체와 별도 책 엔티티

- `enchanting_table` 원본 JSON 본체는 **1요소/6선언면**, bbox **[0,0,0]–[16,12,16]**. 3가지 `bottom/top/side` 원본 PNG와 UV 사각형을 직접 결합하여 **1,280 텍셀 사용**을 확인했다.
- `enchanting_table_side.png`에는 **64/256 완전 투명** 픽셀이 있으나 본체의 `side` 4면이 지정한 UV 영역은 모두 불투명이다.
- 이전 [v8 렌더러 조사](../v8/00_v8_특수렌더_정적동적_비교보고서.md)는 마법 부여대 책에 `EnchantingTableBlockEntityRenderer`를 확인했고, [v9](../v9/00_v9_실제부품구조_분석보고서.md)는 비공식 엔티티 모델 `book` 요소를 조사했다. v30에서 그 책 렌더 결과를 인게임 직접 재현한 것으로 표시하지 않는다.

### 모루: 같은 4요소 기하를 공유하고 윗면 재질만 변경

- `template_anvil` 원본 **4요소/21면**의 몸체 `#body`는 세 leaf에서 **같은 `block/anvil` 텍스처**를 사용한다.
- `anvil`, `chipped_anvil`, `damaged_anvil`은 각각 **자체 요소 0개**, 부모 `template_anvil`을 공유하며 **`#top` PNG만 상태별로 바꾼다**. 하나의 source top face `UV=[3,0,13,16]`에 세 PNG의 **160개씩 실제 불투명 픽셀**을 비교했다. source PNG 전체에는 `anvil_top`의 경우 **96개 투명 픽셀**이 있는데 해당 UV 바깥에 있다.
- 이는 외형의 손상 상태를 **전체 메시 재제작이 아닌 면별 텍스처 교체**로 구현할 수 있는 바닐라 사례다. 손상 상태 전이·내구성 게임 로직은 이번 조사 대상이 아니다.
- [07 7개 블록상태 30개 variants 전수 표](07_seven_blockstates_all_variants.csv), [08 모루 leaf 3개 재질 오버라이드](08_anvil_three_leaf_top_texture_overrides.csv).

## 3. 중요한 검증 오류 발견 및 v26 정정

### 그레이스케일 PNG `tRNS` 처리 누락

v30 최초 검사 중 `anvil_top`을 **모두 불투명**으로 잘못 집계했다. v4 기록의 가시 픽셀 160과 불일치하는 이유를 조사했고, PNG의 **회색조(`color_type=0`) `tRNS` 투명색 값 0**을 무시한 디코더 오류임을 확인했다. 해당 PNG가 지정한 0 그레이스케일 픽셀은 투명으로 처리해야 한다.

- 원본 바이트를 독립 **Pillow**로 `verify()` 및 RGBA 디코딩한 **4개 파일**: `stonecutter_saw`(v26), `grindstone_round`, `grindstone_side`, `anvil_top`. 각각 알파가 정확히 **246/522**, **96/160**, **144/112**, **160/96**(불투명/완전 투명)임을 확인했다.
- v30 새 PNG 계량 CSV 중 `grindstone_round`, `grindstone_side`, `anvil_top`을 **바르게 정정한 최종 값**만 저장한다. 이 3 PNG의 원본 UV에 연결한 선택 영역은 전부 불투명이므로 **v30 면별 UV의 6,012회 불투명**은 수치 변경 없이 확인되었다.
- 이전 **v26 `stonecutter_saw` PNG 자체**는 종전에 **768불투명/0투명**으로 잘못 보고됐으나 정확히 **246/522**이다(프레임별 각각 82/174). v26 톱날 source face×frame 6행(각98 텍셀)은 **82불투명/16투명**이어야 한다. 이에 따라 v26 총 8 PNG/8,704픽셀은 **불투명 3,900·완전 투명 4,804**, 기존 70 face-frame UV/3,652use는 **불투명 3,328·투명 324**로 수정했다.
- **수정 대상 v26 원본 파일:** [v26 보고서](../v26/00_v26_바닐라8PNG_전체RGBA_36면70프레임_실화소보고서.md), [PNG 8종 CSV](../v26/01_eight_png_full_rgba_pixels.csv), [70 UV행 CSV](../v26/02_selected_face_frame_original_rgba.csv), [v26 summary JSON](../v26/v26_vanilla_pixel_uv_audit_summary.json). 수정된 데이터는 v30 커밋에서 함께 게시하며, v26 보고서 상단에 **v30 정정 이력**을 기록했다.
- 이는 분석 정확도 보정을 위한 회고 수정이다. 기존 v27·v28·v29 연구의 Git SHA·표본 수·단계 번호는 임의로 변경하지 않는다.

## 4. 자료 검증 등급 및 남은 과제

- **A (원본 확정 관찰):** 사용자 업로드 GitHub의 JSON과 PNG 실제 바이트/SHA에서 직접 읽은 모델의 요소·면·명시 UV·텍셀 사각형, PNG의 RGBA 화소(단 `tRNS` 필수 처리), leaf의 재질 override 및 원본 blockstate variants.
- **B (간접 연구 결과):** v8/v9에서 비공식 소스·문서를 통해 확인한 책 렌더러/부품 구조. 공식 Mojang `client.jar`과 인게임 재현으로 확정하지 않음.
- **미검증:** 실제 게임의 기하 회전·`uvlock` 구현·조명·컬링·책 애니메이션/상호작용, 원본 업로드 자료의 Mojang 정식 client.jar 일치, 게임 내 스크린샷 픽셀 비교.
- **01 바닐라 텍스처** 기존 선정 표본 **150/150** 유지, v30에서 **18 PNG 전체 RGBA 재디코딩/그중 기존 v4 표본 5경로**, 나머지 **13경로는 v4 표본 외**. 표본 수 150/150은 바닐라 전체 PNG 전수 완료를 뜻하지 않는다.
- **02 바닐라 모델 구조** 5 원본 모델·91면/93면×재질 실제 화소 연결 확장. 이들 중 `flower_pot`의 흙 1면은 v26에서 조사한 반복이므로 **90원본 면을 새로 실화소 대조**했으며, 앞 단계의 36·20·26·40·160면과 동일 경로 중복을 주의한다.
- **상위 1단계 세부 작업 03/04의 v24 모드 데이터는 변경하지 않았다.** 05 최종 비교는 아직 미완료. **확정 완료 0/5**, 전체 완료율 백분율 미산출.
- **다음 우선순위:** 공식 Mojang 1.21.11 `client.jar` 무결성 검증, 실제 런타임의 책/블록 엔티티 렌더링·UV 회전/`uvlock`, 바닐라 가구형 블록 추가 원본 UV+PNG 실화소, 이전 회색조 PNG 처리의 다른 기록 영향 감사.
- **저작권:** 사용자 GitHub 저장소 루트 `1.21.11/`에는 게임 원본 `.class`·PNG·JSON이 공개되어 있어 재배포 권한 확인이 필요하다. v30 산출물에 원본 게임 에셋을 새로 복제하지 않고 파생 수치·경로·SHA만 저장했다.
