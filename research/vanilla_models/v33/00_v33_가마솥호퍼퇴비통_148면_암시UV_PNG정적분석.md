## 2. 빈 공간을 여러 입체 요소로 모델링하는 규칙

### 가마솥: 네 벽과 바닥, 별도 받침

- `cauldron` source는 **13개 elements/58 face 선언**. 기본 벽(좌우/앞뒤), 바닥 내부, 아래쪽 발받침/지지 요소를 나누어 속이 빈 느낌을 만든다.
- 원본 `cauldron_top.png`은 전체 **156불투명/100투명**, `cauldron_bottom.png`은 **84불투명/172투명**이다. 그런데 실제 `cauldron` 선언면에서 유도한 UV 사각형들에 포함되는 픽셀은 **2,336 텍셀 참조 모두 불투명**이었다. 게임 렌더가 자동으로 투명한 부분을 채운다는 뜻이 아니라, 모델 면별로 필요한 PNG 부분만 사용하는 **좌표·재질 선택의 결과**다.
- 원본 `cullface` 유무도 면마다 다르다. `cullface`는 원본 JSON 속성이지 실제 렌더에서 해당 면이 숨겨졌음을 직접 관측한 결과가 아니다.

### 호퍼: 6요소를 유지하고 마지막 배출구 하나만 바꾼다

- `hopper`와 `hopper_side` 모델은 각각 **7요소/32면**. JSON 전체 요소 원시 좌표/face를 비교하면 **처음 여섯 요소가 완전히 동일**, 마지막 요소 **1개만 변형**되며 face 방향 키도 달라진다.
- 아래쪽 출구(요소 인덱스6)의 `from=[6,0,6]`, `to=[10,4,10]`; 측면 출구는 `from=[6,4,0]`, `to=[10,8,4]`. **하단 배출구를 측면 배출구로 배치하는 기하 변경**이 근거가 되는 사례다.
- 원본 `blockstates/hopper.json`에는 5개 상태(`facing=down/east/north/south/west`). 아래는 `hopper` 기본 원형, 옆4방향은 `hopper_side` 원형을 `y=0/90/180/270` 회전하여 선택한다.
- `hopper_top.png`은 **156불투명/100투명**. 아래/측면 호퍼별 유도 UV **1,624 사용씩 전부 불투명**. **출구 변경 = 정적 원형 모델 변경 + 회전**으로 분석했으며 어떤 모션/애니메이션도 분석하지 않았다.

### 퇴비통: 본체는 유지하고 내용물 표면만 높이·텍스처가 변한다

- 본체 `composter`는 **5요소/18면**, 내부 바닥과 벽을 분리해 표현한다.
- `blockstates/composter.json`은 **9개 multipart 원본 규칙**이다. `level=0`에는 본체 1개, **`level=1..8`에는 항상 본체와 해당 내용물 모델의 2개**를 선택한다. 실제로 조건을 **9/9 수준**에 대해 평가하여 선택 중복·누락을 검사했다.
- 내용물 8개 원형은 각 **1요소·윗면1개**, 동일 **x/z=[2,14]** 직사각형 범위를 사용한다. 높이 **y=3,5,7,9,11,13,15,15**로 달라진다.
- **level7과 level8은 정확히 동일한 표면 높이 y=15**이지만, `#inside` 텍스처를 `composter_compost`에서 `composter_ready`로 교체한다. 이 자료는 **고정된 시점의 정적 상태 9종**에 대한 것이며, 보류 중인 변화 과정/움직임을 의미하지 않는다.
- 이전 v26에 검사했던 `composter_top` PNG의 불투명112/투명144는 v33 재측정과 **일치**한다. [03 퇴비통 내용물 0–8 고정상태·높이·텍스처](03_composter_0_to_8_static_level_models.csv) · [09 9상태 원본 multipart 선택 계산](09_composter_9_static_state_model_selection.csv).

## 4. 암시적 UV 추론과 실제 원본 PNG 화소의 경계

### 사용한 유도식 (런타임 검증 아님)

JSON 요소 `from=(x,y,z)`, `to=(X,Y,Z)`인 경우, 마인크래프트 모델 스펙의 자동 UV 원리와 면 방향을 참고하여 아래 UV 사각형을 **유도**했다.

```text
down  = [x,     16-Z, X,     16-z]
up    = [x,     z,    X,     Z]
north = [16-X,  16-Y, 16-x,  16-y]
south = [x,     16-Y, X,     16-y]
west  = [z,     16-Y, Z,     16-y]
east  = [16-Z,  16-Y, 16-z,  16-y]
```

- **원본 파일에 작성된 UV는 148면 모두 없음**. 위 유도식은 공개 모델 문서의 자동 UV 설명과 좌표 관례를 적용한 **정적 분석 코드**로, 1.21.11 공식 게임의 UV 계산 함수를 역컴파일·실행해 검증한 것이 아니다. 정확한 텍스처 좌표 순서·반전·광원/면 컬링은 클라이언트 소스 또는 실제 게임에서 별도 확인해야 한다.
- 참고 문서: [Fabric 1.21.11 block models](https://github.com/FabricMC/fabric-docs/blob/main/versions/1.21.11/develop/blocks/block-models.md), [Minecraft Wiki Block model](https://minecraft.wiki/w/Block_models). 이 외부 설명은 **원본 사용자 GitHub 자료와 다른 종류의 문서 근거**다.

| 원본 모델 그룹 | 면별 추론 UV 사각형에 실제 포함된 텍셀 사용 | 불투명 | 완전투명 |
|---|---:|---:|---:|
| 가마솥 58면 | 2,336 | 2,336 | 0 |
| 아래 호퍼 32면 | 1,624 | 1,624 | 0 |
| 측면 호퍼 32면 | 1,624 | 1,624 | 0 |
| 퇴비통 본체 18면 | 2,544 | 2,544 | 0 |
| 퇴비통 내용물 8상태 8면 | 1,152 | 1,152 | 0 |
| **전체 148면** | **9,280** | **9,280** | **0** |

이 값은 **원본 PNG에서 실제로 복호한 픽셀을 추론 UV 사각형으로 조회하여 합산**한 사용 횟수다. 중복 텍셀 사용 포함, 상태별 서로 다른 모델의 면을 합친 값이며 9,280개의 서로 다른 픽셀·GPU 화면 픽셀·실제 모든 면의 가시성은 뜻하지 않는다.

## 5. 정적 blockstate 원본 15규칙과 검증 한계

**근거 등급:** 실제 JSON 요소·면·재질·원본 12 PNG 전체 RGBA·네 PNG Pillow 교차검증은 **입력 소스에 대한 직접 실측**. UV의 면 방향별 정확한 직사각형/로더의 회전·조명·컬링은 **실행 검증되지 않은 유도 추론**. 퇴비통 조건 선택은 source JSON을 해석한 **정적 평가**, 인게임 UI/게임 상태 재현이 아니다.

**미완료/보류:** 공식 Mojang Minecraft Java Edition 1.21.11 `client.jar`의 독립 출처·해시 대조 미완료. 실제 게임 정적 모델 스크린샷/면별 UV 방향/조명 검증 미완료. **애니메이션은 사용자 지시에 따라 명시적 재개 전까지 보류**, 과거 연구 자료 보존. 모드 v24 지표·최종 05 비교 작업 변경 없음, **상위 1단계 최종 완료 0/5**.
