- 원본 `blockstates/oak_shelf.json` **1개**(SHA `404c901695218478e0bc1df86b4c66538d118f56`), `items/oak_shelf.json` **1개**(SHA `6d9a2c22fff4d4e117e2e98c5fd9f9fb3cb591ba`) 직접 확인.
- 원본 PNG **2개** `oak_shelf.png` SHA `2dd79677605cdc90a3473931f6f6cdb66d423f7c` 및 `stripped_oak_log.png` SHA `dcd8427ed7b8fc5f857b21c40686ef31baad35ea`를 **Base64 바이너리로 직접 조회**하고 v34 1,111 PNG SHA 목록과 **2/2 일치** 검증. - v36 선택 과거 근거 대조 기준으로 이 7개 중 **5개는 이전 SHA 일치 기록이 있고 2개(`oak_shelf_inventory`, `oak_shelf_right`)는 선택 과거 원장에 직접 SHA 증거가 없던 항목**. 이번 회차에서 7개 전부 다시 직접 SHA 확인. 이를 P1 전체 조사 완료율로 표현하지 않는다.

| 모델 계층 | 원본 모델·좌표 | 선언 원소 | 선언 면 |
|---|---|---:|---:|
| `oak_shelf` → `template_shelf_body` | 본체 `[0,0,13]→[16,16,16]`, 아래 받침 `[0,0,11]→[16,4,13]`, 위 받침 `[0,12,11]→[16,16,13]` | 3 | 15 |

| `oak_shelf_center/left/right/unconnected/unpowered` → 각각의 `template_shelf_*` | 공통 **0두께 앞면 패널** `[0,4,13]→[16,12,13]`, 북쪽 1면만 선언 | 각 1 (합 5) | 각 1 (합 5) |

- 부모 7개의 소스 정의 총 **11 elements / 38 declared faces**. 리프 7개는 자체 elements 0, 각 부모의 기하를 상속. 합계 11·38은 **서로 다른 원본 모델 정의의 합**이며 한 블록의 동시 렌더 면 수가 아니다.
- `oak_shelf`의 바운딩 박스는 x:0–16 / y:0–16 / z:11–16이므로, **기하 원본 범위만 기준으로** 블록 전체 깊이의 **5/16**을 차지하는 얕은 선반이다. 가운데 y4–12에는 단일 앞면 패널이 오며, 원본은 벽처럼 두꺼운 세로판 없이 0두께 단면을 활용한다.
- 모든 부품은 원본 `element.rotation`에서 **회전이 없는 직육면체/평면**. 방향 회전은 개별 요소가 아니라 아래 블록 상태의 **모델 전체 Y 회전**으로 지정된다.
- 아이템 에셋은 `minecraft:block/oak_shelf_inventory`를 직접 참조. 부모 inventory 모델은 GUI·fixed·on_shelf 등 별도 **display 변환**을 가지고 있어, 블록에 놓였을 때의 모델과 인벤토리 아이콘용 모델을 분리한다. 인게임 뷰 실측은 없음.

## 3. 정적 멀티파트 24개 규칙과 32개 상태 조합 전수 평가

원본 `blockstates/oak_shelf.json`의 `multipart` 배열 **24개**를 파싱한 뒤, 소스에 나타나는 `facing={north,east,south,west}` × `powered={false,true}` × `side_chain={unconnected,left,center,right}`의 **32개 조합**을 규칙 조건(AND 포함)에 통과시켜 확인했다.

- 각 조합에서 **정확히 2개 원본 모델 규칙이 적용**됨: 공통 `oak_shelf` 본체 1개 + 상태별 앞면 1개.
- `powered=false`면 `side_chain` 값과 관계없이 `oak_shelf_unpowered` 패널 1개가 선택된다.
- `powered=true`면 `side_chain` 값에 따라 각각 `oak_shelf_unconnected`, `oak_shelf_left`, `oak_shelf_center`, `oak_shelf_right` 중 1개를 선택한다.
- `facing`에 따라 두 부품 모두 source `y=0/90/180/270`(북/동/남/서)로 동일하게 지정. `uvlock` 키는 원본 규칙에서 **명시되지 않음**(이 사실을 엔진 내부 기본값의 독립 검증으로 오인하면 안 됨).
- 정적 한 상태에서 소스로 지정한 부품의 선언 원소/면은 **3+1=4 elements / 15+1=16 face instances**. 인벤토리 18면은 이 월드 블록 상태 조합에 추가되지 않는다.
- 24는 **소스 멀티파트 규칙 수**, 32는 **선택한 3개 속성의 조합 수**이므로 서로 다른 개념이다. 실제 게임에서 가능한 조합·전이 제한은 블록 코드/런타임 검증 없이 단정하지 않는다.

## 4. 32×32 원본 재질 아틀라스와 38면 전체 실제 RGBA·UV 대조

| 원본 PNG | 해상도 | RGBA 원본 화소 | 알파 255 | 고유 RGBA 색 | 모델 용도 |
|---|---:|---:|---:|---:|---|
| `oak_shelf.png` | **32×32** | **1,024** | **1,024** | **42** | `#all` → **38개 선언 면 전부** |
| `stripped_oak_log.png` | **16×16** | **256** | **256** | **37** | `#particle` → **기하 면 0개** |

- 독립 원본 화소 합계 **1,280 RGBA**, **완전불투명 1,280 / 알파0 0 / 부분투명 0**. PNG별 모든 청크 CRC32 및 zlib 압축 해제 성공.
- **38/38면 전부 UV 좌표 4개가 원본에 명시**되어 있다. 38면 중 x축 UV 좌표 반전 **8개**, y축 반전 **8개**(한 면이 양쪽에 중복 포함 가능), `cullface` 원본 키 지정 **23개**, 방향 무시한 고유 UV 사각형 **19종**.
- 텍스처는 32×32지만 JSON UV 공간은 0–16 정규화 단위이므로 **1 UV 단위 = 원본 PNG 2픽셀**로 대응된다. 예: 중앙 패널 `[0,12,8,16]` → 원본 PNG `[0,24,16,32]`, **16×8=128화소**.
- Pillow로 각 면의 UV 사각형을 실제 `oak_shelf.png`에서 **38/38개 크롭해 RGBA 읽기**. 합산 **2,304 texel-uses**(각 면마다 동일 원본 영역을 재참조하는 횟수 포함); 전부 **불투명 2,304**. 실물 유니크 PNG 화소 수 1,024와 구별해야 함.
- 앞면 5개의 평면은 각 **128 texel-uses**이며 서로 다른 아틀라스 구역을 지정한다. `center`는 `[0,12,8,16]`, `left`는 `[0,8,8,12]`, `right`는 `[8,8,16,12]`, `unconnected`는 `[8,12,16,16]`, `unpowered`는 `[0,2,8,6]`. 각 영역 RGB 실측 평균은 CSV에 기록.
- source UV 자체의 x/y 방향 반전 및 모델 회전을 **원본 정의로는 확인했지만** Minecraft 엔진에서의 최종 투영·컬링·조명·셰이더·실제 화면 모습은 아직 확인하지 못했다. 따라서 2,304개는 **원본 UV 사각형 화소 검사 횟수**, 인게임 렌더링된 픽셀 수가 아님.

## 5. 가구 모델링 연구에 연결되는 관찰 — 사실과 응용 가설 분리

**소스·화소로 확정된 사실:** 얕은 z 깊이(5/16), 3개 상자형 뼈대, 상태별 두께0 평면 1개, 같은 32×32 재질 아틀라스의 5가지 앞면 UV 선택, 모델 전체 방향 회전, 블록/아이템 모델 분리, 38면 explicit UV/일부 반전, 1,280 원본 RGBA 모두 불투명.

**가구 제작 가이드 후보(아직 게임 실측으로 검증하지 않은 제안):** 선반·장식장처럼 얕은 오브젝트는 큰 전체 큐브보다 소수의 받침 부품과 평면 디테일을 분리할 수 있다. 상태 차이는 새 지오메트리를 중복 작성하기보다 얇은 전면 패널 모델과 공유 아틀라스의 UV 선택으로 표현하는 설계를 시도할 수 있다. 인벤토리/아이템 표시용 면과 `display` 변환을 월드 모델과 별도 검토하는 것이 합리적이다.
