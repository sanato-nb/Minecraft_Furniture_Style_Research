## 이번 체크포인트에서 실제로 읽은 범위

직접 읽고 Git blob SHA를 기록해 파생 계량을 만든 **저장소 파일 50개**: 모델 JSON **32개**(직접 요소 8 + 부모 템플릿 8 + 상속 leaf 8 + 퇴비통 내용물 8), 블록 상태 JSON **8개**, PNG 바이너리 **8개**, 애니메이션 `.png.mcmeta` **2개**. 별도로 기존 비공식 1.21.11 추출본의 동일 경로 **6개 파일**을 재조회하여 Git blob SHA를 교차검사했다. 위 수치는 **이 보고서에 수록된 파생 데이터의 고유 파일 범위**이며, 이전 단계에서 읽은 파일 또는 탐색 중 열었던 추가 모델을 전부 합친 수가 아니다.

### 3. 퇴비통 내용물 8종 — 상태 조건과 고유 기하의 분리

`composter` 상태 JSON은 기본 `composter` 모델을 **항상** 적용하고, `level=1`~`8`에는 해당 `composter_contents*` 모델을 추가하는 **9개의 multipart 규칙**을 가지고 있다.

추가 모델 8개는 모두 자체 **1 요소/1 up face 선언**을 가진다. x,z 범위는 **[2,14]**, y 시작은 0이고, 높이는 `level=1..7`에 **3,5,7,9,11,13,15**, `level=8`에 **15**이다. 마지막 `ready` 상태의 윗면 슬롯은 기존 `composter_compost`가 아니라 `composter_ready`를 가리킨다. 실제 각 상태의 인게임 렌더 높이는 아직 확인하지 않았다. [03 CSV](03_composter_eight_content_layers.csv).

## 모델링 연구에서 얻은 관찰 (잠정)

1. 바닐라는 `cube` 상속 + 재질 면별 변경으로 외형을 표현하는 **텍스처 중심** 사례와, `cauldron`·`hopper`처럼 여러 요소로 실루엣을 만드는 **기하 중심** 사례를 함께 사용한다.
2. `stonecutter`, `template_lantern`, `template_campfire` 등에는 정확히 두께 0인 평면 요소가 등장한다. 평면의 실제 양면 표시·컬링은 게임 렌더에서 별도 검증 필요.
3. `composter`는 본체/내용물 조건부 합성, `door`/ `trapdoor`는 variant별 원형 선택과 회전을 사용한다. 여러 상태를 하나의 외형으로 뭉뚱그리지 말아야 한다.
4. 텍스처는 16×16 정적 리소스만이 아니다. 16×48 애니메이션 스프라이트, 64×64 엔티티 리소스 등이 공존한다.
5. **아직 모델링 규칙서 확정이 아니다**. 선택 표본·원시 JSON에 근거한 관찰로만 보관.
