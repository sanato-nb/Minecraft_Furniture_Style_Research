**작성 2026-11-16 KST · 원본 Minecraft Java 1.21.11 사용자 추출 자산.** 이 문서는 **기하·소스 중심 1차 관찰**, 전체 F의 `VANILLA_GEOMETRY_ARCHETYPES.md` 최종본이 아니다. 원본 PNG 이미지를 새로 눈으로 관찰하지 않았으므로 미술 스타일·재질·텍스처 디테일이 실제 어떻게 보이는지 **확정하지 않는다**.

## 비교 방법
- 분모: F Entry1의 고정 150경로 = P1/P2/P3 각50, 일반 C 직접기하142 + E 특수 소스8. 원본 JSON 각각 Git SHA 직접 확인150/150.
- 상속 모델은 leaf의 `parent`가 가리키는 **B의 검증된 적용 요소**를 사용했다. `from/to` 크기, 0/1 이하 두께, 회전 요소, 0~16 경계 밖, face를 재산출하여 C face원장과 **142모델 모두 일치**했다. B 적용 요소 총371개, 적용 face 참조1,373개. 이는 기존 B/C의 선행 관찰 재계산이며 신규 원본 371요소 발견을 뜻하지 않는다.
- **주 원형 분류는 배타적**이지만 **구조 태그는 복수 중첩 가능**하다. 회전·다중 요소·얇은 평면이 동시에 나올 수 있다.

## 겹칠 수 있는 기하 태그(합산 금지)
- 원본 축 정렬 cuboid 요소 기반142, **얇은 요소 있는 모델57**, **0두께 있는 모델52**, **다중 요소61**, **요소 회전36**, **경계 밖 또는 좌표 역방향16**, 정확한 전체 큐브33, E 예외8. 각각 모델 단위 태그 존재를 집계한 것이므로 합쳐서150으로 만들면 안 된다.
- `THIN_ELEMENT`은 모델 좌표축 `|to-from| ≤ 1`; `ZERO_THICKNESS`는 정확한 0. 이 연구의 비교용 기준이지 Minecraft 엔진의 공식 충돌형상 분류가 아니다.
- `AXIS_ALIGNED_CUBOIDS`는 **요소 원본 from/to 박스 자체**를 뜻하며, `rotation` 속성이 있는 요소가 실제 최종 렌더에서도 축 정렬된다는 뜻은 아니다.

- **아직 F에서 눈으로 확인한 PNG 0개.** C에서 이미 검증한 슬롯546행·고유 face-PNG188경로와 SHA/RGBA 해시만 다시 연결했다. 패널/프레임/다리·표면 등 재사용 용도는 모델링 *후보*이며 게임 속 사물 정체를 확인한 것이 아니다.
