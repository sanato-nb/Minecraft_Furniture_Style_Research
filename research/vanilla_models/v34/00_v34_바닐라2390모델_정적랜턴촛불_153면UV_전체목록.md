# v34 — 바닐라 전체 모델·상태·블록 PNG 실재 파일 목록 + 정적 랜턴·촛불·막대 모델 구조/UV 실화소

**작성:** 2026-11-13 (Asia/Seoul) · **연구 우선순위:** 정적 바닐라 모델 구조·명시 UV·PNG 실제 픽셀·블록상태·소스 출처. **사용자 요청으로 애니메이션 분석 보류 유지.**

> 검증 대상 소스는 사용자 GitHub 리포지토리의 `1.21.11/assets/minecraft/`이다. 이 저장소에 존재한다는 사실은 **Mojang이 배포한 공식 Java 1.21.11 `client.jar`의 바이트 출처/정품 무결성 증거가 아니다**. 실제 인게임 3D 모델, 조명, UV 회전, 컬링도 아직 검증되지 않았다. 게임 PNG/JSON 원본은 이번 연구 결과에 재업로드하지 않았으며 Git blob SHA·구조·파생 픽셀 측정만 공개한다.

## 2. 랜턴: 같은 4요소 형상 계열을 설치 방식·재질에 따라 조합

원본 `template_lantern.json`, `template_hanging_lantern.json`와 4 leaf(`lantern`, `lantern_hanging`, `soul_lantern`, `soul_lantern_hanging`)의 부모·텍스처 할당을 직접 읽었다.

| 종류 | 요소 | 원본 명시 UV 면 | 0두께 교차 평면 | 요소 내부 +45° 회전 |
|---|---:|---:|---:|---:|
| 바닥 설치용 템플릿 | 4 | 15 | 2 | 2 |
| 매달기용 템플릿 | 4 | 16 | 2 | 2 |
| **합계** | **8** | **31** | **4** | **4** |

- 본체 하단 요소는 설치형 **y=0..7**, 매달기형 **y=1..8**로 1단위 위로 이동하며, 위쪽 얇은 교차 부품의 길이와 높이가 더 길어진다.
- 두 번째 요소는 설치형 5개 face에 비해 매달기형 **아래쪽 `down` face 하나를 추가 선언**한다. 일반/영혼 랜턴 leaf는 각각 해당 설치형/매달기형의 **기하를 공유하고 `#lantern` 텍스처 경로만 바꾼다**.
- 원본 UV 31면의 좌표 범위·역순 선언·면별 컬링 표시는 전부 기록했다. 그러나 원본 `lantern.png`, `soul_lantern.png` 헤더가 **16×48**이며, 사용자 지시에 따라 이 PNG의 **프레임·실제 화소 디코딩/face→PNG 화소 대조는 v34에서 실시하지 않았다**. 31면을 PNG 화소 검증 완료로 합산하지 않는다.

## 3. 촛불 1–4개: 세 요소짜리 정적 원형을 배치 위치별로 여러 개 구성

`template_candle`/`template_two_candles`/`template_three_candles`/`template_four_candles` 실제 원본 JSON을 분석했다. 이번 화소 대조는 `candle_one_candle` 등 **꺼진 상태의 기본 `candle.png` 정적 재질만** 사용한다.

| 배치 촛불 개수 | 3D 요소 | 명시 UV 원본 면 | 0두께 평면 | 회전된 평면 |
|---|---:|---:|---:|---:|
| 1개 | 3 | 10 | 2 | 2 |
| 2개 | 6 | 20 | 4 | 4 |
| 3개 | 9 | 30 | 6 | 6 |
| 4개 | 12 | 40 | 8 | 8 |
| **합계(서로 다른 템플릿 4개)** | **30** | **100** | **20** | **20** |

- 각 촛불 구조는 **입체 몸체 1요소 + 서로 교차하는 0두께 평면 2요소**의 반복 조합이다. 교차 평면은 원본 JSON `rotation.angle=+45°/-45°`, `axis=y`로 선언된 정적 형상이다.
- 4개 템플릿에 기록된 원본 명시 UV **100면**의 픽셀 영역을 원본 `candle.png` RGBA에 연결했다. **520 texel-uses가 모두 불투명**했다. PNG 전체 256픽셀은 **불투명 21·완전투명 235**이므로, 전체 이미지의 투명 배경과 실제 모델 UV에 선택된 부분이 크게 다르다.
- 이 결과는 **촛불 개수별 정적 모형을 비교**한 것이며 **불꽃 애니메이션·켜짐 동작·프레임별 텍스처**를 조사한 것이 아니다. `blockstates/candle.json`의 `candles=1..4 × lit=false/true` 8개의 원본 모델 **선택 규칙만 목록화**했고 lit 재질의 픽셀은 새로 검사하지 않았다.

## 4. 엔드 막대·피뢰침: 한 모델 두 요소/11면, 방향과 상태의 정적 분리

- `end_rod.json`은 **2요소/11명시 UV면**, `template_lightning_rod.json`도 **2요소/11명시 UV면**이다. `end_rod.png`·`lightning_rod.png` 원본 16×16 PNG의 각 명시 UV 사각형에 실제 RGBA 픽셀을 대조했다.
- 엔드 막대: **172 texel-uses 모두 불투명**. 원본 PNG 전체는 불투명58/투명198.
- 피뢰침: **196 texel-uses 모두 불투명**. 원본 PNG 전체는 불투명40/투명216.
- `end_rod` blockstate는 `facing` 6방향의 6규칙, `lightning_rod`는 `facing` 6방향×`powered` 2상태의 12규칙. 피뢰침의 `lightning_rod`와 `lightning_rod_on` leaf는 기하 템플릿을 공유하면서 텍스처 경로를 변경한다. 이번 **픽셀 검증은 전원 꺼진 `lightning_rod` PNG만** 했으며 움직임·연속 장면은 연구하지 않았다.

## 5. 독립 PNG 검증 방법과 전수 픽셀 수치

Python/Pillow를 이용해 GitHub에서 실제 Base64로 읽은 원본 PNG 3개 각각에 대해 **PNG 파일 `verify()`, 16×16 전체 RGBA 디코딩, SHA-256 독립 계산, Git blob SHA-1 원본 경로 SHA와 일치 여부**를 직접 검사했다.

| PNG | 원본 전체 픽셀 | 불투명 | 완전투명 | 16×16 명시 UV 선택 텍셀 사용 |
|---|---:|---:|---:|---:|
| `candle.png` | 256 | 21 | 235 | **520** |
| `end_rod.png` | 256 | 58 | 198 | **172** |
| `lightning_rod.png` | 256 | 40 | 216 | **196** |
| **합계** | **768** | **119** | **649** | **888(모두 불투명)** |

- Pillow가 복원한 **각 PNG의 16행×16열 불투명 픽셀 위치**를 행별 16비트 마스크로 기록했다. 원본 모델 UV 사각형의 각 좌표를 이 마스크에 직접 교차해 **122개 원본 명시 UV 면/888 texel-uses 모두 불투명**을 대조했다. **나머지 랜턴 31면은 PNG 미대조**다.
- 모든 8개 기하 원형의 **원본 face 선언 153면에 명시 UV가 존재**, 그 중 **역방향 UV 선언 18면**, 면적 0인 UV 0면, 요소 원시 좌표의 0두께 평면 **24요소**. 8개 원형은 **42요소·153면**, 이 중 122면만 실제 PNG 샘플 대조했다. 불투명/투명 119/649는 **세 PNG 원본의 고유 화소**, 888은 **면별 중복 사용을 포함한 텍셀 참조**이므로 서로 비교하거나 합산해서 게임의 화면 픽셀 수라고 주장하면 안 된다.
- [06 Pillow 독립 원본 SHA/실제 PNG 전체 픽셀/16행 알파 마스크](06_three_static_png_pillow_sha256_alpha_masks.csv).
- 기존 v4의 **150개 선정 텍스처 경로와 이번 3개 PNG 경로의 직접 중복은 0**. 같은 파일을 다른 체크포인트에서 조사했을 가능성과 별개다.

## 6. source 블록상태 5 JSON의 30 정적 선언 규칙

| 원본 blockstate | 선택 규칙 개수 | 구분 |
|---|---:|---|
| `lantern` | 2 | `hanging` false/true |
| `soul_lantern` | 2 | `hanging` false/true |
| `candle` | 8 | `candles` 1–4 × `lit` false/true |
| `end_rod` | 6 | `facing` 6방향 |
| `lightning_rod` | 12 | `facing` 6방향 × `powered` false/true |
| **합계** | **30** | 모든 원본 JSON variants 기록 |

원본 30규칙에서 `x` 회전 비0 **15규칙**, `y` 회전 비0 **9규칙**, `uvlock` 키 미기재 **30규칙**. 이는 속성이 source JSON에 없다는 뜻이며 모든 경우에 게임 로더가 `false`를 부여했거나 실제 회전 후 UV가 정렬된다는 것을 독립 검증한 것은 아니다. `lit`, `powered`는 정적인 **상태 선택 값**만 열람했고 애니메이션 프레임, 동작, 시간별 변화는 연구하지 않았다.

## 7. 명확한 검증 경계와 다음 실제 연구

**사용자 소스 직접 읽기:** 8원형 JSON의 42요소·153면 전체 선언 UV·정적 회전, 10 leaf JSON의 부모/재질 바인딩, 5 blockstate JSON의 30원본 variants, Git tree 전체 모델/상태/블록 PNG 파일 SHA 인벤토리. **독립 픽셀 검증:** PNG 3개 768 RGBA 픽셀 및 그 중 122 face×PNG 사각형의 중복 텍셀 사용 888회.

**의도적 보류:** 랜턴 16×48 PNG 화소·프레임 분석, 모든 불꽃/촛불 lit 텍스처의 시간 경과·움직임, 게임 애니메이션 재생과 키프레임 분석. 과거 연구 증거는 보존하며 사용자가 명시적으로 재개할 때까지 새로운 애니메이션 연구를 하지 않는다.

**미검증:** 공식 Mojang 1.21.11 `client.jar` 바이트 독립 인증; 엔진 내부 UV winding·`uvlock`/광원·면 컬링; 인게임 정적 모델 화면 대조; 전체 2,390 JSON 중 가구에 실제 해당하는 검증 대상의 선정과 완료율. 기존 v24 모드/05 비교 수치는 변경하지 않았고, Stage 1 최종 완료 **0/5**를 유지한다.

**다음 우선 작업:** 전체 원본 모델 파일 인벤토리 기반의 **가구형 정적 모델 검수 대상 정의**, 인게임과 로더 수학의 정적 UV 교차확인, 새로운 복합 가구 정적 부품 모델 확대. 원본 게임 파일 재배포 권한은 별도 점검.
