# v27 — 바닐라 1.21.11 선반 32×32 아틀라스와 퇴비통 자동 UV·블록 상태 원본 검증

## 0. 새로 확인한 범위, 증거 종류

- 사용자 저장소 `1.21.11/assets/minecraft`의 **새로운 PNG 5경로를 직접 전체 RGBA 디코딩**: `oak_shelf`(32×32), `composter_side`, `composter_bottom`, `composter_compost`, `composter_ready`(각 16×16). **2,048 소스 픽셀, 불투명 1,824 / 완전 투명 224 / 부분 투명 0**. 단, `oak_shelf`는 기존 v4 150 텍스처 표본에 이미 포함되어 있었다. `composter_top`은 v26에 디코딩된 파일을 원본에서 다시 읽어 UV 샘플에 재사용한 것으로 신규 5종·2,048픽셀에 포함하지 않음.
- 선반 원본: `blockstates/oak_shelf.json` 1개, `oak_shelf` leaf와 템플릿 **6개** (`template_shelf_body` 및 상태별 5개) JSON을 직접 읽어 원본 Git blob SHA 기록; 나머지 5개 leaf도 각 부모·텍스처 override를 재조회했다.
- 퇴비통 원본: `models/block/composter.json` 자체 **5요소/18선언 면**, `composter_contents1..7` 및 `contents_ready` 8종의 **v25 원본 JSON 직접 읽기 근거/SHA CSV 재사용**. `blockstates/composter.json` 기본 본체+상태별 내용물 9개 multipart 규칙은 v25 원본 근거를 계승.
- **명시적 UV**(선반) 20개 면과 **미기재 UV의 좌표 재구성**(퇴비통 본체 18 + 내용물 8) 26개 면을 원본 텍스처에 대조. 둘 다 이미지 실제 RGBA 픽셀을 샘플링했지만 **UV 좌표의 검증 등급이 다르다**. 퇴비통은 아래의 공식/참조 식으로 `uv`를 **유도한 값**으로, 원본 JSON에 적혀 있지 않다. 실제 게임 엔진 바이트코드/인게임 UV 검증 완료로 표시하지 않는다.
- 원본 데이터와 재생성 통계만 게시했으며, Minecraft 저작권 원본 JSON/PNG/클래스/JAR을 이번 연구 폴더에 새로 복제하지 않았다.

## 1. 선반: 32×32 PNG와 모델 얼굴의 실제 UV 픽셀

원본 `oak_shelf.png` **32×32=1,024픽셀**, 42가지 RGBA 값, **1,024픽셀 모두 불투명**(투명 0, 부분 알파 0). 원본에 저장된 모델 UV 수치는 통상 **0–16 좌표 단위**이므로, 이 32px 텍스처에서 `UV×2 = 실제 텍셀 경계`로 변환해 샘플링했다. `0.5` UV 단위도 32px 스프라이트에서는 정확한 1픽셀 경계에 놓임. 좌표가 텍셀 경계와 맞는지 **20/20 직접 검증**.

| 모델/타입 | 요소 | 원본 선언 면 | 면 UV 실제 픽셀 표본 |
|---|---:|---:|---|
| `template_shelf_body` | 3 | 15 | 본체·위·아래 전부 샘플 |
| `template_shelf_unpowered` | 1 (0두께) | 1 | 전면 상태 UV 한 면 |
| `template_shelf_unconnected` | 1 (0두께) | 1 | 전면 상태 UV 한 면 |
| `template_shelf_left` | 1 (0두께) | 1 | 전면 상태 UV 한 면 |
| `template_shelf_center` | 1 (0두께) | 1 | 전면 상태 UV 한 면 |
| `template_shelf_right` | 1 (0두께) | 1 | 전면 상태 UV 한 면 |
| **합계** | **8 (각 원형 독립 합계)** | **20** | **20면** |

**면 20건 실제 텍셀 사용 합계 1,376회**, 불투명 1,376/완전투명 0/부분투명 0, 반전 UV 4면, 0면적 UV 0면. 이것은 *서로 다른 1,376개 텍셀*이나 1회 선반을 게임에 배치한 상태의 면 수가 아니며, **본체 15면 + 서로 다른 전면 표시 5면**을 개별 원형마다 샘플한 합계이다.

대표: 몸체 `east` UV `[8,0,9.5,8]`은 32px 원본에서 **[16,0,19,16]** 영역이며 **48픽셀**, 실제 알파는 전부 불투명. 전면 상태 템플릿 5개는 각 **128픽셀(전부 불투명)**을 별도 아틀라스 영역에서 가져온다.

### 선반의 실제 상태 조립: 24개 source multipart 규칙

`oak_shelf`의 블록 상태 JSON에는 **총 24개의 multipart rule**: 4방향 본체 4개, `powered=false` 전면 4개, `powered=true` + `side_chain` 값 `unconnected|left|center|right` 각각 4방향×4종=16개. 원본에 나오는 **4방향×전원2종×연결상태4종 = 32개의 구성 상태를 명시적으로 열거해**, 그중 각 조건에 적용되는 rule을 계산했다.

**32/32 입력 조합에서 본체 1개 + 전면 1개 = 모델 경로 2개**가 선택되며 두 모델의 `y` 회전값이 일치(0, 90, 180, 270)했다. `powered=false`에서는 연결상태에 관계없이 `unpowered` 전면이 선택된다. **이 32종은 소스의 네 side_chain 분기값으로 구성한 합성 조합 표본**이며 모든 게임 내부 유효 상태가 존재한다는 보증이나 실제 인게임 방향/텍스처 uvlock 검증이 아니다.

[03 방향·전원·연결 32조합의 선택 모델·회전 검산](03_oak_shelf_32_combination_rule_evaluation.csv)

## 2. 퇴비통: 생략된 UV 자동 생성의 좌표식과 실제 이미지 픽셀

`composter.json`의 18개 면은 명시적 `uv`가 **전부 빠져 있다**. `contents1..7`/ `contents_ready`도 각 상단 face에 `uv`를 지정하지 않는다. 일반적인 Java Edition 블록 모델 설명에서는 `uv` 미기재 시 요소 좌표에서 UV를 생성한다고 설명한다([Minecraft Wiki Model](https://minecraft.wiki/w/Model)). 정확한 1.21.11 클라이언트 소스/실행 검증과 혼동하지 않기 위해, 다음 projection을 **재구성 가설/모델 외부 좌표식**으로 기록했다.

`from=[x,y,z]`, `to=[X,Y,Z]`일 때 (단위 0–16):

| face | 유도 UV `[u1,v1,u2,v2]` |
|---|---|
| down | `[x,16-Z,X,16-z]` |
| up | `[x,z,X,Z]` |
| north | `[16-X,16-Y,16-x,16-y]` |
| south | `[x,16-Y,X,16-y]` |
| west | `[z,16-Y,Z,16-y]` |
| east | `[16-Z,16-Y,16-z,16-y]` |

**검산:** 동일 1.21.11 원본의 `stairs.json` 명시적 UV **11면**, `slab.json` **6면**, `fence_post.json` **6면**을 각각 이 식과 비교했을 때 **23/23 동일 순서·동일 숫자**가 나왔다. 이 데이터 기반 검사로 해당 좌표식이 원본 선언 사례를 설명함을 확인했지만, 1.21.11 모델 loader의 실제 처리·회전/flip까지 검증한 것은 아니다. [04 원본 명시 UV 23면과 유도 식 교차검사](04_uv_projection_23_explicit_face_source_crosschecks.csv).

- 새로 전체 픽셀 디코딩한 4개 퇴비통 PNG: `composter_side` (256/256 불투명), `composter_bottom` (256/256 불투명; 팔레트 bit depth 2), `composter_compost` (144 불투명 +112 투명), `composter_ready` (144 불투명 +112 투명). **신규 PNG 4종 = 1,024픽셀, 불투명 800·완전 투명 224**.
- 기존 v26 원본 `composter_top` (112 불투명+144 투명)도 다시 읽어 표본 면에 대조했다. 이 PNG는 v27 신규 텍스처/신규 화소 숫자에 더하지 않았다.
- **본체 `composter` 5요소의 18개 선언 면**: 위 유도 UV 범위를 실제 원본 PNG 3종(`composter_top`, `_side`, `_bottom`)의 픽셀에 조회해 **2,544 텍셀 사용(불투명 2,544, 투명 0)**.
- **상태별 내용물 8개 원본 1면씩**: `up` face의 유도 UV는 공통 `[2,2,14,14]` (12×12=144 픽셀). `level=1..7`은 `composter_compost`, `level=8`은 `composter_ready`. 여덟 source face에 걸쳐 **1,152 텍셀 사용(불투명 1,152, 투명 0)**. 높이 `maxY=3,5,7,9,11,13,15,15`와 원본 model SHA는 v25 CSV에서 확인한 값을 재사용.
- **퇴비통 전체 (생략 UV 재구성 적용)**: **26개 face / 3,696 텍셀 사용(전부 불투명)**, 역방향 UV 0, 0면적 UV 0. 이 값은 명시적인 `uv`가 원본에 적힌 사례와 검증 수준이 다르므로, 통계에 `uv_source=derived...`를 별도로 기록했다.

원본 근거/재구성 영역/각 면 텍셀·RGBA 및 Git SHA:
- [05 퇴비통 5 PNG 실화소 (신규4+기존1)](05_composter_five_png_rgba.csv)
- [06 퇴비통 기본18+상태8 = 암시 UV 26면 실제 PNG 픽셀](06_composter_26_implicit_uv_face_rgba.csv)

**중요한 차이:** `composter_top` 원본 이미지에는 투명 144픽셀, `composter_compost`·`ready`에는 각각 투명 112픽셀이 들어 있다. 하지만 이번에 모델 좌표에서 유도한 UV 사각형이 사용하는 픽셀은 **26면 모두 불투명한 영역**에 위치한다. **PNG 전체 알파 분포 ≠ 실제 참조되는 UV 영역의 알파 분포**라는 구체적 원본 데이터 증거다. 인게임 커팅·다른 렌더 레이어가 이를 어떻게 보여 주는지는 별도 확인 필요.

## 5. 리소스 재배포·증거 한계

- 사용자 연구 저장소의 `1.21.11` 폴더에는 Minecraft 원본 바이너리 `.class`, PNG, JSON 등이 존재하며 저장소 공개 상태다. 공개 재배포 권한을 검토하고 원본 파일을 분리/비공개 저장하는 것을 권장한다.
- 이번 GitHub 커밋은 **오직 원본 SHA, 파생 좌표·통계·보고서만 추가**, 원본 이미지·JSON·JAR 복제 없이 수행한다.
- 원본 PNG 디코딩은 GitHub Base64 전 바이트에서 PNG/DEFLATE/PLTE/tRNS/scanline 역산했고 픽셀 카운트를 검산. **PNG CRC-32와 zlib Adler-32 자체 검사 및 독립 Pillow end-to-end 재실행은 여전히 미완료**.
- 미러 Git blob SHA 5/5는 동일 버전 공개 추출본과의 일치 증거일 뿐, **공식 1.21.11 Mojang 클라이언트 JAR 검증**이나 게임 실행 화면 검증으로 처리하지 않았다.
