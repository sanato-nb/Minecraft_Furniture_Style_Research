### C 직접 검증에 포함

1. 2,304개 leaf별 원본 blob SHA와 부모 체인, 기하를 선언한 소스 SHA, 텍스처 슬롯의 상속과 재정의 및 `#slot` 참조 해석.
2. 각 적용 face의 원본 방향·`texture`·명시 `uv` 유무·원본 UV 값·face 회전·UV 좌표 역방향. 한 부모 선언이 여러 leaf에 재사용되면 적용 행과 고유 선언을 별도 집계한다.
3. 최종 바인딩이 가능한 `minecraft` 블록 PNG의 원본 경로·blob SHA 및 **PNG 전체의 실제 RGBA 픽셀·알파 분포**. 경로+SHA가 동일한 PNG는 단계 전체에서 한 번만 고유 실적으로 센다. 원본 PNG가 애니메이션 시트이면 시트 전체 픽셀을 읽되 재생·프레임 타이밍 인증은 하지 않는다. 관련 `.mcmeta`가 있으면 존재·경로·SHA와 후속 소관을 기록한다.
4. 소스에서 바인딩되지 않은 부모 템플릿 슬롯은 실제 하위 leaf와 소스 SHA를 근거로 `template_unbound`로 분류한다. 순환 슬롯, 찾을 수 없는 부모/PNG, 설명할 수 없는 참조는 원인을 원장에 남기고 종료 감사에서 차단 항목으로 취급한다.
5. v1~v69의 P1 544개 경로/SHA와 선행 UV·PNG 근거를 연결한다. 과거 파일의 열 존재·이름 언급은 의미론 검증이나 최초 신규 연구로 승격하지 않는다. 채택한 과거 주장은 정확한 원본 파일·행/면·SHA와 검증 등급을 붙인다. 자료에 없는 주장은 `not_found_in_examined_sources`로 표기하며 역사상 연구되지 않았다는 뜻으로 쓰지 않는다.

### C 완료 조건에서 제외

E 예외 86개에 대한 특수 렌더·런타임 기하, blockstate 방향·`uvlock` 및 상태 조립(D), 공식 게임 엔진의 암시 UV 계산·애니메이션 재생·실게임 화면 인증, 1,111개 전체 PNG 목록 중 어떤 C face에도 연결되지 않는 PNG, F/G 스타일 유형화와 최종 프로젝트 감사, 실제 가구 제작 및 PZ 변환. UV 키 부재는 `implicit_source_absent`로 기록하며 공식 렌더 UV를 추정 인증하지 않는다.
