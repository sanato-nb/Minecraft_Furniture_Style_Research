## 각 Entry 실제 실행 절차
1. 시작 시 GitHub 최신 `main` HEAD 및 해당 회차 입력 원장의 Git SHA 확인; 이전 SHA와 차이를 기록한다.
2. 배정된 모델·blockstate·PNG의 **원본 자산 본문과 path/blob SHA**를 직접 재조회하고, A/v34 인벤토리 및 B/C/D/E/F 각 단계 결과의 담당·증거 수준을 연결한다. 파일 이름/목록만으로 PASS 금지.
3. 모델은 부모 체인·요소·face·UV·PNG 슬롯 및 E 예외, D 직접·미직접을 결합한다. blockstate는 variants/multipart 조건·선택 모델·x/y/uvlock/weight **명시 여부**를 원본과 대조한다. PNG는 C RGBA·F 첫 프레임·sidecar 및 미참조 이유를 확인한다.
4. 작성과 **독립된 검산 경로**로 타입+경로+SHA·참조·합계를 재산출한다. 오류와 명시 미결정을 분리한다. 정정은 신규 `G_ERRATA`로 기록하고 A~F/v69 원본은 수정하지 않는다.
5. 매 Entry에 `G_SOURCE_CROSSWALK.csv`, `G_REF_LINKS.csv`, `G_EXCEPTIONS.csv`, `G_INDEPENDENT_AUDIT.json`, `G_ENTRY_REPORT.md`, `G_NEXT.md`를 남긴다. GitHub 커밋 후 SHA·행수·본문을 원격 재조회한 부분만 승인한다. Entry별 종료 없이 다음 회차 진행 금지.
