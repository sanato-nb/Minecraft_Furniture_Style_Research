# TV-001 — 오프라인 기술 검증 고정 계약 v1.1

**상태:** 실행용 계약, 아직 완료 판정 전  
**기준:** 연구 설계 v0.6 / 데이터 명세 v0.2 (현재 대화에서 확정한 정책)  
**원본 기준:** main `176f7f34de2336eb7984c4734e97b6eb156c19f4`  
**실행 환경:** Ubuntu 24.04 GitHub Actions, Python 3.12, Blender (버전은 실행 로그 기록), Pillow  
**금지:** 유료 AI API, Minecraft 게임 실행, 원본 자료 수정, 테스트 도중 분모 추가

## 1. 목표와 종료선

이번 TV-001은 **모델링 연구용 분석·렌더링 도구의 실행 가능성을 평가하는 독립된 기술 검증**이다. 바닐라 전수 연구나 가구 제작 연구가 아니다.

합격을 주장할 때 다음을 구분한다.

- **정적 분석 PASS:** 고정된 입력과 예상 구조·참조·오류 분류가 일치한다.
- **렌더링 실행 PASS:** 25개 이미지가 정상 생성되고, 해시·크기·시각적 기본 검사를 통과한다.
- **렌더링 정확성 검증:** 독립적인 기대 형상과 UV·상태 변환을 확인해야 하며, 파일 생성 또는 서로 다른 이미지라는 사실만으로 PASS가 아니다.
- **TV-001 전체 PASS:** 위 필수 확인과 체크포인트 재개·재현성 검증이 모두 완료되었을 때만 가능하다.
- **PARTIAL:** 검증 가능한 기능만 완료된 상태다. 원래 범위의 미완료 항목을 보존한다.

**Blockbench 웹 직접 조작은 제외한다.** Blockbench 자동화의 기술 가능성은 향후 별도 실험 제안 대상으로 기록하며, 이번 CI의 필수 조건으로 변경하지 않는다.

## 2. 고정 시험 대상: 정확히 12개

| 그룹 | ID | 검증 내용 | 고정 출력 PNG |
|---|---|---|---:|
| 정상 | P01 | 기본 큐브의 6면과 UV | 6 |
| 정상 | P02 | 회전 원점 및 다중 요소 | 2 |
| 정상 | P03 | 2단계 부모 모델 상속 | 2 |
| 정상 | P04 | 4개 방향의 상태별 모델 회전 | 4 |
| 정상 | P05 | 2개 연결 속성 조합의 multipart | 4 |
| 정상 | P06 | 투명 텍스처와 90도 UV 회전 | 2 |
| 오류 | N01 | 텍스처 PNG 의도적 누락 | 0 |
| 오류 | N02 | 부모 모델 순환 참조 | 0 |
| 미지원 | U01 | 지원하지 않는 사용자 정의 형식 | 0 |

바닐라 파일의 참조 관계는 `1.21.11/assets/minecraft/`를 기준으로 해석한다. 파일 경로와 SHA-256은 실행 결과 매니페스트에 기록한다.

## 3. 고정 렌더 조건

- 해상도 256×256 RGBA PNG
- 직교 카메라, 픽셀 텍스처 최근접 보간, 투명 배경
- P01 여섯 방향, P02 두 방향, P03 두 방향
- P04 동·서·남·북 방향 상태, 같은 정면 카메라
- P05 연결 조합 4개, 같은 정면 카메라
- P06 앞·뒤, R01 사선 1개, R02 두 상태, R03 두 상태
- 기본 렌더러 Blender EEVEE, CPU 기반 GitHub 표준 Runner
- 카메라 좌표와 출력 설정은 코드의 고정값이며 실행 도중 임의 확장하지 않음

**유의:** 자체 Blender 변환 로직은 실제 Minecraft 클라이언트와 픽셀 동등하다고 아직 검증되지 않았다. 특히 면의 기본 UV, `uvlock`, 모델/요소 회전의 기준 및 투명도 렌더링은 독립 기준과 대조해야 한다. 이 항목을 입증하기 전에는 전체 PASS를 내리지 않는다.

## 4. 고정 작업 순서

| 단계 | 작업 | 계획된 증거 |
|---|---|---|
| T0 | 기존 DB·원본 검사·체크포인트 재사용 검토 | 기능 대조·새 기능 범위 |
| T1 | 12개 입력 생성과 분모 고정 | 입력 JSON/PNG, manifest, SHA |
| T2 | 원본·구조·상속·UV·상태 정적 검증 | 사례별 판정 |
| T3 | Blender를 한 프로세스에서 연속 실행 | 25개 이미지·작업 로그 |
| T4 | 독립 기대값 및 시각 정확성 검증 | 정확성 판정, 불확실성 |
| T5 | Blockbench 자동 검증 가능성 확인 | **필수 범위 제외** (웹 직접 조작하지 않음) |
| T6 | GitHub Actions 무유료 API 실행 | CI 실행 결과·환경 |
| T7 | 12개 렌더 후 재시작→13개 재개→재실행 0개 | 세 배치 로그 및 체크포인트 |
| T8 | 범위별 결과 합산·종료 판정 | PASS/PARTIAL/HOLD/FAIL 보고 |

이 워크플로가 자동 증명하는 것은 T1~T3 및 T6~T7의 기본 실행 능력이다. T4의 독립 렌더링 정확성은 자동 CI PASS에 포함되었다고 간주하지 않는다.

## 5. 재사용 및 비용 원칙

기존 저장소의 `src/mcfr/research_db.py`, `research_engine.py`, `source_jobs.py`, `visual_check.py`를 별도 조사해 재사용 가능성을 판단한다. 본 실험의 테스트 체크포인트는 별도 실행 디렉터리에 저장하여 운영 DB에 쓰지 않는다.

렌더러는 모델별로 재시작하지 않는다. 같은 Job에서 12개 연속 렌더, 새 Job 아닌 **새 Blender 프로세스**에서 13개 이어서 렌더, 세 번째 프로세스에서 재렌더 0개를 검증한다. 이는 **Job 간 영속성**을 증명하지 않는다. Job 간 영속성은 아티팩트 등의 복원 절차가 별도로 검증되어야 한다.

CPU 렌더링과 Python의 결정적 파싱에는 유료 AI API가 필요 없다. GitHub Actions Job 시간 제한을 제거한다고 주장하지 않는다.

## 6. 실패·미지원 및 범위 변경

- 고정 검증 범위의 분석기 오류는 수정하고 해당 사례만 재검증한다.
- 원본 데이터 결함·특수 미지원 형식은 유형과 영향 범위를 기록한다.
- 완료된 사례와 미완료 사례를 분리해 PARTIAL 판정을 허용한다.
- 새로운 의문을 이유로 검증 케이스·렌더 수·카메라를 늘리지 않는다.
- TV-001 전체 종료 심사 후에만 후속 연구 후보를 묶어서 제안한다.
- 기존 main, 과거 연구 증거, 원본 모델과 운영 DB는 수정하지 않는다.

## 7. 판정 방식

CI 성공만으로 TV-001 전체 완료라고 표시할 수 없다. 
정적 구조 검증, 생성된 PNG 검사, 정확성 교차 검증 및 실제 실행 로그를 각각 분리해 판단한다. 
작동하지 않는 기능은 FAIL/HOLD, 일부 검증만 가능한 범위는 PARTIAL로 기록한다.

이 계획은 TV-001 연구 실행 전의 고정 범위이며, 기존 v0.6 계약의 새 의문 분리·후속 제안 규칙을 그대로 따른다.
