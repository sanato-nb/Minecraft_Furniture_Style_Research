# 마인크래프트 가구 모델링 학습 프로젝트 — 1단계 실행 계획 v1

- **프로젝트:** 좀보이드 → 마인크래프트 맵
- **문서 성격:** 학습/분석 실행 계획서 (실제 분석 결과 보고서가 아님)
- **작성일:** 2026-11-11
- **최종 프로젝트 목표:** (1) 마인크래프트 바닐라 및 가구 모드의 모델링·텍스처 방식 학습 → (2) 분석 근거에 기반한 마인크래프트 가구 모델링 규칙서 작성
- **이 문서의 범위:** **1단계**만 계획. 좀보이드 가구 변환 및 실제 모델 제작은 수행하지 않음.

## 0. 목표와 원칙

### 0.1 핵심 목표

마인크래프트 기본 블록 및 가구 모드의 **실제 3D 모델·텍스처·배치 표현**을 조사하여, 가구를 자연스럽게 마인크래프트 스타일로 디자인하는 방식을 **근거 자료와 수치**로 이해한다. 이후 2단계에서 제작 규칙을 도출할 수 있도록 검증 가능한 분석 DB를 구축한다.

### 0.2 기본 원칙

1. **바닐라 먼저, 가구 모드 나중에:** 바닐라의 시각 언어를 익힌 뒤 모드가 이를 어떻게 확장했는지 비교한다.
2. **실제 파일 우선:** 가능한 경우 게임 리소스의 PNG, 모델 JSON, 블록 상태 JSON, 모드의 공개된 에셋 등을 직접 확인한다. 스크린샷만으로 확인한 내용은 별도 표시한다.
3. **근거 상태 구분:** `원본파일_확인`, `인게임_관찰`, `스크린샷_관찰`, `추론`, `미확인`을 섞지 않는다.
4. **사실과 제안 구분:** 측정치(예: 다리 두께)와 향후 권장치(예: 가장 적절한 두께)는 다른 필드에 저장한다. 결론을 먼저 정하고 수치를 맞추지 않는다.
5. **원본 버전 고정:** Minecraft **Java Edition**을 1차 기준으로 하되, 실제 분석에 사용할 게임/모드 버전은 자산 확보 후 고정하고 기록한다. 다른 버전의 에셋은 분리한다.
6. **저작권·라이선스 준수:** 모드 에셋과 텍스처를 임의 재배포하지 않는다. 원본은 허용 범위 내에서 열람하고 DB에는 출처, 분석치 및 허용되는 증거만 보존한다.
7. **재현 가능성:** 각 관찰은 원본 파일 경로·버전·객체 ID·분석 방법·검수 상태와 연결한다.

## 1. 전체 학습 흐름

```text
[01 바닐라 재질·텍스처]
          ↓
[02 바닐라 3D 모델·블록 상태]
          ↓
[03 가구 모드 3D 모델]
          ↓
[04 가구 모드 텍스처·UV]
          ↓
[05 바닐라 ↔ 가구 모드 비교·검증]
          ↓
[1단계 분석 데이터베이스·근거 자료 완성]
          ↓
[2단계 모델링 규칙서 작성 — 별도 단계]
```

## 2. 세부 실행 계획

### 01. 바닐라 재질·텍스처 분석

**목적:** 바닐라가 재질·색상·음영·반복 패턴을 제한된 픽셀로 어떻게 표현하는지 파악한다.

**우선 조사할 재질 계열**

- 목재: 참나무·가문비나무·자작나무·짙은 참나무 등
- 석재·벽돌: 돌, 조약돌, 석재 벽돌, 점판암 등
- 금속: 철, 구리 및 관련 블록
- 직물: 양털, 카펫
- 유리: 유리, 색유리
- 도기·색면: 테라코타, 유광 테라코타
- 기타 가구에 활용될 표현: 콘크리트, 판자·원목 단면, 책장 등

**분석 항목**

| 분류 | 기록할 내용 |
|---|---|
| 기본 정보 | 파일 경로, 게임 버전, 텍스처 크기, 알파 유무 |
| 색상 | 주요 색, 색상 수, 명도·채도 분포 |
| 픽셀 패턴 | 경계의 선명도, 반복 단위, 잡음·무늬 밀도 |
| 재질 특성 | 나뭇결·돌결·금속 하이라이트·직물 질감 등 |
| 음영 | 대비, 하이라이트, 그림자, 방향성 |
| 타일 연결 | 경계 이음새, 반복 시 자연스러움 |
| 판정 근거 | 원본 이미지, 관찰 메모, 확실성 |

**예상 1차 표본:** 10~15개 재질 계열에서 80~150개 텍스처를 시작 목표로 설정. 이는 **계획치**이며 실제 확보·검수 수량이 아님.

**산출물:** `vanilla_textures.csv`, `vanilla_material_families.md`, 출처·검증 로그, 필요한 경우 허용되는 비교 시각화.

### 02. 바닐라 3D 모델·블록 상태 분석

**목적:** 단순 정육면체를 넘어 바닐라의 입체 구조, 비율, 디테일 배치, 방향 전환과 특수 렌더링을 이해한다.

**우선 조사할 블록·물체**

- 기본 큐브, 계단, 반 블록, 울타리, 담장
- 문, 다락문, 표지판
- 책장, 독서대, 작업대, 통, 상자
- 침대 등 가구와 비교 가능한 오브젝트

**분석 항목**

| 분류 | 기록할 내용 |
|---|---|
| 형식 | 모델 JSON / 블록 상태 JSON / 엔티티·특수 렌더링 등 |
| 좌표 | 모델 요소별 `from`, `to`, 회전 원점·각도 |
| 치수 | 전체 외접 상자 크기, 파트별 비율, 블록 점유 범위 |
| 구조 | 요소 개수, 반복 부품, 결합 방식 |
| UV·텍스처 | 면별 텍스처 참조, UV 좌표, 재사용 방식 |
| 방향 | 블록 상태·회전에 따른 외형 변화 |
| 디테일 | 3D 형상으로 표현한 부분 vs 텍스처로 표현한 부분 |
| 예외 | 일반 블록 JSON만으로 구조가 설명되지 않는 객체 구분 |

**방법:** 리소스 파일 읽기 → 데이터 추출 → 유형별 표 작성 → 필요하면 모델 렌더링 또는 게임 화면과 비교 검수.

**산출물:** `vanilla_models.csv`, `vanilla_model_elements.csv`, `vanilla_model_rendering_exceptions.md`.

### 03. 가구 모드 3D 모델 분석

**목적:** 바닐라 스타일을 유지하거나 확장하는 가구의 부품 설계법을 비교한다.

**1차 비교 후보 모드**

- Another Furniture — 바닐라 친화적인 비율·단순한 외형 관찰
- Macaw's Furniture — 수납장·책상·연결형 가구의 구조 비교
- Handcrafted — 소파·의자 등 다양한 가구의 디테일 수준 비교

> 위 목록은 **분석 후보**다. 실제 분석 가능 여부는 지원 게임 버전, 파일 접근성, 에셋 형식, 라이선스 및 확보된 원본 자료를 확인한 후 확정한다. 필요시 대체 모드를 선정한다.

**우선 비교할 가구 분류:** 의자, 작은 테이블, 큰 테이블, 캐비닛·서랍장, 책장, 소파, 침대, 주방 가구, 장식물.

**분석 항목**

- 전체 모델 크기(블록 기준), 요소 개수·두께·길이·간격
- 다리·좌판·등받이·프레임·손잡이·쿠션 등 부품 구분
- 하나의 블록 또는 다중 블록 점유 방식
- 방향·회전·연결형 가구 변화
- 바닐라에 비해 추가/생략한 디테일
- 모델 파일 형식(JSON, 기타 전용 형식), 확인 가능한 범위와 제약

**중요:** 같은 종류의 가구를 여러 모드에서 **동일 측정 기준**으로 비교한다. 단일 모드의 디자인을 바닐라 전체의 보편적 규칙으로 일반화하지 않는다.

**산출물:** `mod_furniture_catalog.csv`, `mod_model_elements.csv`, `furniture_category_comparisons.md`.

### 04. 가구 모드 텍스처·UV 분석

**목적:** 모델의 간결한 3D 구조를 텍스처로 어떻게 보완하는지 파악한다.

**분석 항목**

- 텍스처 크기와 픽셀 밀도, 모델 면과 텍스처의 관계
- 색상 팔레트, 음영·하이라이트, 재질 표현
- UV 레이아웃, 동일 텍스처 재사용·변형
- 손잡이·못·봉제선·무늬 등 질감을 3D 대신 텍스처로 해결하는 사례
- 바닐라 텍스처를 그대로 참조한 경우와 독자 텍스처 사용 사례
- 모드 간 이질감 발생/감소 사례 및 근거

**산출물:** `mod_textures.csv`, `mod_uv_analysis.csv`, `mod_material_comparison.md`.

### 05. 바닐라 ↔ 가구 모드 비교·검증

**목적:** 2단계의 가구 모델링 규칙을 만들 수 있도록 **확인된 공통점·차이점·예외**를 정리한다.

**비교 축**

1. 외형 비율: 높이·너비·다리 두께·손잡이 크기
2. 모델 복잡도: 요소 수·세부 기하학·다중 블록 구성
3. 텍스처 스타일: 해상도·팔레트·명암·픽셀 밀도
4. 실루엣: 멀리서 읽히는 특징과 부품 비중
5. 3D와 텍스처의 역할 분담
6. 모드가 바닐라의 표현 방식을 재현 또는 변형한 지점

**결과는 세 층으로 분리**

- **바닐라 공통 특성:** 바닐라 원본에서 직접 확인
- **가구 모드 공통 특성:** 둘 이상의 모드 등 독립 사례를 비교하여 확인
- **모드 고유 특성:** 특정 모드에서만 관찰된 표현

**검증 단계**

- 원본 파일과 데이터베이스 값 대조
- 동일 가구 유형의 비교 기준 일치 여부 확인
- 스크린샷 관찰과 파일 확인이 충돌할 경우 보류 처리
- 통계와 소수 사례를 혼동하지 않고 표본 수 표기
- 미확인 에셋·라이선스·렌더링 예외를 별도 목록화

**산출물:** `vanilla_vs_mod_comparison.csv`, `observations_and_exceptions.md`, `review_status.csv`, `stage1_final_report.md`.

## 3. 데이터베이스 기본 설계(초안)

| 테이블/파일 | 핵심 필드 |
|---|---|
| `sources` | source_id, edition, game_version, mod_name, mod_version, url_or_path, license_note, hash |
| `textures` | texture_id, source_id, path, width, height, material_family, palette_metrics, shading_note |
| `models` | model_id, source_id, object_name, object_type, format, bounding_box, block_occupancy, element_count |
| `model_elements` | model_id, element_index, from_xyz, to_xyz, rotation, face_textures, uv |
| `observations` | observation_id, target_id, claim, evidence_type, evidence_path, confidence, reviewer_note |
| `comparisons` | category, source_a, source_b, metric, value_a, value_b, interpretation |
| `issues` | target_id, issue_type, description, status, resolution |

초기에는 CSV로 시작하되, 중복 자료 연결·대량 조회가 필요해지면 SQLite로 통합한다. 기존 좀보이드 타일 분석 DB와는 별개로 관리하고, 추후 2단계에서 규칙 자료와 연결한다.

## 4. 단계별 완료 판단 기준

- [ ] 실제 사용할 **Java Edition 버전**과 참조할 리소스 출처를 고정했다.
- [ ] 바닐라 주요 재질의 PNG를 확보하고 텍스처 특징을 근거와 함께 기록했다.
- [ ] 바닐라 대표 블록의 3D 형상·좌표·UV·회전과 렌더링 예외를 기록했다.
- [ ] 분석할 가구 모드를 선정하고 원본 모델·텍스처 접근 가능 여부를 검증했다.
- [ ] 복수 모드에서 같은 가구 유형을 공통 지표로 비교했다.
- [ ] 가구 모드별 텍스처 및 UV 표현을 비교했다.
- [ ] 바닐라 공통/모드 공통/모드 고유 특징을 분리했다.
- [ ] 모든 주요 분석 결과에 출처·버전·확인 방법·검증 상태가 남아 있다.
- [ ] 미확인 항목과 분석 한계를 별도로 기록했다.
- [ ] 2단계 규칙서 작성을 위한 분석 DB와 1단계 완료 보고서가 준비됐다.

> 수량만 채우는 것을 완료로 보지 않는다. 각 항목이 **확인 가능한 원본과 연결**되어야 한다.

## 5. 범위 제외 및 다음 단계

**1단계에서 하지 않을 작업:** 좀보이드 가구의 3D 변환, 시험용 가구 모델 신규 제작, 마인크래프트 모드 구현, 실제 맵 배치, 검증되지 않은 수치의 권장 규칙 확정.

**2단계에서 할 작업(예고):** 1단계에서 확인된 제작 사례를 토대로 가구 유형별 모델링 기준, 치수·비율 권장 범위, 텍스처·UV·재질 규칙, 예외 처리 및 스타일 판정 기준을 **근거 기반 규칙서**로 만든다.

## 6. 실행 시작 순서

1. 바닐라 Java Edition 기준 버전과 분석할 리소스 범위 확정.
2. 재질별 원본 텍스처 목록 수집 및 1차 샘플 분석.
3. 해당 재질을 사용하는 바닐라 블록 모델로 구조 분석 확대.
4. 가구 모드의 파일 접근성과 버전을 검증하고 표본 선정.
5. 모드별 모델 및 텍스처 분석, 동종 가구 간 비교.
6. 결과 DB 검수 및 1단계 완료 판정.

**문서 상태:** 계획 수립 완료 / 실제 1단계 자료 분석은 별도 진행 필요.
