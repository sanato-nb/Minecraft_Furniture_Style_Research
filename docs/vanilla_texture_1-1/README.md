## 명령 사용법

- `1-1-01 시작해줘` → 목재·원목 18개부터 A→G 과정을 실행
- `1-1-08 E단계 진행해줘` → 복합·기능면의 소스 모델·UV 연결 작업 집중
- `1-1-11 남은 파일 검수해줘` → 구조부품 31개 중 근거 부족한 파일만 우선 검증
- 한 단계에서도 기존 v4/v35~v38 측정을 먼저 재사용·대조하며, 작업 기록에 “기존 측정”, “이번에 직접 재검사”, “공식/런타임 미검증”을 따로 표시한다.

## 모든 번호에 공통으로 적용할 일곱 세부 검사 (A–G)

1. **A — 파일·기존 기록 확인:** 해당 분류의 정확한 `texture_id`, `source_path`, 표본 수, v4 SHA-256·측정 메타데이터를 정리. 이전 체크포인트와 중복 검토.
2. **B — 원본 PNG 확보·무결성:** 원본 PNG 바이너리를 읽어 SHA-256, Git blob SHA(혼동 금지), 크기, PNG CRC/해독 여부 확인. 현재 공개 미러로만 확인한 파일은 공식 Mojang 인증과 구분.
3. **C — 픽셀 분석:** RGB/팔레트/밝기·채도, 알파(255/0/부분), 픽셀 분포, 방향성·경계·반복, 필요한 경우 RGB 상관분석. 실제 픽셀을 직접 검사한 범위만 실측으로 기록.
4. **D — 재질별 특화 항목:** 각 번호별 문서의 3가지 정밀 검사 수행. 가구 스타일로 일반화하기 전 표본 편향과 예외 기록.
5. **E — 정적 3D 모델 적용:** 모델 JSON parent/texture slot/element/face/UV/블록 상태에서 어떤 위치에 쓰이는지 확인. `#particle` 전용과 진짜 면 렌더 텍스처 구분. 동적 애니메이션 데이터 분석 금지.
6. **F — 원본·게임 검증:** 공식 1.21.11 `client.jar`의 출처·SHA를 독립 인증하고 가능하면 인게임 **정적** UV·표면·광원·알파/틴트 비교. 현재 접근 불가면 “검증 대기” 표시하고 소스 분석 단계만 결과로 인정.
7. **G — 결과 저장·완료판정:** 정적 연구 보고서·파일별 증거 원장·재현 지침을 GitHub에 기록하고 체크포인트 갱신. 공식/인게임 검증이나 대표성 확인이 남아 있으면 **과제 전체 완료로 선언하지 않는다**.

> 기존 표본 **150/150 = 표본 경로 수집 목표 충족**이지, 각 번호의 A–G 또는 1-1 전체 완료 100%가 아니다. 검증 기준이 서로 다른 원본/UV/인게임 진행률을 하나의 퍼센트로 합치지 않는다.

## 각 단계별 독립 새 채팅 시작/인수인계

**[11단계 전용 START_PROMPT / HANDOFF / STATE 실행 링크 모음](NEW_CHAT_LAUNCHER.md)** · [버전 겹침 방지·동시 작업 규칙](ISOLATED_CHAT_VERSIONING.md)

`1-1-01`은 `TEX01-R000`, ... `1-1-11`은 `TEX11-R000`으로 시작한다. **`R000`은 계획/인수인계이며 신규 분석을 했다는 뜻이 아니다.** 실제 원본 연구 결과가 신규로 남으면 각 단계에만 `TEXnn-R001`, `R002` 등을 쓴다. 이전 전체 프로젝트 `v38`은 별개로 유지하고, 서로 다른 채팅이 공통 `v39` 같은 이름을 쓰거나 루트 `HANDOFF.md`를 덮어쓰지 않는다.
