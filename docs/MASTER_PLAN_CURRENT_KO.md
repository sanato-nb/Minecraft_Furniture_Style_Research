## 1. 목적과 결과물

바닐라 마인크래프트와 가구 모드가 **형태, 비율, 재질, 픽셀 텍스처, UV, 방향·상태, 특수 렌더**를 어떻게 구성하는지 원본 근거로 조사한다. 이 결과에서 가구를 마인크래프트 스타일로 설계할 때 쓸 **검증 가능한 모델링 규칙서**를 도출한다.

전체 연구는 **1단계 분석 자료 구축 → 2단계 규칙서 작성** 순서다. 프로젝트 좀보이드 가구의 실제 변환, 신규 마인크래프트 모델 제작, 모드 구현과 맵 배치는 이 연구가 완료된 후 별도 제작 과제로 정의한다. 연구 완료를 제작 완료로 표기하지 않는다.

## 4. 가구 모드 연구와 비교

### 1-3 모델 구조

분석 후보는 **Another Furniture, Macaw's Furniture, Handcrafted** 등이다. 후보를 확정된 표본으로 세지 않는다. 지원 게임 버전, 접근 가능한 모델 원본·형식, 라이선스와 재현 가능성을 확인한 뒤 조사할 모드와 의자·테이블·수납장·책장·소파·침대·장식물 등의 공통 비교 표본을 정한다. 요소 좌표·외접 크기·부품 두께·연결형·다중 블록·방향 상태를 동일 단위로 측정한다.

### 1-4 텍스처·UV

1-3에서 확정한 모델과 연결된 PNG·UV를 경로/SHA로 연결한다. 픽셀 밀도, 팔레트, 재질·음영, 디테일의 3D/텍스처 분담, 바닐라 텍스처 참조 여부를 측정한다. 모델에 없는 모양을 파일명이나 스크린샷만으로 추정하지 않는다.

### 1-5 비교·검수

같은 가구 유형에서 바닐라 근거와 둘 이상의 모드 사례를 같은 기준으로 비교한다. **바닐라 공통 / 여러 모드 공통 / 특정 모드 고유 / 미확인·반례**를 분리한다. 충돌하는 측정치와 렌더 예외를 공개된 근거와 함께 보류하고, 1단계 분석 DB·비교표·최종 보고서를 독립 검수한 뒤 종료한다.

## 5. 2단계 모델링 규칙서

1단계의 관찰값과 제작 권장값을 별도 필드로 둔다. 가구 유형별 실루엣·블록 점유·부품 비율, 권장 좌표 범위, 텍스처 해상도·팔레트·UV, 방향·연결 상태, 특수 렌더 예외와 스타일 판정 기준을 **해당 원본 경로·SHA·사례**에 연결한다. 근거가 부족한 항목은 제안 또는 미확인으로 표시한다. 규칙서의 완료는 제작용 샘플이나 실제 PZ 맵의 완성을 의미하지 않는다.

## 6. 기록·검증 규칙

- 모든 분석 행은 `게임/모드 버전 → 원본 경로 → Git SHA → 모델·면·텍스처·상태 ID → 관찰/계산 방식 → 검수 상태`로 추적한다.
- `원본파일 직접 확인`, `정적 계산`, `정적 코드 근거`, `인게임 관찰`, `스크린샷 관찰`, `추론`, `미확인`을 분리한다. 공식 배포 JAR 인증과 런타임 렌더 확인을 실제 수행하지 않았으면 완료라고 쓰지 않는다.
- 경로가 다른 동일 SHA 자산, 부모 원형 재사용, 과거 v1~v69 연구와 새 측정을 구분한다. 이미 완료된 A~D 및 1-1 원본 자료는 보존하고 필요한 정정은 별도 근거로 기록한다.
- 각 회차는 배정표 → 원본 판독 → 산출 원장 → 독립 재계산 → 예외 처리 → 원격 SHA·행수 재조회 → 인수인계 순으로 닫는다. 오류가 남으면 성공 수치에서 제외한다.
- 모드 에셋은 라이선스와 공개 범위를 확인하고 재배포 대신 출처·측정치·허용되는 증거를 기록한다.

## 7. 종료 순서와 후속 제작 경계

1. **E → F → G**를 각 고정 범위와 게이트에 따라 종료해 **1-2 전체**를 판정한다.
2. **1-3 → 1-4 → 1-5**의 선정 표본·비교·독립 검수를 끝내 **1단계 분석 DB**를 완성한다.
3. **2단계 규칙서**를 근거 연결·반례·미확인 목록과 함께 발행한다.
4. 그 뒤 별도 제작 과제로 **PZ 가구 타일의 실제 배치·정체 근거 → Minecraft 대응 설계 → 모델·텍스처 제작 → 맵 배치·시각 검수**를 계획한다. 이 제작 범위·버전·산출물·완료 기준은 현재 연구 계획에 확정되지 않았다.

기존 [1단계 계획 v1](01_1단계_학습계획_v1.md)은 당시의 초기 계획으로 보존한다. 본 문서는 현재 상태를 연결하는 계획이며 E 이후의 조사 완료를 주장하지 않는다.
