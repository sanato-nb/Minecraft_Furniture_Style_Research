# Minecraft Furniture Style Research — 연구 운영 계약 v0.6 (합의사항 재구성본)

> **문서 성격:** 2026-11-27 전체 합의 정리본에서 연구 계약에 해당하는 내용을 주제별로 재구성한 작업용 문서다. 이전 채팅에 작성된 v0.6 원문을 1:1로 복제한 문서는 아니다. 내용 상충 시 [전체 합의 정리본](PROJECT_AGREEMENTS_2026-11-27_FULL.md)과 이후 사용자 명시 결정 및 해당 연구 회차의 잠긴 계약을 우선 대조한다.
>
> **상태:** 운영 원칙의 합의 기록. 모든 관련 소프트웨어가 새 기준의 검증을 통과했다는 뜻이 아니다.

## A. 목적과 현재 연구의 경계

1. 프로젝트의 목적은 Minecraft Java Edition 바닐라 및 다양한 가구 모드의 실제 모델·텍스처·UV·블록상태·디자인 특성을 조사해, AI가 이후 Minecraft 스타일의 가구를 제작하는 데 재사용할 수 있는 지식을 구축하는 것이다.
2. 파일·수치의 단순한 수집으로 끝내지 않는다. 가구의 부품 역할, 상대 비율, 구조, 질감·색상, 제작 기법을 상세히 추출하고 원본 근거·신뢰도를 함께 기록한다.
3. 상위 프로젝트는 프로젝트 좀보이드 → Minecraft 맵 제작이다. 그러나 현재 연구 회차의 필수 산출물은 Minecraft 모델링 지식이며 **PZ 맵 변환과 실제 신규 가구 제작은 별도 후속 작업**이다.
4. 연구 목적으로 Minecraft 게임 플레이·게임 클라이언트 실행·인게임 F2 촬영을 필수 조건으로 추가하지 않는다. 기존에 작성한 인게임 근거는 보존한다.

## B. 연구 대상 정책

- 바닐라를 먼저 조사하고, 가구 모드는 **모드별로 독립된 연구 단위**를 만든다.
- 모든 연구에 적용할 Minecraft 버전·로더 하나를 강제하지 않는다. 대상의 정확한 원본 버전, Minecraft 버전, 해당하는 로더, 배포 출처와 해시를 기록한다.
- 연구 범위는 대상의 원본 사전 조사 결과로 확정한다. **범위에 포함한 원본은 전수 열거**하고, 임의 표본을 검사한 결과를 전체 완료로 승격하지 않는다.
- 모드 버전이 바뀌면 추가·변경된 자료를 증분 연구할 수 있고, 삭제된 리소스와 참조 영향도 기록한다. 사용자가 요청하면 고정 범위를 처음부터 다시 연구한다.
- 연구 회차 방식은 기존 `NEW`, `INCREMENTAL`, `REVALIDATE`, `FRESH`를 유지한다.

## C. 연구 시작 전 필수 관문

### C1. 원본 사전 조사

- 조사할 실제 원본 파일, 대상 버전, 참조 관계, 모델·PNG·블록상태 종류 및 수량을 먼저 열거한다.
- 지원 가능한 형식, 미지원 형식, 결측 원본과 검증 환경의 제약을 분리하여 파악한다.
- 연구 분모를 추정치가 아닌 확인된 목록으로 설정한다.

### C2. 연구 범위 상세 고정

- 포함·제외 항목, 원본 목록, 원본 경로·버전·해시, 모델 요소·면·UV·텍스처·상태 분석 범위, 렌더링 대상/조건과 이미지 수를 문서화한다.
- 구조적 분석, 디자인·부품 의미 분석, 독립 검증 중 **필수와 선택**을 구분한다.
- 실패·미지원·PARTIAL·HOLD 처리와 종료 조건, 산출물·증거 규격을 미리 정한다.

### C3. 실행계획 상세 고정

- 실행 순서, 대상과 선행 조건, 도구, 배치 크기, 입력·출력, 기대값, 비교 기준, 결과 저장 위치, 체크포인트, 재개, 검수와 종료 심사를 미리 정한다.
- 이후 연구는 잠긴 범위를 기준으로 수행한다.

**순서:** 원본 사전 조사 → 상세 범위 확정 → 상세 실행계획 확정 → 실제 연구 → 종료 심사.

## D. 연구 중 새 문제 발견 시 규칙

- 실제로 발견한 새로운 연구 질문·개선 아이디어를 근거와 함께 별도 후속 연구 후보에 기록한다.
- 해당 문제가 **잠긴 범위 밖**이면 현재 연구의 필수 작업을 늘리지 않는다.
- **잠긴 범위 안의 구현 오류·근거 오류**는 수정하고 해당 범위를 재검증한다.
- 새 의문 때문에 이미 검증 완료한 모듈을 일괄 무효화하지 않는다.
- 원래 작업과 종료 심사를 완료한 뒤 후속 후보를 한 번에 정리하여 제안한다. 새 연구는 사용자의 승인과 새로운 사전 조사·범위·계획을 거친다.

## E. 증거와 모델링 지식

- 직접 원본 확인(`SOURCE`), 계산(`CALCULATED`), 관찰(`OBSERVED`), 추론(`INFERRED`), 미확인(`UNKNOWN`), 해당 없음(`NOT_APPLICABLE`)을 구분한다.
- 좌표, 크기, 모델/텍스처 참조, PNG 해상도처럼 객관적인 구조는 직접 증거와 계산으로 확인한다.
- '의자 다리', '좌판', '장식' 등 의미적 부품 정체는 **확정 / 추정 / 미확인**으로 분리한다. 미확인 부품이 있다고 객관적인 좌표 분석 결과까지 무효화하지 않는다.
- 디자인·모델링 지식에는 적용 가능한 형태·조건·출처·근거·신뢰도를 기록한다. 단일 모델의 특성을 보편적 기법으로 단정하지 않는다.
- 연구 데이터는 이후 AI의 모델·텍스처·UV·블록상태 제작을 지원하도록 검색·재사용 가능해야 한다.

## F. 검증과 완료 판정

| 상태 | 의미 |
|---|---|
| `PASS` | 해당 연구 회차에서 사전에 정한 필수 검증을 전부 통과 |
| `PARTIAL` | 확인된 부분 범위만 완료; 전체 완료로 표시하지 않음 |
| `HOLD` | 원본·실행 환경 등의 문제로 필수 항목의 판정을 내릴 수 없음 |
| `FAIL` | 필수 항목이 기대값과 불일치하거나 실제 검증 실패 |

- **대상 전체 수, 시도 수, 정상 검증 수**를 분리한다.
- PNG 파일 생성 및 서로 다른 이미지 출력은 Minecraft 모델의 형상·UV·상태 정확성을 입증하지 않는다. 독립된 기대 기준으로 필요한 정확성을 검사한다.
- 검증 불가능한 필수 영역이 남았다면 확인된 범위만 PARTIAL로 종료하거나 HOLD/FAIL을 기록한다.
- 한 번의 CI 통과가 곧 전체 연구 완료를 의미하지 않는다.

## G. 실행·비용·보존 원칙

- 반복적인 JSON·PNG·UV 분석과 오프라인 일괄 렌더링은 결정적 프로그램에 맡기고, ChatGPT는 예외 확인과 의미·디자인 해석에 집중한다.
- GitHub Actions를 자동화 실행 환경으로 활용하며, Blender 렌더러는 가능한 한 **동일 배치에서 연속 재사용**한다.
- 작업이 끊길 수 있음을 전제로 체크포인트·결과 복원·중복 작업 방지를 설계한다. Job 시간 제한을 없애거나 무제한 상시 실행된다고 주장하지 않는다.
- 유료 외부 AI API를 필수 구성으로 두거나 별도 승인 없이 호출하지 않는다.
- Blockbench 웹 직접 조작은 기본 연구 경로에서 제외한다. Blockbench 자동화는 후속 검토 대상이다.
- 기존 GitHub 연구 원본, 경로, 고정 SHA, 역사 DB 및 과거 PR을 임의 수정·삭제·정리하지 않는다.
- 권리·배포 가능 여부가 확인되지 않은 제3자 모델·텍스처 원본을 재배포하지 않는다.
- 기존 연구 1단계의 역사적 **5/5 종료 기록**은 보존하되, 새 계약 통과로 자동 인정하지 않는다.

- 실행 성공과 모델 정확성 검증을 구분한다. TV-001의 현재 전체 판정은 `PARTIAL`이다.

## I. 결정되지 않은 항목

이 계약 자체는 아래 사항을 새로 확정하지 않는다.

- 전체 연구 DB의 실제 테이블·이관 설계
- 첫 본 연구 바닐라 원본의 구체 버전·분모
- 다음 가구 모드 대상 및 연구 범위
- Blockbench 자동 검증의 도입 여부
- GitHub Actions **서로 다른 Job 간** 렌더링 체크포인트 복원 성능
- 실제 대규모 처리 속도와 원본별 시각 정확성

이들은 각각 해당 순서의 사전 조사와 작업계획에서 결정한다.
